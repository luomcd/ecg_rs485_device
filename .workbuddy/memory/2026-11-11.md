## 2 「485 源被 FILE 抢回」根因（10:30，已定案三层）

**① 标签误导（不是切源）**：`cli_console.c:1789`
`st.active ? "RS485" : "FILE（SD 回放）"`，而 `st.active=(s_src==RS485)&&s_running`
⇒ **管线没在跑就显示 "FILE（SD 回放）"**，把"未运行"和"文件回放"混成一个显示。
以后判真复位只看 `UART: ready / 未初始化`。

**② 本窗口（240 s）= 没复位、没切源，是用户按了 3 次清屏**：
日志 `app_state: clear -> visual only` → `ecg_pipe: rpeak detector reset on request (epoch=12/13/14)`，
间隔 10.0 s / 2.6 s。🛑 **清屏会 reset 检测器**（epoch++），`peaks`/`fed` 归零
⇒ 这就是我看到的"计数器回退、Δpeaks 负数"的真相。**T212 说"清屏＝纯视觉"只针对 play 与回放位置，
不包含检测器**，措辞需要补准。

**③ 早期的「UART 未初始化」——两种可能，未定**（我先前断言"一定是复位"，是过度断言）：
`s_ready` 只在 `rs485_init()` 置位、全工程无 deinit ⇒ false 有两种成因：
(a) **芯片复位过**（上电初值 false）；(b) **`rs485_init()` 首次就失败**
（`uart_param_config`/`uart_set_pin`/`uart_driver_install` 任一报错即 return，s_ready 永停 false）。
🛑 我当时只打印 `.splitlines()[0]`（命令回显），**把 banner / "启动失败: xxx" 过滤掉了 ⇒ 无法回溯区分**。

**为什么只有 2 次**：同会话 5 轮 stop→start，第 1 轮成、2~5 轮 start 全败。
失败 = `Δrx` 63/64 B 全 resync（= `start FAIL: idx=..` 回显，idx 一位=63/两位=64）⇒
**失败寄存器下标不固定** ⇒ 写后回读的时序问题，非某寄存器坏；同时 0x10 快照 80 B 正常 ⇒ 读通写不通。

🛑 **11:50 订正**：我曾断言"每关一次 COM35，ESP32 就复位一次"——**实测推翻**。
A/B 实测：关端口后用 DTR=0/RTS=0 重开、用默认 DTR=1/RTS=1 重开，**两种都保持 源=RS485/UART=ready**。
真相：新会话 `frames=0` 是因为 **`485-start` 内部 `rs485_reset_stat()` 清零计数器**；
`源=FILE` 是因为上一轮结束时源已非 RS485。**都不是复位。**
⇒ 纪律仍然成立（多轮测试同一会话做完），但理由是"每轮 485-start 会清零计数器"，不是"关串口复位"。

**成功率趋势：3/6 → 1/8 → 0/8（随时间单调变差）**，且"读（snap 80 B）一直正常、写才失败"。

## 15 LOD 实施清单成册（T232，未动码）

**现状核对（源码级）**：`ECG_LOD_EN=0`；`0x06 LOD_CN=0x08`（**SHDN_LOD=1 整块关断**）、
`0x07 LOD_EN=0x00`（六路全关）、`0x08 LOD_CURRENT=0x00`（**0 µA，不注入电流**）；
`0x18 ERROR_LOD` **逐样本已在读**（`ecgraw.lod`）但只进 ASCII 列，**二进制帧不含、`STATUS.bit4` 写死 0**。
⇒ 现在 `lod=0` 是常量，**不是判据**（11-11 三态全 0 不能当"LOD 无效"的证据——它根本没开）。

**寄存器地址以 `ads1293.h` 为准**：0x01/0x02 是 **FLEX 通道路由**（非 LOD），0x06/0x07/0x08/0x09 才是 LOD 四件套。
（11-11 那次 `start FAIL idx=2 reg=0x01` 是欠压，与 LOD 无关。）

**任务分 5 组**：A 寄存器（含**电流档必须从低往高扫，别直接上 T215 的 0xFF**）、B 数据层（bit4 改运行期读 + 防抖）、
C 协议/显示/联动（LOD 置位 ⇒ 抑制打点、BPM 立即 `--`）、D **基线重建（最大代价）**、E 专项验证（含"关输出不该报脱落"）。

**三个前置待拍板**：P-a 关输出是否等于开路（决定会不会误报）、P-b 是否要分路提示（需扩协议）、P-c 电流档。
**最大代价**：LOD-ON 后 B 的 200 µV 门限与全部噪声判据要重标定（T215 §4.2：原有基线全部作废）。

烧录后 `stat on` → 读了 3 个 1 s 窗口（窗口号 4/9/13，间隔 2.5 s 各 +5 窗口，计数自洽）：

**三个用法级结论**：
1. 噪声峰 |v| ≈ **182 LSB = 27.8 µV** ⇒ 与 B 的标定锚点（±26 µV）**一致**，交叉验证成立；
   B 的门限 200 µV ⇒ **7.2 倍余量**，与 T229 §17 的推算吻合。
2. **50 Hz 幅度仅 0.4~0.6 LSB（<0.1 µV）** ⇒ 陷波与共模都很好，工频不是问题。
3. ⚠ **峰峰值 30~50 µV，略高于 IEC 60601-2-25 的「内部噪声 ≤30 µV pp」**。

   含 AECG 输出级噪声与本底漂移 ⇒ **不能直接判不合规**，需按标准条件复测才有效。

## 18 LOD 台架首轮通过（17:50-17:55，8 nA 足够）

配置 `0x06=0x00` / `0x07=0x07(IN1+IN2+IN3)` / `0x08=0x01(8 nA)`；AECG 3 mV/60 bpm；四线全接。

| 动作 | lod | peaks | 判定 |
|---|---|---|---|
| 基准 | 0 | 增长 | ✓ |
| **拔 IN1(LA)** | **0→1（≤1.6 s）** | **冻结** | ✅ |
| 接回 IN1 | 1→0（≈1 s） | 恢复 | ✅ |
| **拔 IN2(RA)** | 0→1 | **冻结** | ✅ |
| 接回 IN2 | 1→0 | 恢复 | ✅ |
| **拔 IN3(N2 地)** | 0→1 | **继续增长** | ✅ **分路能力成立** |
| 接回 IN3（晚 26 s） | 1→0 | 恢复 | ✓ |
| **拔 IN4(N1=RLD)** | 0→1 | **继续增长** | ✅ 检出 OK；⚠ 见下 |
| 接回 IN4 | 1→0（≈2 s） | 恢复 | ✅ |

**四条结论**：① **8 nA 足够**（拔线后 ≤1.6 s 置位，§15.4 的升档预案作废）；
② 恢复 ≤2 s；③ **分路可区分**（拔 IN3 只报警不停 QRS，拔 IN1/IN2 报警且 QRS 冻结）；
④ 回流依赖成立（拔 IN4 时三路全报，与手册 §8.3.16 一致）。

🛑 **纠正我自己的一个预期（§15.3 第 5 行）**：我原写"拔 IN4 ⇒ peaks 停"。**实测继续涨，而且这才是对的**——
CH1 = AECG_RA − AECG_LA 是**差分**信号，RLD 只管共模；拔 RLD 回流会让共模失稳 + LOD 全报，**但差分 QRS 仍在**。
⇒ 以后判"QRS 是否失效"**只看 IN1/IN2**，不能看 IN4。
