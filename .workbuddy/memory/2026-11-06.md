## T214 `485-perf` 与首次真机性能测量（15:27~15:45）

### 为什么加

`485-stat` 全是累计量，算速率要两次采样手减、分母靠人掐表 ⇒ 口径每次不同、换版本无法对比；
30 min 长稳没法手工抄；手工采样还容易把多帧打在同一时间戳（CH340 `read(4096)` 阻塞 3.49 s），
曾算出 46 fps 假值（真值 19.6）。`485-perf [secs]` 把分母钉死为 **esp_timer 实测窗口时长**。

### 第一次真机测量（30 s 窗口，STM32 在发，单通道）

```
实测窗口 30000 ms
帧   : +599 帧 → 19.97 fps        （判据 ≥19）
字节 : +35341 B → 1178.0 B/s  帧长 59.00 B/帧（单通道）
样本 : +14975 → 499.2 /s   理论 15000
错误 : crc +0  resync +0 B  bad_len +0  seq_gaps +0
链路 : parity +0  frame_err +0  ovf +0  chunks +231  tx +0 B
环缓 : peak 100/5000  drop +0
内存 : int_heap 89 → 89 KB（Δ0）
⇒ PASS
```

**关键自洽**：599 帧 × 25 样本/帧 = **14975 = 实测 pushed 增量**，一帧不差
⇒ 帧内样本完整、无丢样本。`tx +0 B / 30 s` 顺带把 **T206 拍板⑤「RUN 态零下行」**验了。

### 起流流程（实测确认）

`485-start`（ESP32 侧开 UART1）≠ 让 STM32 出数据。**必须再发 `485-send start`（0x01）**，
STM32 才进 RUN。15:31 那次 `485-perf` 全 0 就是因为只 485-start、没发 0x01。

我原写「DRDY 周期 2000 µs」——**错**。

### 为什么给「固定 300 s」而不给时长参数

**溢出是静默截断**（只置 `s_dump_overflow`）⇒ 开放任意时长等于给一个
"看起来记了、其实丢了"的坑。猛哥 17:07 拍板：**只记 300 s，不带参数**。

### 32 KB 静态缓冲的风险评估（猛哥问）

`mem` 实测：内部 RAM 总 196 KB / 空闲 89 / **最大连续 40 KB**。
- 它是 `.bss` 静态数组，**开机占位，不是运行时 malloc** ⇒ 不产生堆碎片
- 但它吃掉 32 KB，正是"最大连续块只剩 40 KB"的主因之一
- 本项目已有实测支撑：性能测试 `int_heap` 89→89 KB，Δ0
- ⚠ `CONFIG_SPIRAM_ALLOW_BSS_SEG_EXTERNAL_MEMORY` **是关的** ⇒ 静态数组不能直接放 PSRAM
- 结论：现在不必挪；要长记录/内部 RAM 告急时再改（T215 §2.6 方案甲）
