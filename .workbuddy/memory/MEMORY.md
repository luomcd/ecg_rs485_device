## 1 判据与真值（别信直觉）

- 🛑🛑 **「RUN 态下行丢命令」不存在**。真凶＝**SWD attach**（`mode=hotplug` 每次 attach 都 halt 内核 ⇒ UART5 ORE ⇒ 该包只剩**尾巴**）。10 次 attach ⇒ `comm_rx_loss` +41。**测下行成功率时禁碰 SWD。**
- 🛑 **下行丢帧真值**（2026-11-09 已解决）：根因＝**UT-2211 无源电荷泵缺 +5 V**。接上 5V 后下行 50%→**100%**（50/50）、上行坏帧 1.4~2.3%→**0.000%**。🛑 **它不只影响下行**——上行也带 1.4~2.3% 的帧损坏（错误集中在帧头，富集 5.6 倍）。**「上行通下行不通」只是它最明显的症状，不是全部。**
- 🛑 **判双通道生效只看帧长**：`Δrx/Δframes`＝**109 B/帧**（59+50）。屏上画布切了**不代表**下行生效。
- 🛑 算速率分母必用**首末帧实测到达时刻差**：CH340 `read(4096)` 实测阻塞 **3.49 s**（≠标称 0.1 s），批量读把多帧打同一时间戳 ⇒ 曾报 46 fps 假值（真 19.6 fps / 495 Hz）。判 PASS 用**帧数**驱动。

## 2 协议门控（全是静默丢弃，不报错）

- **状态门**：`0x10`/`0x06`/`0x11` **必须** STOP 态；`0x01`~`0x05` 不加门。
- **长度门**：`0x04`/`0x05`/`0x06` 都要求 `argLen==2`，否则静默丢弃。
- **CRC8**：poly=0x07 / init=0x00 / 不反射，覆盖 `TYPE+LEN(2)+CMD+ARG`。🛑 代码注释里那四个 CRC **曾经全是编的**（真值 `FA/FD/C5/C2`）——动协议先跑一遍实算，别抄注释。

## 3 STM32 上游陷阱

- 🛑 UART5 RX（**PD2**）**必 `GPIO_NOPULL`**：上拉 40 k×模组 `PA12` 的 ESD 二极管分压 ⇒ **0.7 V** < 0.72 阈值 ⇒ RX 恒低、零字节。**断电量电阻 >3 MΩ ≠ 没下拉。**
- 🛑 读寄存器**必 `mode=hotplug`**（默认软复位 ⇒ 读回假空白）；缺 `ErrorCallback` ⇒ 一次 FE **永久失聪**。
- 🛑 STM32 侧 **CH2 ≡ CH1**（`ads1293.c:1533` 直接复制，不滤波不重采样）⇒ 真发了必然两路一样。

## 4 ESP32 侧陷阱

- 🛑 **上电全局日志被压到 ERROR**（`main.c`：`esp_log_level_set("*", ESP_LOG_ERROR)`）⇒ `click btn` / `clear -> idle` / `ecg_pipe: paused` / `restart from beginning` **默认一条都不打印**。任何靠日志判据的验收/探针，第一句必须 `log info`（`restart` 会复位回 ERROR）。
- 🛑 **`play` 在 RS485 源下是静默空操作**：`start_replay()` 见管线在跑就只调 `ecg_pipeline_set_file()` ⇒ 只置 `s_change`，而 **485 生产者从不消费它**；CLI 照样打印「纯回放中：波形在屏上」。先 `485-stop` 回 FILE 源。
- 🛑 **`485-start` ≠ 让 STM32 出数据**：它只开 ESP32 侧 UART1，**必须再发 `485-send start`（0x01）** 才进 RUN。只发前者时 `485-perf` 全 0，会被误判成"链路坏"（11-06 一天踩 3 次）。**ESP32 重启/烧录后同样要重来一遍**。
- 🛑 `485-send` 未 `485-start` 时**原地返回**（`Δtx=0`，不是发失败）。
- 🛑 **非 `0x01` 合法帧会被当样本**：`ecg_frame.c:125` LEN<hdr 时 `n_total` 下溢 65535 ⇒ `:137` clamp 50 ⇒ `:141` **越界读 99 B 且 CRC 仍过** ⇒ PC 每发一条下行＝屏上多 50 个垃圾点。规避：**先发 `0x01` 再敲 `485-start`**（`rs485_init` 有 `uart_flush`）。
- 🛑 `storage_sd_scan_files()` **只在 `main.c:349` 开机跑一次，无命令可重扫** ⇒ 换卡/加文件必 `restart` 或断电。
- 🛑 **清屏＝纯视觉动作**（T212／11-06 猛哥拍板方案 B）：**不 `restart()`、不归零回放位置、不改 `play`**。🛑 别再往清屏里加 `ecg_pipeline_restart()` —— 它 `fseek(0)` 会把进度拨回 0（5 min 数据在 1 min 处清屏＝白重看 1 min）；`app_action_clear()` **不得**再改 `play`（改了就与按钮文字分家，且连点两次行为相反）。要「从头看」用「回放」键。**自动回归用 `ui-clear`**（`ui_clear_apply()`，与按钮共用同一段，⚠ 只覆盖动作层、**不覆盖 LVGL 事件分发**）。生产者里 **`if(s_restart)` 仍必须排在 `if(s_paused)` 之前**（回放键靠 `restart()` 的"隐含恢复"起播）。

## 5 HRV / 测量判据（T218）

- 🛑 **时基只看 RR 中位数，别看拟合斜率**：多检让平均间隔变短 ⇒ 斜率偏小 ⇒ **伪装成"时基偏快"**。210 bpm 实测：斜率给出 +1.012%，中位数只有 **−0.100%**。斜率只在"无异常间期"时才可引用。
- 🛑 **σ(e) 别用「去趋势残差 std」**：峰位置是 RR 的**累加** ⇒ 残差是随机游走（std ∝ √k），会虚高 8 倍（实测 30.9 vs 真值 2.25 样本）。用 **σ(d2)/√6**（主）与 **σ(RR)/√2**（校验）两法互校，比值应在 0.7~1.4。
- 判定线：σ(e) ≤ **0.5 样本（1 ms）** = PASS（由「RMSSD 污染 <5%」反推）；>1 样本 = FAIL。
- 🛑 **链路有丢帧时，σ(e) 完全不可信**：5V 未接时 60 bpm σ=20 样本，接上 5V 后同一心率 **0.30**（接近量化极限 0.289）——那 20 全是丢帧造成的假象。**测 HRV 前先确认 `crc_err`/`seq_gaps` 增量为 0**。
- **现况（5V 后 6 心率 × 3 次）**：60/150/180/210 = **0.21~0.32（PASS）**；**90/120 = 2.72/5.93（FAIL）**。FAIL 的形态是「**单拍下降支误检**」——不是高心率退化、不是整数 RR（两者都已被数据推翻）。见 `docs/T221`。

## 5b QRS 检测器真因（T223 → Path B 离线重放，11-10 定）

- 🛑 **故障强度与信号幅度强相关**：同一算法，2 mV 时 σ(e)=2.6（FAIL），1 mV 时 0.30（假 PASS）。
  **「重放不复现现场故障」第一件事查幅度/增益**，别先怀疑算法移植错（11-10 为此白跑一整天）。
- 🛑 **真因 = 回溯路径 `locate_rpeak()` 覆盖不足**：`[trigger±40]` 落在 `filt_hist(140)` 之外 ⇒
  `found=false` ⇒ `return found ? best_idx : integrated_peak;` **原样返回 trigger、零精修**。
  90 bpm 实测回溯 trigger 落后当前样本 **212** 个，回溯峰 21/22 全部未精修 ⇒ 每个坏落点 2 个异常间期 ⇒ 42。
- 🛑 **修法选「候选入池即存 fid」（评审 Q2 双坐标），不要选「加大 filt_hist」**：所需历史
  = `1.66×RR−80+40` **随心率线性涨**（90→253 / 60→≈794 / 40→≈1170），512 在低心率必然失效且白吃 4 KB。
  fid 缓存零内存、与心率无关、主路径行为一字不改。离线实测两者在 90 bpm 都是 σ=0.35 PASS。
- 工具：`485tools/pc485_cmd.py`（PC 直接下行，绕开 ESP32）、`pc_sweep_replay.py`（采+比一条龙）、
  `replay_rpeak.py` 的 `RP_FID_MODE` / `--skip`。结案报告见 **`docs/T224`**（9 心率回归表 + 代码级根因）。
- 🛑 **原「缺陷 B」（无幅度/极性门）已结案：存在但极小，判定不做**（11-10 15:40，T227 §4）：
  MIT-BIH 48 条 / 108,900 拍里 `rr == REFRACTORY` 指纹 **8 例（0.0073%）**，形态真实
  （伪触发被接受 → 真拍卡在不应期边界）。但：①8 个 FP 只占总 FP 的 0.8%，加门收益 +0.01pt；
  ②幅度门要设 k≈0.35 才覆盖，还有一个 0.89 的拦不住；③**记录 108 的 TP 主极为负**，
  极性门会误杀其正常拍。⇒ **不做 C1/C2。**
  11-09 那 2 秒的事件率比这高约 **300 倍** ⇒ 仍归因输入瞬变，不是同一现象。
- 🛑 **MIT-BIH 基线（T227）**：48 条 108,887 拍，Se **99.11** / +P **99.09** / DER **1.80**；
  `fid` 修法 Se/+P/DER **零变化**，落点均值 5.72→5.00（p99 44→38）。
