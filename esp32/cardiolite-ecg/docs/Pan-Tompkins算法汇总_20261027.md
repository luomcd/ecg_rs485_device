# CardioLite · Pan-Tompkins 算法汇总（ESP32 侧）

**日期**：2026-10-27　**适用**：`cardiolite-ecg/main/ecg/ecg_rpeak.{h,c}`（147 + 319 行）
**目的**：给「ADS1293 EVM 路线（AECG100 播 MIT → EVM → PC）」建立**对照基线** —— 先把 ESP32 这侧到底实现了什么钉死，再谈两条路线怎么比。

---

## 0. 一句话

**这是 `WinApp_ADSECG/.../HeartRateDetector.cs` 的逐行 C 移植，判据一个都没省，只把 `double→float`。
真正与参考实现不一致的只有两处：`LocateRPeak` 窗 ±55→**±40**（Q6 定案）、以及 float 带来的单向偏多检。**

⚠ **不是标准 Pan-Tompkins。** 名字借了，判据层改了四处（见 §4），微分器也不是教科书的 5 抽头（见 §3.3）。拿教科书参数去调它一定对不上。

> **📌 先用一句记住两个数（本阶段唯一必须记住的口径差异）**
> **C# 参考端（WinApp）跑的是 LocateRPeak ±55，而 ESP32 基线是 ±40。**
> 两条路线对账前必须先对齐（见 §7.1），否则 55/40 的差异会盖过模拟链路那 ≤0.04 pp 的真实影响。

## 3. 实际频率响应（算出来的，不是注释抄的）

源码注释只写了"低通→高通→微分→平方→积分"，**没写通带**。这里把它算清楚，否则调参就是盲调。

### 3.1 三个一阶极点

| 级 | α | τ | f₋₃dB |
|---|---|---|---|
| 主基线（当高通用） | 0.002 | **1000 ms** | **0.159 Hz** |
| 低通 | 0.25 | ≈7 ms | **≈23 Hz**（离散精确值 23.05 Hz @fs=500） |
| 高通（相减式） | 0.05 | 40 ms | **4.08 Hz** |

> 🛑 **低通截止的两种算法（2026-10-30 订正）**：连续近似 `fc = −fs·ln(1−α)/2π = 22.9 Hz`；
> 离散精确解 `cos ωc = 1 − α²/(2(1−α)) = 0.958333` ⇒ `ωc = 0.28969 rad` ⇒ `fc = 23.05 Hz`。
> 两法都 ≈23 Hz，**写文档统一写 ≈23**，不要再出现 22.89 / 26.5 两个数（26.5 是错的）。

### 3.2 主能量分布（fs=500，N=60，平方后能量域）

| 分位 | 频带 |
|---|---|
| 50% 能量 | **11.8 ~ 37.2 Hz** |
| 80% 能量 | 15.3 ~ 59.9 Hz |
| 90% 能量 | 19.6 ~ 73.1 Hz |

⇒ 落在 QRS 的典型能量带（10~40 Hz）里，**低频端靠 4.08 Hz 高通砍掉 T/P 波与基线漂移**，这是它能压住 T 波误检的根本原因（不是靠后面那道 T 波判据）。

### 3.3 🛑 微分器是**四点**，不是教科书的五点

| | 系数 | @500 Hz 峰值 |
|---|---|---|
| 本实现 | `(2, 1, −1, −2)/8`，滞后 0,1,2,3 | **90.9 Hz** |
| 教科书 PT | `(2, 1, 0, −1, −2)/8`，滞后 0,1,2,3,4 | **68.9 Hz** |

本实现**少一阶滞后、峰值右移 22 Hz**。后果：对高频噪声（肌电、50 Hz 残留）比教科书更敏感，靠后面的积分窗压回来。
⇒ **别照教科书抄 5 抽头替换**，会连带动 `filteredHistory` 的时序对齐与 LocateRPeak 的偏移分布。

### 3.4 🛑🛑 积分窗是个**梳状滤波器**，50 Hz 恰好是它的第 6 个零点

60 样本滑动平均的零点在 `k·fs/N`：

| fs | 零点间隔 | 50 Hz 位置 | 50 Hz 处 \|H\| |
|---|---|---|---|
| **500**（正常） | 8.333 Hz | 50 / 8.333 = **6.000**（整数） | **0**（-∞ dB） |
| **853.2423**（raw853） | 14.221 Hz | 50 / 14.221 = 3.516（两零点之间） | 0.091（**-20.8 dB**） |

**两个结论**：

1. ✅ **fs=500 时工频被积分窗完全抵消，不需要陷波器。** 这解释了为什么固件里没有 50 Hz 陷波却看不到工频 —— 不是巧合就是巧，但**它依赖 fs 精确等于 500**。
2. 🛑 **raw853 下这个零点失效**：50 Hz 从"精确零点"掉到 -21 dB，而且此时 50 Hz 落在第 3→第 4 零点之间（**相位已反过一次**）。所以 S9 的 raw853 降级**不是简单的"降采样再跑同一套判据"** —— 判据的样本数常量（80/60/360/40）全部按 500 Hz 写死，一旦数据是 853 Hz：
   - 不应期 80 样本：160 ms → **93.8 ms**
   - 积分窗 60 样本：120 ms → **70.3 ms**
   - T 波门 360 样本：720 ms → **422 ms**
   - 50 Hz 抑制：-∞ → **-21 dB**

   ⇒ raw853 必须先重采样到 500 Hz，或者把全部常量按 853/500 = 1.7064 缩放。**这是 S9 的真实工作量，别低估。**

## 4. 判据层（四道，按执行顺序）

滤波器只负责"让 QRS 突出"，**检不检出来全看这四道**。

### 4.1 双阈值（`c:198-199`, `c:205`）

```
主阈值   thr1 = max(1e-12, noise + 0.25·(signal − noise))     ← 判"是不是峰"
副阈值   thr2 = max(1e-12, noise + 0.50·(signal − noise))     ← 判"要不要进候选池"
signal ← 0.125·value + 0.875·signal    （仅在 accept 时更新）
noise  ← 0.125·value + 0.875·noise     （判负时更新）
```
- 这是**经典 Pan-Tompkins 的 0.25 / 0.5 双阈值**，含"低阈值存候选、高阈值才接受"的两级结构。
- 🛑 阈值靠**前 6.15 s 的噪声自举**收敛 ⇒ 启动瞬态乱跳（实测 187→222→…→85→72→60）。这是参考实现的固有行为，不是移植 bug；UI 侧用 **3250 样本（6.5 s）保护窗**遮掉（`app_config.h:127`、`ui_bpm.c:76`）。

### 4.2 候选池（`c:208-216`，深度 64）

只要过副阈值就入池，**不管有没有被接受** —— 这是回溯搜索的素材库。池满丢最旧。

### 4.3 T 波门（`c:222-223`）

```c
is_twave = (spacing < 360) && (last_slope > 0) && (slope < last_slope * 0.5)
```
"离上个峰 <720 ms **且** 斜率不到上一个峰的一半 ⇒ 判为 T 波，丢弃并计入 noise"。
- 🛑 **这是 P1-1 的靶点**：判据只用"相对斜率"，对**形态异常但斜率正常**的 T 波（或相反：低幅真 QRS 紧跟高幅 PVC）会判错。全量表里形态异常类漏检 582 个与此相关。

### 4.4 不应期（`c:225`）

`spacing >= 80` 样本 = **160 ms** ⇒ 生理上限 **375 bpm**。

### 4.5 回溯搜索（`c:239-287`）

```
触发：距上一峰 > 1.66 × 最近5个RR的**算术平均**（不是中位数）
动作：在候选池里取 (last_peak+80, now−80) 区间内 value 最大者
再过一遍副阈值，接受后丢弃 index ≤ 它的全部候选
```
- 专治"QRS 幅度掉到主阈值以下、但过了副阈值"的漏检（低幅、基线漂移、伪差后）。
- 🛑 **实现依赖一条隐式不变量**：候选按 index 单调入队，所以"index ≤ X"一定是队首连续前缀。C 版用 `cand_n -= drop` 直接把计数往前推，**靠这条不变量才等价于 C# 的 `Dequeue()`**。将来若允许乱序入池，这里会静默错。

### 4.6 LocateRPeak（`c:44-72`）

在积分峰 ±W 内回看 `filteredHistory`（低通−高通后的 `value`），取 **\|value\| 最大**的点。
- 为什么用 `value` 而不是原始样本：此时 T 波/P 波已被 4.08 Hz 高通压掉，极值基本只有 R 峰。
- 🛑 **W 参与判据**：返回值写进 `last_peak`，参与 T 波门的 `spacing` 和不应期。所以 W 太宽 → **相邻心搏的更大极值被吸进来** ⇒ 不是"定位不准"，是**直接改变检出序列**。Q6 把 55→40 就是这个原因（RR=250 时 ±55 占 RR 的 44%）。

## 5. BPM 口径（`c:78-114` + `ui_bpm.c:74-92`）

**算法侧**（`update_bpm`）：
```
最近 5 个 RR → 过滤 [80, 1000] → **升序排序取中位数** → HR = 60·fs / RR_median
```
🛑 **是中位数不是均值**（需求 §5.3 写"均值"是错的，以源码为准）。中位数的好处是对单拍漏检/多检不敏感；代价是**对整体平移不敏感** ⇒ 「BPM 对」不等于「识别准」，必须拆四层看（`tools/check_rpeak_localization.py`）。

**显示侧三道门**（`ui_bpm.c:74-92`）：

| 顺序 | 条件 | 结果 |
|---|---|---|
| ① | 冻结中 | 保持冻结时刻的值（本函数不调用） |
| ② | 本 epoch 已喂 < **3250 样本**（6.5 s） | `--` |
| ③ | bpm ≤ 0 | `--` |
| ④ | 距上一峰 > **3 s**（且未暂停） | `--` |
| ⑤ | 其余 | `(int)(bpm + 0.5f)` |

🛑 **②按"已喂样本数"而不是墙上时间计时**：上电时管线是暂停的，若按时间算，用户 30 s 后才开播，窗口早过期 ⇒ 瞬态照跳。

🛑 **范围过滤（20~250）与稳定门控（连续 3 次互差 ≤5%）都被实测否决**：前者压不住 187/222/250/85/72，后者会把持续 0.6~1 s 的错值误判成"稳定"。

## 6. 跨核数据通路（改坏不报错）

检测器跑在 **Core 1 生产者任务**（`producer_task`，`ecg_pipeline.c:128`；`xTaskCreatePinnedToCore` `:382`，prio 5 低于 LVGL 6），UI 在 **Core 0**（消费者 `:393`，prio 3）。两者只交换"绝对样本号"。

```c
if (ecg_ring_push(&s_ring, v1, v2)) {
    const uint32_t newest_global = s_push_seq;
    s_push_seq = newest_global + 1u;              /* 🛑 永不重置 */
    if (ecg_rpeak_process(&s_rp, (float)v1, &pk) && pk >= 0) {
        const uint32_t fed  = (uint32_t)ecg_rpeak_sample_index(&s_rp);
        const uint32_t back = (fed - 1u) - (uint32_t)pk;
        rp_q_push(newest_global - back);          /* 发布：全局绝对号 */
    }
}
```
UI 侧：`ago = s_pulled_total - 1 - peak_abs`（`ui_waveform.c:493`）。

| 方案 | 结论 |
|---|---|
| **绝对样本号 + 两端计数器永不归零** | ✅ **现行**。`s_push_seq` / `s_pulled_total` 跨换文件/清屏都不归零 |
| epoch 归零式索引 | ❌ 归零时刻两边不同步 ⇒ **永久偏 25 样本** |
| 传 `ago` 相对年龄让 UI 累加 | ❌ 峰在一帧取数中途检出，"检出后到本帧结束"那 0~37 个样本补不进去 ⇒ **±25 样本随机误差** |
| `epoch` 的用途 | 仅作废陈旧标记，**不参与定位** |

🛑 两条硬约束：**只在 `ecg_ring_push()` 成功后**才喂检测器（丢样本时两边同步跳过，计数器才等价）；**冻结时 `sync_rpeaks()` 仍要跑**。

## 7. 与 C# 参考实现的差异清单（路线 A 必读）

| 项 | C# (`HeartRateDetector.cs`) | 固件 (`ecg_rpeak.c`) | 影响 |
|---|---|---|---|
| 数值精度 | `double` | `float` | 🛑 48 条实测：30 条逐位一致 + 3 条 1 峰换位 + 15 条**只多检**、0 条少检 ⇒ **单向偏多检** |
| **LocateRPeak 窗** | **±55**（`:238-239` 硬编码） | **±40**（`h:58`） | 🛑 **C# 侧未跟随 Q6**。同一份数据 PC 与板上会差约 1 拍/3600，难例更多 |
| 主基线慢跟踪 | 有 `baselineSlow`（α=0.0002） | 无 | 仅诊断字段，不参与判据 ⇒ 无影响 |
| `recent`/`amplitude` | 有（1500 深，每样本 `Max()`） | 无 | 仅赋给 `lastAmplitude` ⇒ 无影响。跳过还顺手免了 C# 的 O(n²) |
| `rawHistory` | 有（180 深） | 无 | 仅诊断 ⇒ 无影响 |
| 锁 | `lock(sync)` | 无（Core 1 独占） | 无影响 |
| 容器 | `Queue<T>` / `List<T>` | 定长环形数组 | 无影响（免动态分配） |

**唯一行为性差异 = LocateRPeak 窗 + float。** 其余全是诊断字段。

### 7.1 📌 路线 A 的前置动作

走「AECG100 → ADS1293 EVM → PC」这条路时，PC 端跑的是 **C# ±55**，而 ESP32 侧基线是 **±40**。
两条路线的数字要对得上，**必须先把 C# 的 55 改成 40**（一行改动，`:238-239`），否则差异会被误读成"模拟链路吃掉了精度"—— 而 §AFE 报告已经证明模拟链路只吃 ≤0.04 pp，这个 55/40 的差异反而更大。

## 9. 移植 / 上板注意（踩过的）

1. 🛑 **全部判据常量都是"样本数"，不是时间。** 换 fs 必须整体缩放，见 §3.4 的 raw853 清单。
2. 🛑 **`ECG_RP_LOCATE_HALF` 有 `#ifndef` 保护**（`h:57`），这是给 PC 夹具做窗宽扫描用的（`gcc -DECG_RP_LOCATE_HALF=30`）。固件编译时无人定义它。
3. 🛑 **`filteredHistory` 只有 140 深**，W 加到 >140 会静默降级（退化成返回积分峰索引）。
4. 🛑 **候选池"index ≤ X 即前缀"是隐式不变量**，改候选管理逻辑时别破坏它。
5. 检测器状态是**任务私有**，没有锁；任何跨核访问都要走 `rp_q`，别直接读 `ecg_rpeak_t`。
6. `ecg_rpeak_reset()` 保留 `fs` 重建其余（`c:147-151`），清屏/换文件走它。
