## 0. 一句话目标

用 **串口 CLI 命令作为测试总控入口**，引入显式的「测试模式状态机」：
上电正常进 UI + CLI；CLI 进入测试模式后 UI 按钮禁用、只当波形显示器；退出后按钮恢复。
批处理**保留**为「全速对账」的底层机制，从「上电自动」改为「CLI 登记 + 重启触发」。

## 2. 模式状态机（核心设计）

```
┌──────────────┐   test-mit / test-ladder   ┌──────────────┐
│   正常模式    │ ─────────────────────────▶ │   测试模式    │
│  UI 按钮有效  │                            │  UI 只显示     │
│  CLI 也可用   │ ◀───────────────────────── │  CLI 总控      │
└──────────────┘        test-exit           └──────────────┘
```

- 全局标志 `g_test_mode`（`NORMAL` / `MIT` / `LADDER`）。
- CLI 命令翻转它；UI 事件处理器读它决定「按钮响不响应」。

### 2.1 三种状态

| 状态 | 值 | UI 按钮 | CLI | 说明 |
|---|---|---|---|---|
| 正常 | `NORMAL` | ✅ 有效 | ✅ 可用 | 上电默认态 |
| MIT 测试 | `MIT` | ❌ 禁用（只显示波形） | ✅ 总控 | 跑 MIT 对账 |
| 阶梯测试 | `LADDER` | ❌ 禁用（只显示波形） | ✅ 总控 | 跑心率阶梯 |

## 3. 两种「跑」法（核心设计，务必分清）

CLI 要覆盖批处理的全部能力，而批处理和回放是**两种速度对立的跑法**，必须同时支持（方案 A：两套并存，各干各的）：

| 跑法 | 底层实现 | 速度 | 屏幕 | 数据源 | 输出 |
|---|---|---|---|---|---|
| **回放展示** | `ecg_pipeline_start(path, loop)` | 按 500Hz 节拍（可倍速） | 显示波形 | SD 文件 / 未来实时 | 波形 + **峰序列 printf（对账）** |
| **全速批处理** | `ecg_batch.c` 的 `run_one`/`run_manifest` | 能多快跑多快（30min 几秒） | **黑屏**（可接受）+ 串口进度提示 | SD 文件 | 峰序列 printf（对账） |

**关键**：回放展示**不只是目测波形 + 演示，也要对账 Se/+P**。即回放时边跑边 `printf` 峰序列，跑完和批处理一样能交给 `ecg_batch_eval.py` 对账（**Se/+P 由上位机 `ecg_batch_eval.py` 算，固件只输出峰序列**——决策「歧义 1」）。

### 3.1 数据源（决策 2，方案甲）

| 命令形态 | 数据源 | 现状 |
|---|---|---|
| `mit-run 105` / `ladder-run 060`（带参数） | SD 卡 `mit_105_500.bin` / `sr_060bpm.bin` | ✅ 现有管线已支持（回放） |
| `mit-run` / `ladder-run`（不带参数） | AECG100 → ADS1293 → ESP32 实时采集 | 🚧 **待开发**（§3.3） |

### 3.2 回放路径要「新增峰序列输出」

- 现有 `ecg_pipeline.c` 的 `producer_task` **已经在做 R 峰检测**（`ecg_rpeak_process`），峰推进队列供 UI 画点，但**没有 `printf` 峰序列**。
- 要对账，需在回放时**额外把每个峰的样本号 `printf` 出来**（格式同批处理的 `P <idx>` 行）。
- 这是回放路径唯一的增量改动（检测逻辑已存在，只补输出）。
- **峰序列输出方式（决策「歧义 2」）**：**边跑边打，开小缓冲一次打 n 个**（如每满 8~16 个峰 flush 一次），**不开大缓冲**。

### 3.3 倍速播放（决策「歧义 3」）

回放展示默认按 500Hz 实时节拍（30min 数据 = 30min），但为兼顾「看波形 + 对账」的效率，加**倍速选项**：

| 命令形态 | 说明 |
|---|---|
| `mit-run 105` | 默认 1x 实时播放 |
| `mit-run 105 --speed 2` | 2x 倍速（4x / 8x 可选） |

- 倍速实现：`producer_task` 的节拍周期 `period` 按倍速缩短（2x ⇒ 1ms/样本），波形滚动变快但仍可目测。
- 峰序列输出**不受倍速影响**（峰号是样本号，与播放速度无关）。

### 3.4 全速批处理「黑屏 + 进度提示」（决策「歧义 4」，2026-10-28 定）

- `mit-run-all` / `ladder-run-all` 走全速批处理时，**屏幕黑屏（可接受）**，这是批处理的固有特性（全速跑必然独占 CPU）。
- 串口输出**进度/标识提示**（如 `RUN mit_105_500.bin 2/48 ...`、`RUN-DONE mit_105_500.bin`），让人知道正在跑什么。
- ⚠ 实现约束：全速批处理仍放在 **LVGL 初始化之前**（沿用现有 `main.c` 的 `S7_BATCH` 位置），保证串口干净 + 速度正常，**不引入独立高优先级任务的复杂度和风险**。
- **清单分两份**（决策「各用各的清单」）：`mit-run-all` 跑 `batch_mit.txt`（只 MIT），`ladder-run-all` 跑 `batch_ladder.txt`（只阶梯）。现有 `make_sdcard_batch.py` 生成的单一 `batch.txt`（阶梯+MIT 混一起）需拆分适配。

### 3.5 实时采集（未来通道，占位不实现）

- 现在固件**没有** ADS1293 实时采集路径（只有 SD 回放）。
- 未来补「ADS1293 EVM → 485（或 IIC）→ ESP32」通道，展示实时数据。
- **待定**：485 还是 IIC。
- 本期只占位，命令不带参数时返回「通道未实现」提示。

## 3b. 🛑 峰号口径（对账能不能对上的关键）

两种跑法的峰号口径**不同**，回放路径要对账，必须统一成「文件内相对样本号」：

| 跑法 | 现在的峰号 | 对账需要 |
|---|---|---|
| 全速批处理 `run_one` | `pk` = `ecg_rpeak_process` 返回值 = **文件内相对样本号**（`init` 后从 0 累加） | ✅ 已是相对号，直接对 |
| 回放 `producer_task` | `newest_global - back` = **全局绝对样本号**（`s_push_seq` 跨文件永不归零） | ❌ 需转成**文件内相对号**才能用 `_ann500.txt` 对 |

**约束**：回放路径 `printf` 峰序列时，必须输出**文件内相对样本号**（与批处理一致），否则 `ecg_batch_eval.py` 拿同一个 `_ann500.txt` 对账会对不上。

**上位机解析依赖**（`ecg_batch_eval.py` 硬依赖，CLI 输出必须逐字节对齐）：
- 文件名必须是 `mit_<rec>_500.bin` / `sr_<bpm>bpm.bin`（解析器按 `mit_`/`sr_` 前缀认记录）。
- `FILE <name> frames= samples= bad= peaks= bpm=` 字段顺序不能变。
- `P <idx>...` 每行最多 16 个峰索引。

## 6. UI 按钮禁用机制（决策「歧义 5」）

- **进模式就禁**：`test-mit` / `test-ladder` 一执行，UI 按钮立即失效（`g_test_mode != NORMAL`），**不是**等跑命令才禁。
- 目的：**防止测试时误触按钮**，简单直接。
- 粒度 A（粗）：UI 事件回调入口 `if (g_test_mode != NORMAL) return;`。
- 测试模式下波形仍正常显示（管线照跑），仅按钮不响应。
- `test-exit` 退出后按钮自动恢复，无需额外处理。

### 9.5 🛑 关键设计约束：全速批处理「黑屏」与 CLI 常驻的时序矛盾

这是「黑屏可接受」决定带来的**矛盾，已定案解法 A**：

- 全速批处理按 `main.c` 现有逻辑放在 **LVGL 之前**（上电早期），此时**串口只能 printf 输出，CLI/REPL 还没起来**（REPL 要等上电后期启动）。
- 但需求是「CLI 命令触发批处理」（`mit-run-all`），意味着批处理要在 CLI 起来之后触发，这就回到「LVGL 之后跑批处理 → 慢 130 倍 + 串口交错」的老坑。

**✅ 定案：解法 A —— 命令「登记」，重启后自动跑。**

- `mit-run-all` / `ladder-run-all` 命令把「要跑批处理 + 跑哪个清单」写进 **SD 卡标记文件 `/sdcard/batch_pending.flag`**（内容为清单路径，如 `batch_mit.txt` / `batch_ladder.txt`），回复「已登记，请重启」。
- 重启后，`main.c` 在 LVGL 之前（SD 已挂载）读标记文件，取出清单路径并自动跑 `ecg_batch_run_manifest`，跑完删除标记文件。
- **代价**：多一次重启（可忽略）。
- **收益**：批处理速度 / 串口干净性 100% 保留，完全避开 `main.c:352` 的 130 倍 + 交错灾难。
- `mit-run <rec>`（回放）**不受影响**——回放走 `ecg_pipeline`，本就是节拍播放、和 UI 天然共存。
