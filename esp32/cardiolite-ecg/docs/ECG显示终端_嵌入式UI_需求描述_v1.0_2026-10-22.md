## 2. 数据源：SD 卡回放

### 2.1 为什么第一阶段不走 RS485

板载 RS485（SP3485，GPIO43=RXD / GPIO44=TXD，方向硬件自动切换）在硬件上可用，但**采集端（ADS1293 板）当前只有 USB CDC，没有 485 收发器**。贸然上 485 需要先改采集端硬件。

因此第一阶段改为 **SD 卡回放**：把采集端录制好的原始字节流拷到卡上，终端读文件回放。

这也是个架构优势：**数据源做成抽象层**，将来切 485 只换"读文件"为"读 UART"，解析、缓冲、绘制、检测全部复用。

### 2.2 文件格式

录制源：参考工程「● 记录」按钮产出的 `recordings\ecg_{yyyyMMdd_HHmmss}.bin`，内容为**收到的原始字节流原样**（含帧头与 CRC，`Storage/Recorder.cs`）。

终端解析规则（不得按固定 58 字节硬切）：

```
AA 55 | TYPE(1) | LEN(2, LE) | PAYLOAD(LEN) | CRC8(1)
帧总长 = 6 + LEN
```

| 帧型 | LEN | 总长 | 含义 |
|---|---|---|---|
| 显示帧（v1.1 旧） | 52 | 58 | 单通道，无 STA |
| 显示帧（v2.2） | 53 | 59 | 单通道，含 STA |
| 显示帧（双通道） | 103 | 109 | CH1 25 点 + CH2 25 点，**块布局不交错** |

> 🛑 参考工程 `Core/ReplaySource.cs:35-40` 里 `const int frameSize = 58` + `Thread.Sleep(50)` 是**按 58 硬切**的写法，只在单通道旧帧下成立。双通道文件（109 B）会立刻错位，终端不得照抄。

### 2.3 回放节奏

每 **50 ms** 输出一帧（25 样本/通道）= **500 样本/s**，与实时链路同节奏，保证走纸/时窗换算与实机一致。

### 2.4 文件组织【待确认】

三选一，未拍板：

- **A**：固定文件名（如 `/sdcard/ecg.bin`），换数据就换卡 —— 实现最简
- **B**：开机扫描目录列文件，点击选择 —— 需要额外一屏列表
- **C**：单个文件循环播放

默认为 **A**，切 C 只需一个标志位。

### 2.5 通道数【待确认】

现有样本 `1mv-2026-09-11 155357.txt` 解出 `LEN = 0x34 = 52` ⇒ **单通道、无 STA 的 v1.1 旧帧**。

单通道文件下画布 2 全程显示「无数据」。需确认是接受此状态，还是补录一份双通道数据。

## 4. 波形绘制与标定

> 核心公式全部沿用参考工程，**横纵解耦**这一条不得回退（见 `EcgWaveformControl.cs:136-145` 的警告）。

### 4.1 横向 —— 纸密度常数

| 概念 | 公式 | 本工程取值 |
|---|---|---|
| 纸密度 | `mmX = plotW ÷ 125` | `752 / 125 = ` **6.016 px/mm**（常数，不随走纸变） |
| 可见跨度 | `VisibleWindowSeconds = 5 × 25 ÷ 走纸` | 12.5→**10 s**｜25→**5 s**｜50→**2.5 s** |
| 每样本像素 | `pxPerSample = mmX × 走纸 ÷ 500` | 12.5→**0.150**｜25→**0.301**｜50→**0.602** |

- 最新样本贴右边界，数据从右往左生长（启动初期不被拉伸）
- 取数点数 = `VisibleWindowSeconds × 500`，缓冲容量按最长 10 s ⇒ **5000 样本/通道**

### 4.2 纵向 —— 恒 ±5 mV 满量程

| 概念 | 公式 | 本工程取值 |
|---|---|---|
| 纵向毫米基准 | `mmY = plotH ÷ 50`（50 mm = 2 × 5 mV × 5 mm/mV） | `200 / 50 = ` **4.0 px/mm** |
| 每 mV 像素 | `pxPerMilliVolt = 增益 × mmY` | 默认增益 5 ⇒ **20 px/mV** |
| 可见量程 | `2 × 5 mV × 5 ÷ 当前增益` | 默认 **10 mV 峰峰 = ±5 mV** |

| 增益 | px/mV | 可见量程 | 1 mV 标尺高 |
|---|---|---|---|
| 2.5 | 10 | ±10 mV | 10 px |
| **5（默认）** | **20** | **±5 mV** | **20 px** |
| 10 | 40 | ±2.5 mV | 40 px |
| 20 | 80 | ±1.25 mV | 80 px |

**分辨率后果（知情接受）**【推算】：

| 波形成分 | 幅度 | 默认增益下高度 |
|---|---|---|
| QRS | 1~2 mV | 20~40 px |
| T 波 | 0.2~0.3 mV | 4~6 px |
| **P 波** | **0.1~0.2 mV** | **2~4 px** |

双画布各 216 px 是**已拍板**的结构，P 波只剩 2~4 px 是这个结构的必然代价，不再讨论。

### 4.3 网格

- 小格 1 mm（横 6.016 px / 纵 4.0 px），大格每 5 小格（横 30.08 px / 纵 20 px）
- 毫米基准 < 1 px 时只画大格（防止每帧上千条线，参考 `:334-338` 的同类保护）
- 0 基线恒在 plot 垂直中点，不随数据长度变

参考工程 `:371-383` 明确记录了这条：写死 `10 × mm` 会导致增益换档后**标尺说谎**。

## 5. 心率 / R 峰检测

### 5.1 算法来源

移植参考工程 `Processing/HeartRateDetector.cs`（**355 行**）的 Pan-Tompkins 变体。关键常量（`:26-34`）：

```
SampleRate              = 500 Hz
LowPassAlpha            = 0.25
HighPassAlpha           = 0.05
IntegrationWindowSamples= 60      (120 ms)
RefractorySamples       = 80      (160 ms)
MinimumRrSamples        = 80      (160 ms)
SlowBaselineAlpha       = 0.0002
```

流水线：`低通 → 高通 → 三点微分 → 平方 → 60 样本积分 → 自适应阈值(signal/noise) → 不应期`

### 5.2 移植改动

| 项 | 原实现 | 移植后 | 原因 |
|---|---|---|---|
| 浮点类型 | `double` | **`float`** | S3 只有单精度硬件 FPU，`double` 走软浮点慢约 10 倍 |
| 队列 | `Queue<T>` | 环形数组 | 避免动态分配；各窗长固定（60/80/200 项） |
| 线程同步 | `lock` | 无锁（单核独占） | Core 1 独占，不存在并发写 |
| 代码量 | 355 行 C# | 约 300 行 C | — |

### 5.3 计算量【推算】

每样本约 30~50 次乘加 ⇒ `500 Hz × 50 = 25 kFLOP/s`。ESP32-S3 @240 MHz 单精度 FPU 理论 >100 MFLOP/s ⇒ **占用 < 0.1%**。一个核带这点负载是极大的浪费，实际这个核还要跑数据管线（读卡 + 解析 + 缓冲）。

### 5.4 BPM 口径

- 显示值 = 最近 **5 个 RR 间隔**的均值反算，四舍五入到整数
- R 峰检出后 **3 个 RR** 才开始显示（不足时显示 `--`）
- 超过 **3 s** 无新峰 ⇒ BPM 归 `--`（不得停在旧值）
- 范围限制 20~250 bpm，超范围丢弃

## 6. 双核任务划分

```
Core 0 ── LVGL 渲染任务（esp_lv_adapter 的 task）
      ── 触摸事件 → 按钮状态机
      ── 波形绘制（消费样本队列）

Core 1 ── 数据源任务：读 SD 卡 → 帧解析 → 写入环形缓冲
      ── R 峰检测：逐样本消费 → 峰值索引 + BPM
```

### 6.1 必须改的配置

`sdkconfig` 现为 `CONFIG_EXAMPLE_LVGL_PORT_TASK_CORE=1`（LVGL 跑在 Core 1，继承自厂家 demo）。**必须改为 0**，把 Core 1 让给信号处理。

### 6.2 跨核通信

| 数据 | 方式 | 说明 |
|---|---|---|
| 波形样本 | 环形缓冲 + 读写指针（原子操作） | Core 1 写、Core 0 读，**不共享可变游标** |
| R 峰索引 | 定长队列（深度 64） | Core 1 入队，Core 0 取走用于打点 |
| BPM | 单变量 + 版本号 | 双字写入，读侧比对版本防撕裂 |
| UI 命令 | FreeRTOS 队列 | 按钮 → Core 1（清屏、启停） |

**不得在 Core 0 的绘制路径里做任何阻塞操作**（不读 SD、不申请大块内存）。

### 6.3 内存预算【推算】

| 项 | 容量 | 位置 |
|---|---|---|
| 波形缓冲（2 通道 × 5000 × 4 B） | 40 KB | 内部 RAM |
| 画布位图（2 × 800 × 216 × 2 B） | 691 KB | PSRAM |
| LVGL 显示缓冲 | 由 adapter 管理 | PSRAM |
| SD 读缓冲 | 4 KB | 内部 RAM |
| 代码 + 字库 + 资源 | < 1 MB | Flash |

## 8. 交互状态机

### 8.1 按钮语义

| 按钮 | 停止态 | 运行态 | 冻结态 |
|---|---|---|---|
| 开始/停止 | 显示`开始`，可点 | 显示`停止`，可点 | 可点（停回放） |
| 冻结 | 禁用（灰） | 显示`冻结`，可点 | 显示`继续`，高亮 |
| 清屏 | 可点 | 可点 | 可点（清完仍冻结） |
| 增益/走纸/模式/陷波/通道 | 可点 | 可点 | 可点 |

### 8.2 冻结语义

**冻结只停绘制，不停数据管线** —— 样本继续进环形缓冲，解冻后立刻显示最新数据（参考 §5.6「冻结 / 继续」的定义）。冻结期间 BPM 保持在冻结那一刻的值，不解冻不更新。

### 8.3 清屏语义

清空波形缓冲 + R 峰队列 + BPM（归 `--`）+ 重画网格。清屏**不重置**文件播放位置【待确认：是否要"回到文件开头"】。

### 8.4 模式 / 陷波 / 通道 在回放阶段的语义【待确认】

这是本稿最大的开放问题。三个参数在真实系统里是**发给采集端**的命令（协议 `0x04/0x05/0x06`），回放时采集端不存在，点了不产生数据变化。三种处理：

| 方案 | 做法 | 代价 |
|---|---|---|
| A | 按钮只改高亮，波形不变 | 零成本，但演示时显得"假" |
| **B** | 在终端侧对**显示数据**做实际滤波：陷波切 50 Hz 陷波器、模式切诊断/监护两套带通参数；通道切画布 2 显示哪一路 | 多写 2 个 IIR 滤波器，但按钮真的改变画面 |
| C | 第一阶段灰显禁用 | 最诚实，但少了演示效果 |

**推荐 B**：陷波和模式在终端侧做滤波本来就有独立价值（采集端 dump 下来的原始数据常常需要二次滤波看效果），而通道切换在双通道文件下天然有意义。

## 9. 明确不做（第一阶段）

| 项 | 原因 |
|---|---|
| RS485 实时链路 | 采集端无 485 收发器，见 §2.1 |
| I2C 数据链路 | 最终形态，第二阶段 |
| SD 卡录制 | 本阶段 SD 只读不写 |
| 协议下行命令（START/STOP/SET_*） | 无采集端可发 |
| 配置校验 / 快照比对 | 那是上位机测 AFE 的功能，终端不需要 |
| 文件列表页 | 见 §2.4，默认固定文件名 |
| 截图 / 波形导出 | 无 |
| 鼠标游标读数 / 双游标 | 触摸屏不适合精确定位，且原工程也未实现 |
| LVGL 升级到 9.x | 8.4 已验证，升 9 要重写显示适配层，收益不抵风险 |
| WiFi / BLE 上传 | 无需求 |

## 11. 验收判据

| 项 | 判据 | 方式 |
|---|---|---|
| 布局 | 各区域坐标与 §3.1 逐像素一致 | 截图比对 |
| 网格 | 1 mV 纵向 = 20 px ± 1 px（默认增益） | 画已知幅度方波，量像素 |
| 走纸 | 25 mm/s 下可见窗口 **5.0 s ± 0.1 s** | 数 R 峰个数或量两峰间距 |
| 标尺 | 1 mV 标尺高度随增益变（20/40/80 px） | 切换增益观察 |
| 波形 | 走纸换档后横向缩放可见，纵向不变 | 目视 |
| BPM | 与实际心率误差 ≤ 2 bpm（60~120 bpm 区间） | 用已知心率文件回放 |
| 帧率 | 稳定 ≥ 20 FPS，无可见撕裂 | `lv_timer` 计数 + 目视 |
| 稳定性 | 连续回放 30 min 无重启、无内存泄漏 | 长跑观察 heap |
| 触摸 | 8 个按钮全部可点，无误触相邻按钮 | 手点 |
