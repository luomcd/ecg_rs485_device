## 2. 数据源：SD 卡回放

### 2.1 为什么第一阶段不走 RS485

板载 RS485（SP3485，GPIO43=RXD / GPIO44=TXD，方向硬件自动切换）硬件可用，但**采集端（ADS1293 板）当前只有 USB CDC，没有 485 收发器**。上 485 需先改采集端硬件。

因此第一阶段为 **SD 卡回放**。数据源做成抽象层，将来切 485 只换「读文件」为「读 UART」，解析、缓冲、绘制、检测全部复用。

### 2.2 文件格式

文件名固定 **`/sdcard/ecg.bin`**，只存一个，再存覆盖。内容为**原始字节流原样**（含帧头与 CRC，来源为参考工程「● 记录」的 `recordings\ecg_*.bin`）。

```
AA 55 | TYPE(1) | LEN(2, LE) | PAYLOAD(LEN) | CRC8(1)
帧总长 = 6 + LEN
CRC8：多项式 0x07、初值 0x00，范围 = TYPE + LEN + PAYLOAD
```

| 帧型         | LEN | 总长  | 样本数 N | 说明                             |
| ---------- | --- | --- | ----- | ------------------------------ |
| 显示帧 v1.1 旧 | 52  | 58  | 25    | **无 STA**                      |
| 显示帧 v2.2   | 53  | 59  | 25    | SEQ(2) + STA(1) + 25×int16     |
| 显示帧 双通道    | 103 | 109 | 50    | CH1 25 点 + CH2 25 点，**块布局不交错** |

**样本数解析口径**：`N = (LEN − 3) / 2`（LEN 为奇数，含 STA）；LEN 偶数时 `N = (LEN − 2) / 2`。  
🛑 **严禁按固定 58 字节硬切** —— 参考工程 `Core/ReplaySource.cs:35-40` 的 `const int frameSize = 58` 只在单通道旧帧下成立，双通道 109 B 会立刻错位。

### 2.3 回放节奏

每 **50 ms** 输出一帧 = **500 样本/s**，与实时链路同节奏。

文件播完（按累计时长判定）⇒ 回放状态置 `ended`，按钮变「重播」。

### 2.5 双通道的真实情况【实测】

`ecg_20260928_113120.bin` 是真双通道帧（LEN=103，1775 样本/通道），但：

```
CH1 == CH2 逐位相同：1775 / 1775（100.0%）
CH1 range: -623 ~ 5634 ；CH2 range: -623 ~ 5634
STA = 0x06 → mode=诊断, notch=开, channel=I&II, raw853=0
```

**固件 `CH2 ≡ CH1` 逐位复制**，双画布在这份数据上会画出两条完全重合的线。

协议 v2.2 §3.1 亦有对应口径：「`channel=I&II` 的『数据上传 → 显示』不验收（无输入源）」。

⇒ 第一阶段画布 2 显示「无数据」；真正的第二路信号到位后再启用。**演示时不得把两条重合线说成「两个导联」。**

> **2026-10-27 订正（两处，均由实测决定）**
>
> 1. **底板必须不透明。** 原稿写 `rgba(255,255,255,0.9)`，实测 α 混合 160×50 = 8000 px
>    每帧额外 **2.3 ms**（S7 报告 §6.4）。浮层落在画布范围内 ⇒ 画布每帧 invalidate 时它必然重绘，
>    这 2.3 ms 是**每帧固定成本**。改为不透明后省下这笔，视觉上仅差 10 % 白度，肉眼不可辨。
> 2. **单位 11 px → 12 px。** 11 px 中文子库里没有，`bpm` 走 Montserrat 12 px 才有对应字形；
>    11 px 会触发 LVGL 字形查找失败并回退到默认字体，实测字号不一致。
>
> 另：浮层位置由"右上"改为**右下**（见 §3.1 表）。原位置会与画布 1 的右上角标
> （`5.0 s 窗口 / 500.0 Hz`）重叠，而角标是独立 label、浮层在画布内，两者相交后角标每帧陪着重绘。

做成浮层而非顶栏，是为把 480 px 全给两个画布：有顶栏时画布仅 190 px，无顶栏 216 px，**1 mV 从 17.6 px 提升到 20 px**。

> 🛑 **深色的网格必须重新设计，不是简单反色**：浅色下网格是"略暗于背景"的辅助线；深色若照搬，网格会因亮度差过大而抢波形重心。B 方案把小格压到 `#1C222A`（几乎不可见）、大格 `#2A323C`（勉强可辨），只保留大格与基线参与读数。
>
> ⚠ **IPS 屏深色不省电**（背光恒定 550 cd/m²，不像 OLED 靠像素自发光）。选深色只为观感与抗环境光。

### 3.5 配色切换机制

| 项   | 规定                                        |
| --- | ----------------------------------------- |
| 默认  | 浅色纸（A）                                    |
| 入口  | **长按 BPM 浮层 2 s** 在 A ↔ B 之间切换（不占用按钮位）    |

## 4. 波形绘制与标定

> 核心公式沿用参考工程，**横纵解耦不得回退**（`EcgWaveformControl.cs:136-145` 有明确警告）。

### 4.1 横向 —— 纸密度常数

| 概念    | 公式                  | 取值                                       |
| ----- | ------------------- | ---------------------------------------- |
| 纸密度   | `mmX = plotW ÷ 125` | **6.016 px/mm**（常数）                      |
| 可见跨度  | `5 × 25 ÷ 走纸`       | 12.5→**10 s**｜25→**5 s**｜50→**2.5 s**    |
| 每样本像素 | `mmX × 走纸 ÷ 500`    | 12.5→**0.150**｜25→**0.301**｜50→**0.602** |

最新样本贴右边界；缓冲容量按最长 10 s ⇒ **5000 样本/通道**。

### 4.2 纵向 —— 恒 ±5 mV 满量程

| 概念      | 公式                 | 取值                  |
| ------- | ------------------ | ------------------- |
| 纵向毫米基准  | `mmY = plotH ÷ 50` | **4.0 px/mm**       |
| 每 mV 像素 | `增益 × mmY`         | 默认 5 ⇒ **20 px/mV** |

| 增益        | px/mV  | 可见量程      | 1 mV 标尺高  |
| --------- | ------ | --------- | --------- |
| 2.5       | 10     | ±10 mV    | 10 px     |
| **5（默认）** | **20** | **±5 mV** | **20 px** |
| 10        | 40     | ±2.5 mV   | 40 px     |
| 20        | 80     | ±1.25 mV  | 80 px     |

**分辨率后果（知情接受）**【推算】：QRS 1~~2 mV ⇒ 20~~40 px；T 波 0.2~~0.3 mV ⇒ 4~~6 px；**P 波 0.1~~0.2 mV ⇒ 2~~4 px**。  
双画布各 216 px 是已拍板结构，P 波 2~4 px 是其必然代价。

### 4.3 网格 / 标尺 / 角标

- 小格 1 mm，大格每 5 小格；毫米基准 < 1 px 时只画大格
- 定标标尺：左上角方形 1 mV 脉冲，**高度 = 增益 × mmY**（随增益变，不得写死）
- 左上角标：`导联 I · CH1 = IN2−IN1`
- 右上角标：`5.0 s 窗口 / 500.0 Hz`（**BPM 浮层已移至右下，角标不再需下移避让**）

### 4.4 覆盖文案

| 场景       | 文案                            |
| -------- | ----------------------------- |
| 画布 2 无数据 | `单通道文件（导联 I）— 画布 2 无数据`       |
| SD 无文件   | `SD 卡无数据文件 — 请插入含 ecg.bin 的卡` |
| 冻结       | `已冻结 — 点「冻结」恢复`               |

### 4.5 渲染性能预算【2026-10-27 已实测，原推算作废】

| 项                          | 原推算（v1.2 稿）                   | **实测（S4/S6/S7）**                          |
| -------------------------- | ------------------------------- | ------------------------------------------ |
| 画布像素量（2 × 800×216×2 B）     | 691 KB（PSRAM）                  | ✅ 一致；framebuffer 实为 **3 个 = 2,304,000 B**（三缓冲抗撕裂，硬编码） |
| PSRAM 写到 20~40 MB/s ⇒ 全屏重绘 | 17~35 ms                        | ❌ **低估 2~3 倍**：单帧 PSRAM 峰值 **79 MB/s**（面板 32 + canvas fill 20 + canvas→fb 拷贝 27） |
| 目标刷新率                      | **20 FPS**（50 ms，与数据节拍对齐）      | ❌ **达不到**：**13.6 FPS**（渲染 25.5 ms，dt=[65,76]） |

**实测帧率全表（fps 必须带条件，否则没有意义）**

| 条件 | 帧率 | 渲染耗时 |
|---|---|---|
| **gain 5 / 25 mm/s / 单通道 / 有波形（生产版基线）** | **13.6 FPS** | 25.5 ms |
| gain 20 / 25 mm/s / 单通道 / 有波形 | **9.7 FPS** | 52.2 ms |
| 空载（无波形） | 14.1 FPS | 23.5 ms |
| 双通道 / gain 20 | 9.8 FPS | 52.8 ms |

**三条硬结论**

1. **瓶颈不是"画波形"，是"每帧往 PSRAM 写 300 KB canvas"。** 每帧 71 ms 的分解是：
   `canvas_fill 15 + 网格 6 + 波形 2 + vsync 等待 24 + canvas→fb 拷贝 22`。波形绘制只值 2~3 ms。
2. **提高 pclk 反而更慢**：16 MHz → 24 MHz 时帧率 14.0 → **11.6**。因为面板经 LCD_CAM 持续从
   PSRAM 读 framebuffer（32 → 48 MB/s），与 CPU 的 canvas 读写抢同一块 PSRAM。**pclk 必须保持 16 MHz。**
3. **帧率对增益极敏感**（竖线长度 ∝ 波形高度）。任何 fps 数字都必须标增益，
   否则不同人测出的数会差 45 % 却都"没错"——S6 报告里"双通道 9.8 FPS"其实主要是 gain=20 造成的。

接口优先级：① `lv_canvas` 全量重绘波形层（网格层单独缓存）；② **不做脏矩形**（实测
"被遮挡⇒不用刷"在本平台会丢整段波形，见 S7 §6.14.1）；③ **不用 `lv_chart`**。

## 5. 心率 / R 峰检测

### 5.1 算法来源

移植 `Processing/HeartRateDetector.cs`（355 行）的 Pan-Tompkins 变体。关键常量（`:26-34`）：

```
SampleRate=500  LowPassAlpha=0.25  HighPassAlpha=0.05
IntegrationWindowSamples=60(120ms)  RefractorySamples=80(160ms)
MinimumRrSamples=80(160ms)  SlowBaselineAlpha=0.0002
```

流水线：`低通 → 高通 → 三点微分 → 平方 → 60 样本积分 → 自适应阈值 → 不应期`

### 5.2 移植改动

| 项  | 原          | 移植后         | 原因            |
| -- | ---------- | ----------- | ------------- |
| 浮点 | `double`   | **`float`** | S3 仅单精度硬件 FPU |
| 队列 | `Queue<T>` | 环形数组        | 免动态分配         |
| 同步 | `lock`     | 无锁          | Core 1 独占     |
| 规模 | 355 行 C#   | 约 300 行 C   | —             |

计算量【推算】：约 25 kFLOP/s ⇒ 占用 <0.1% CPU。

### 5.3 BPM 口径

> **2026-10-27 订正（整节重写，四条全部以源码与实测为准）**
> 原稿四条里，第 1 条与实现不符（写"均值"、实为"中位数"），第 4 条缺"不得据此过滤"的约束，
> 另缺"启动保护窗"这一条 —— 而它正是解决启动瞬态的唯一有效手段。

- 最近 **5 个 RR** → 过滤 `[80, 1000]` → **排序取中位数** → `HR = 60 × fs / rr`，四舍五入
- 检出 **3 个 RR** 后才显示，否则 `--`
- 超过 **3 s** 无新峰 ⇒ 归 `--`（**暂停/冻结时不判**，否则暂停后会先闪一个 `--`）
- **启动 / 换文件 / 清屏后 6.5 s 内一律显示 `--`**（= 已喂满 **3250 样本**才开门）
- 有效范围 20~250 bpm，**但严禁据此做范围过滤**

**为什么是中位数不是均值**（源码 `ecg_rpeak.c` 的 `AcceptPeak()` 明确是 median）

单个异常 RR 就能把 5 点均值拉偏：漏检一拍会产生 2×RR，早搏会产生 0.6×RR。
取中位数后，5 点里坏 2 个仍能得到正确值；均值则直接偏 20 %。需求原稿写"均值"是笔误，
**以源码为准**（这也解释了 Q3 为什么必须闭环：两种口径在实测里差了 30 %）。

**为什么稳定窗按"样本数"而不是"墙上时间"**

上电后是**暂停态**，样本不进来。若按时间算 6.5 s，暂停期间窗口就"过期"了，
一按开始立刻显示乱值。按已喂样本数算，才能真正等价于"攒够 6.5 s 的数据"。
实测开门时间 **6.82 s**（S7 报告 §3.4）。

**为什么不能拿"有效范围 20~250 bpm"做过滤**

S7 实测的启动瞬态持续 **6.15 s**，期间读数在 **187 / 222 / 250 / 85 / 72 / 326** 之间乱跳 ——
**这些值几乎全部落在 20~250 范围内**，范围过滤一个也压不住。同理"连续 N 次一致才算稳定"的门控
也被否决：错值会连续维持 0.6~1.0 s，会被误判成稳定。
⇒ 只能靠**保护窗**（时间上不让它显示），不能靠**数值判据**（试图认出哪个值是错的）。

## 6. 双核任务划分

```
Core 0 ── LVGL 渲染 + 触摸事件 + UI 状态机
Core 1 ── 数据源（读 SD / 帧解析 / 写环形缓冲）+ R 峰检测
```

> **2026-10-27 补充（两条纪律，S7 踩出来的，写进需求以免重犯）**
>
> **① R 峰检测必须挂在 `ecg_ring_push()` 成功之后，不能先喂检测器再入环。**
> 环缓满时会丢最新样本（§4.3），此时若检测器已经吃掉了这个样本，它的
> `sample_index` 就比 UI 的「已取样本数」多 1，且**这个偏差是永久的、不会自愈** ——
> 反复丢样本会让峰标记越画越偏。挂在 push 成功之后再喂，两边同步跳过丢掉的样本，
> 计数器才永远等价。
>
> **② 跨核只传「相对年龄 `ago`」，绝不传绝对索引。**
> 生产者在检测当场算出 `ago = sample_index − 1 − peak_index` 发布；UI 每帧把 `ago`
> 加上本帧取走的样本数，收到时再减环缓水位。这样**两边完全不需要计数器对齐**。
> 首版传绝对索引 + epoch 归零，在暂停/换文件/清屏的边界上永久偏一帧（25 样本），
> 表现为红点画在下降支、最新一两拍被裁掉（S7 报告 §6.11）。

### 6.1 必须改的配置

`sdkconfig` 现为 `CONFIG_EXAMPLE_LVGL_PORT_TASK_CORE=1`（继承厂家 demo）⇒ **必须改为 0**，把 Core 1 让给信号处理。

### 6.2 跨核通信

| 数据    | 方式                         |
| ----- | -------------------------- |
| 波形样本  | 环形缓冲 + 原子读写指针（**不共享可变游标**） |
| R 峰索引 | 定长队列（深度 64）                |
| BPM   | 单变量 + 版本号（防撕裂）             |
| UI 命令 | FreeRTOS 队列                |

**Core 0 的绘制路径不得有任何阻塞操作**（不读 SD、不申请大块内存）。

## 8. 交互状态机

### 8.1 第九个按钮：回放 / 记录

**第一阶段（回放）**

| 条件             | 显示                 | 行为          |
| -------------- | ------------------ | ----------- |
| SD 无 `ecg.bin` | `回放` + `无数据`，灰显    | 不可点         |
| 有文件，idle       | `回放` + `SD 35.2 s` | 点击开始播放      |
| playing        | `暂停` + `播放中`，高亮    | 点击暂停        |
| paused         | `播放` + `已暂停`，高亮    | 点击继续        |
| ended（播完）      | `重播` + `已播完`       | 点击从头播放（清缓冲） |

**长按 1.5 s（任意可点状态）** ⇒ 弹出删除确认对话框「删除录制数据？」，含「取消 / 删除」两个按钮；确认后删除 `ecg.bin`，按钮转为灰显。

> 为什么用长按而不是双击：LVGL 无原生双击事件，做双击必须让单击等待 300 ms 才能确认，**回放点击会有明显迟滞**；长按与单击零冲突，且是嵌入式设备的标准手势。

**第二阶段（实时）**

| 条件        | 显示              | 行为               |
| --------- | --------------- | ---------------- |
| 未点「采集·开始」 | `回放`（SD 有文件时）   | 同第一阶段            |
| 已点「开始」    | `记录` + `SD 覆盖写` | 点击开始录制，显示 REC 计时 |
| recording | `停止` + `计时中`，标红 | 点击停止录制并 flush    |

⚠ **「记录」在第一阶段不实现**（无实时数据源，本阶段只仿真界面形态）。实现时机 = 接上采集链路。

### 8.2 采集（开始/停止）按钮

- 第一阶段：**灰显不可点**
- 第二阶段：可点；点击后第九个按钮从「回放」变「记录」
- 回放进行中：**灰显**（回放时「开始/停止」无效，与需求一致）

### 8.3 冻结语义

**冻结只停绘制，不停数据管线** —— 样本继续进环形缓冲，解冻后立刻显示最新数据。冻结期间 BPM 保持冻结时刻的值。

### 8.4 清屏语义

清空波形缓冲 + R 峰队列 + BPM 归 `--` + 重画网格。**播放状态与回放位置均不变。**

> **2026-11-06 订正（猛哥拍板，T212）：删除原稿的「回放位置归零」。**
>
> 原稿写「清空波形缓冲 + R 峰队列 + BPM 归 `--` + 重画网格；**回放位置归零**」。
> 实测发现这一条与「清屏不改变播放状态」自相矛盾，产生两个可复现的怪现象：
>
> | 现象 | 机理 |
> |---|---|
> | 播放中点「清屏」，波形从头重滚，按钮却变成「回放」 | `restart()` 里 `fseek(f,0)`；同时 `app_action_clear()` 把 `play` 强改成 `IDLE`，而按钮文字由 `play` 驱动 |
> | 连点两次「清屏」，第一次重播、第二次静止 | 第一次已把 `play` 改成 `IDLE`，第二次 `prev_play != PLAYING` ⇒ 补 `pause()` |
>
> 定稿口径：**「清屏」是纯视觉动作** —— 抹掉已画出来的历史，播放进度不动，
> 画面空白后**由后续样本从左侧接着铺**。
> 要「从头看」用「回放」键（它自己走 `restart`）；要「停住」用「暂停」。
>
> 代价：5 分钟数据在 1:00 处清屏，不会再退回 0:00 重看；屏幕左侧从 1:00 之后的数据接上。

### 8.5 模式 / 陷波 / 通道

| 阶段       | 行为                                                                        |
| -------- | ------------------------------------------------------------------------- |
| 第一阶段（回放） | **模式 / 陷波灰显不可点**（属采集端 `0x04`/`0x05`，回放无采集端可改）；**通道可点**（纯显示层，不碰采集端） |
| 第二阶段（实时） | 模式/陷波在 **RUN 态**可点（`0x04/0x05`）；通道**仅 STOP 态**可点（`0x06`，因为切通道会改帧长 53↔103） |

> **2026-10-27 订正：通道在第一阶段放开为「可点」。**
> 原稿把三个按钮统一灰显，理由都是"属采集端命令"。这个理由对**模式/陷波**成立，
> 对**通道**不成立 —— 通道的语义被两阶段共用却含义不同：
>
> | | 切通道改什么 | 需要采集端配合？ |
> |---|---|---|
> | 第一阶段（回放 SD 文件） | **只改画布 2 显不显示**：LEN=53 文件没有 CH2，LEN=103 文件两导联都在帧里，切 `I`/`I&II` 是纯画布层决策 | **否** |
> | 第二阶段（实时） | **改帧长 53↔103**（`0x06` 让采集端改并发多少通道） | **是** |
>
> 而且"要能切单/双通道数据文件"是验收必需能力（§2.4 的 6 个入选文件里就有 103 帧样本）。
> 所以第一阶段**必须可点**；第二阶段维持"仅 STOP 态"。**两者的约束不是同一条，不能合并成一句"灰显"。**

**无 STA 时的初始显示（兼容路径）**：LEN=52 的 v1.1 旧帧不含 STA，三参数状态**未知**。按协议 §4 口径填哨兵 `0xFF`，按钮显示「未知」，**不得显示「诊断 / 关 / I」** —— 那会把未知伪装成已知。  
演示数据（LEN=53/103）全部带 STA，此路径仅为兼容真实链路里的旧固件。

### 8.6 raw853 降级

`STA.bit3 = 1` 时，真实采样率是 **853.2423 Hz**，而显示链路按 500 Hz 解释，所有时间相关量都会偏。

| 项     | 处理                               |
| ----- | -------------------------------- |
| 横幅    | 画布 1 顶部显示 `raw853 模式 — 波形时基未经标定` |
| BPM   | 强制 `--`，停止计算                     |
| R 峰标记 | 不绘制                              |
| 右上角标  | 改为 `raw853 / LEN={n}`，**不显示秒数**  |
| 波形    | 仍按 500 Hz 解释绘制（不做 853 重采样）       |

理由：协议 §4 已论证「识别 + 降级」远优于「支持 853 解析」——后者要重做 R 峰检测器的全部标定（不应期、积分窗、BPM 换算 4 处触点）。  
验收样本：`ecg_20261010_150845_S4LOD-S7b.bin`（唯一 bit3=1 的文件）。

3. 绘制代码**不得内联颜色字面量**，一律走 `ui_theme_t` 字段，否则两套配色无法切换。
