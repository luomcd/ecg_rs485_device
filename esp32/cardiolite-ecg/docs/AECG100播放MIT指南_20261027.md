## 2. 格式口径（三处刻意选择，别改）

### 2.1 不重采样，按 360 Hz 原生播

MIT-BIH 原生采样率就是 **360 Hz**，48 条全部一致。直接写进头部 `fs=360`，AECG100 按此播放。
实测 `100_60s.txt` 显示 `00:01:00:000` 精确对上，说明 360 Hz 被正确接受。

> **不要**为了"凑 500 Hz"去重采样：插值会改变波形频响，而 Pan-Tompkins 的积分窗/不应期都是按样本数写的，
> 一旦重采样式样变了，W1 数字基线就不再是同一个基准。

### 2.2 3 位小数——刚好无损，2 位会砍半

MIT-BIH 量化是 **200 ADU/mV** ⇒ 1 ADU = **0.005 mV**，即 0.005 的整数倍。

- 3 位小数（0.001 mV）⇒ 分辨率比原量化细 5 倍 ⇒ **无损**
- 2 位小数（0.01 mV）⇒ 比原量化粗 2 倍 ⇒ **每点最多丢 1 个 ADU，相当于幅度阶梯**

AECG100 的 D/A 分辨率是 **2.5 µV**，所以 3 位小数的 1 µV 已被设备自己的量化吃掉，
再细没有意义；2 位则会引入**额外**于设备的误差。3 位是唯一正确值。

### 2.3 超 ±5 mV 一律整体缩放，不削顶

手册 §4.8：ECG 数据范围 **[-5, +5] mV**。

**削顶的代价**：留下平顶段 ⇒ 微分器在平顶两端各出一次尖峰 ⇒ 人为制造候选点 ⇒ 污染检出序列，
而且是"多检"方向，正好和 Q6 已经观察到的「单向偏多检」混在一起，事后分不清。

**本库实况**：48 条里**只有 116 号越界**（977 点 / 0.1503%，原始范围 −5.120..+5.115 mV），
按 `5.0 / 5.120 = 0.97656` **整体缩放**，保形态。缩放后 **−5.0000..+4.9950 mV，零越界**。
其余 47 条 `scale=1.0`，一个点没动。

> ⚠ 116 号是**唯一带缩放**的记录。做 W1/W2 对照时，若把 116 号的峰位置和数字基线比，
> 幅度缩了 2.34%，但**时间轴完全没动**，峰序列应逐峰一致——这正是选缩放而非削顶的理由。

## 3. AECG100 操作路径（手册 p31-32）

```
ECG 模式
  └ 下半部 (2) Player 标签页
      ├ (9) 载入 → 选 aecg_raw\{rec}.txt
      │    载入后 Total Length 显示播放时长（应 = index.csv 的 duration_s）
```

1. **只有 Waveform Raw 走 Player 标签**。Standalone（Mode A/B/C）与 PC（`.ecg`）走的是 (1) Signal 标签，
   放错页面会找不到文件类型。
2. **license 与我们无关**。手册说「若要**储存** Waveform Raw，须购买 license」——那是限制在 AECG100 上
   *存文件*。我们是在 PC 上按规则生成、在 (9) 载入，手册同款原文即「或**根据鲸扬科技规则自行建立的 raw data**」，
   属正常使用，不需要开通钥匙。

## 5. 分段播放（用于抽查波形，不是绕开长度限制）

生成器带 `--chunk`（秒）：

```bash
# 100 号按 60 s 切段 → 100_seg01.txt ... 100_seg31.txt（末段不足 60 s）
python tools/mit2aecg.py --record 100 --chunk 60 --outdir aecg_raw_chunk

# 整库切段（48 条 × ~31 段 ≈ 1488 个文件，体积同全程，只是文件数多）
python tools/mit2aecg.py --all --chunk 60 --outdir aecg_raw_chunk
```

切段后 `index.csv` 的 `start_s` 会记录每段起点，**对账时用 `record + start_s` 定位**，
不要靠文件名里的 `seg01` 序号去猜（末段长度不规则）。

> 切段的代价：每段边界会丢掉检测器的状态（滤波器初值、不应期、T 波门）。
> **算全长 Se 必须用全程文件**，切段只用于"验证链路 + 看波形"。

## 8. 接 W2 时必须记住的口径

AECG100 播 **360 Hz** → ADS1293 EVM 以 **853.24 Hz** 采集 → WinApp 收到的是**重采样后**的数据。

所以 W2 的「整机峰序列 vs 数字基线 Se 差 ≤ 0.1 pp」这条判据里，**混进了重采样误差**，
不全是模拟链路 + 采集的贡献。要拆开看：

- 若 W2 差值 ≤0.1 pp ⇒ 重采样 + 模拟 + 采集总代价可接受，链路可用
- 若超标 ⇒ 先在 PC 上把 360 Hz 数字数据重采样到 853 Hz 再跑一遍检测器，
  得到的差值就是**重采样单项代价**；剩余部分才是模拟 + 采集的账

⚠ 另外 Pan-Tompkins 的积分窗是 **60 个样本**（不是固定毫秒）：360 Hz 下 166.7 ms、853 Hz 下 70.3 ms。
两边参数若按同一份代码跑，**积分窗等效时长差 2.4 倍**，这是 W1/W2 对比里最大的隐性变量，
比接线问题更需要先确认清楚。

### 8.1 ✅ AECG100 起停沿的实测证据（2026-10-28，W2-2-001）

首次真实录制 `ecg_20261028_104807_W2-2-001.bin`（播 `100_60s.txt`，诊断档 + 陷波开）的逐点对账，回答了
「录到的波形段为什么比 60s 长」：

- **起点零偏移**：`100_60s` 的第 1 点 = 录制样本 3025（帧 121），互相关 **0.993**，首部无斜坡。
- **尾部多 0.95s**：60s 内容止于样本 33025（帧 1321），波形段却延续到样本 33500（帧 1339）。
  这 0.95s（帧 1322~1339）是 **AECG100 停播后 ADS1293 模拟前端的直流恢复尾巴**：
  均值 1906→1714 单调衰减、std 仅 66、无任何 QRS 节律（RC 耦合 + 0.5Hz 高通放电）。

**对 W2-2 录制的硬要求（比 §4.1 更具体）**：AECG100 每段内容**尾部要预留 ≥1s 的 AFE 恢复时间**，
对账时把这段尾巴掐掉。真正的对账区间 = 帧 121~1321 = 精确 60s = 30000 样本 @500Hz，
与 `100_60s` 的 21600 点 @360Hz 一一对应。

### 8.1b 📌 标准播放顺序（2026-10-28 定，W2 录制一律照此）

```
start → 记录(开始) → AECG100 播放 … → AECG100 播放结束 → 记录(停止)
```

**先点记录、后点播放** ⇒ 录件的**首尾都是基线**，波形段夹在中间：

```
[首部基线 ~6s] [波形段 60s] [尾部基线/衰减 ~6s]
    ↑ 检测器在此自举      ↑ 只对这段逐峰比    ↑ AFE 直流恢复
```

**这条顺序是 W2 对账的前提，不是可选项**，理由（首验实测坐实）：

1. **首部基线让检测器自举**：检测器在首部基线里把自适应阈值 `signalPeak/noisePeak` 建立起来，
   进入波形段时已收敛——首验里含首部基线完整喂时，波形段 FP 从 2 个降到 1 个。
2. **尾部基线留出 AFE 恢复**：AECG100 停播后 ADS1293 前端有 ~0.95s 的 RC 放电尾巴（§8.1），
   尾部基线把这个尾巴隔离在波形段之外。

**对账口径（首尾基线录件专用，别再用「排除首尾 5s」）**：

- 检测器**从首部基线开始喂**（不是从波形段起点硬切）。
- **只对波形段逐峰比**，且**只排除波形起点 0.1s 的人工切割沿**（那里是「基线→波形」的陡变沿，
  会制造一个边界假峰，与链路/算法无关）。
- 🛑 「排除首尾 5s」是给 **W1 数字基线**（从样本 0 直启、无空白）的口径，用在首尾基线的录件上
  **会误伤波形段前 12 个真搏动**，作废。

### 8.2 📌 幅度标定：`.bin` 码反推 µV 只用 `×0.1526`（2026-10-28 定）

W2-4 逐峰对账要比较幅度时，先分清手里是**哪个域**的码，再选系数——两个系数不是同一个数：

| 数 | 域 | 含义 | 性质 | 值 |
|---|---|---|---|---|
| `ECG_UV_PER_CODE = 0.1122` | **853 Hz 调试流 code 域**（`filterraw`，ASCII 列⑤） | 1 code = 多少 µV | **实测校准**（AECG100 回代） | 0.1122 µV/code |
| `ECG_LSB_OUT_UV = 0.1526` | **500 Hz 输出 int16 域**（`.bin`、显示链） | 1 LSB = 多少 µV | **设计约定**（恒等式） | 0.1526 µV/LSB |

**0.1122 的来由**（`ads1293_demo/tools/ADS1293_µV换算校准_待复核项_2026-09-07.md` §9）：
手册三错（G 当 6 / 分母 2²³ / 对称量程）弃用后，半跨重推 `2.4V ÷ (ADCMAX/2) ÷ 3.5 = 0.11287`，
再用 AECG100 已知幅值回代 `880µV/7845 = 0.1122`、`1000µV/8867 = 0.1128` 定稿 **0.1122**（与手册差 0.6% 自洽）。

**0.1526 的来由**（`ecg_out.h:67`、`winapp/Config/AppConfig.cs:16`）：设计约定「**±5 mV ↔ int16 ±32767**」，
即 `5mV ÷ 32767 = 0.1526 µV/LSB`，是**不随信号变的固定刻度**。

**两级怎么串**（`ecg_out.c:72-87` `ecg_out_codes_to_lsb()`）：

```
uv  = codes × 0.1122      // 853 域 code → µV
lsb = uv ÷ 0.1526          // µV → 输出 LSB（clamp ±32767）
```

500 Hz 档的 `dsrateraw` 已经是该函数输出（**已是 LSB 域**），所以：

> **`.bin` 的 int16 反推 µV 只用 `×0.1526`**，不再碰 0.1122。
> 只有当手里是 `filterraw`（853 域文本流）时，才用 `×0.1122`。
> 二者比值 `0.1526 / 0.1122 = 1.3600`，同源自洽。

W2-2-001 实测回代即按此口径：`.bin` 码 `×0.1526` 得端到端增益 0.944（74 拍逐拍比，std 0.038）。
