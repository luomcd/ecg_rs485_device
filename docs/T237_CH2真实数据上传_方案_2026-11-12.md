# T237 CH2 真实数据上传：实施方案（2026-11-12）

> **目标**：把 ADS1293 的 **CH2 真实数据**（`0x3A~0x3C`，CH2 = **IN3 − IN1**）经**完整滤波链 + 重采样**后
> 送上二进制帧的 CH2 段，**默认双通道打开**；当前 CH1 行为必须**逐位不变**。
> **状态**：⚠ **待评审**，未动代码。
> **上下游**：`T101` 协议 v2.4 §3.1（帧长 53/103）、`T232`/`T234`（LOD，与本项无关）、G8（CH2≡CH1 的旧拍板）

---

## 0 一句话

CH2 的**原始码早就在读**，但从未进滤波链；要让它"真实"，必须先把
`ecg_restore_process()` 这套**全局单实例状态机**改造成可按通道实例化，再接第二套链。

## 2 三种做法对比

| | **A 最小**：只 `dc_block` + 重采样 | **B 上下文重构**（推荐） | C 复制函数 |
|---|---|---|---|
| 滤波 | ❌ 无 notch / 带通 | ✅ 与 CH1 同一条链 | ✅ 同 B |
| 满足"真实数据"要求 | 否（你已明确要求进滤波） | ✅ | ✅ |
| 改动 | ~15 行 | **~120 行，但全是机械搬移** | ~200 行重复代码 |
| CH1 回归风险 | 低 | 低（CH1 走兼容包装，签名不变） | 中（两份状态机必然分叉） |
| 长期维护 | — | ✅ 一套逻辑两实例 | ❌ 改一处必漏另一处 |

**推荐 B**。理由：`ecg_restore_process()` 的伪迹/基线逻辑是**项目调出来的知识资产**，复制一份必然分叉；
改成 ctx 结构体后，CH1 与 CH2 共用同一段代码、各自持状态，逻辑永远一致。

## 3 方案 B 详细设计

### 3.1 新增通道上下文（`fast_restore_snippet.c` / 或提到 `.h`）

```c
typedef struct {
    ecg_dc_block   dc;          /*  40 B：去直流（含预热快相） */
    ecg_filter_f64 flt;         /* 912 B：D3 档 16 节（含 notch_on / mode） */
    double    base;             /*   8 B：慢基线 */
    uint32_t  startup;          /*   4 B：START 静默窗剩余样本 */
    uint32_t  restore_cnt;      /*   4 B：伪迹态次数（诊断） */
    uint16_t  hold;             /*   2 B：空白态保持计数 */
    uint8_t   seen;             /*   1 B：首样本已定基线 */
    uint8_t   blank;            /*   1 B：伪迹空白态 */
} ecg_restore_ctx;              /* ≈ 972 B */
```

### 3.2 接口（**兼容层保证 CH1 调用点零改动**）

```c
void   ecg_restore_ctx_init(ecg_restore_ctx *c);                  /* 等价旧 ecg_restore_start() */
double ecg_restore_ctx_process(ecg_restore_ctx *c, int32_t x);    /* 等价旧 ecg_restore_process() */

/* ---- 兼容包装（CH1 继续用这两个名字，`ads1293.c` 一行不改）---- */
void   ecg_restore_start(void);              /* = ecg_restore_ctx_init(&s_ctx1) */
double ecg_restore_process(int32_t x);       /* = ecg_restore_ctx_process(&s_ctx1, x) */
```

**关键**：`s_ctx1` 就是原来那 6 个 static + `g_dc` + `f64` 的打包体。
改造是**纯机械搬移**，CH1 的每一步运算顺序、每一个系数都不变 ⇒ 理论上逐位相同（用 §6 的硬判据验证）。

### 3.3 `ads1293.c` 的接入

```c
static ecg_restore_ctx s_ctx2;    /* CH2 独立上下文 */
static ecg_out_f32     out2;      /* CH2 独立重采样器 */

/* ads1293_filter_chain_init()：两路一起复位 */
ecg_restore_start();                        /* CH1（保持原样） */
ecg_restore_ctx_init(&s_ctx2);              /* CH2 新增 */
ecg_out_f32_init(&out2);                    /* 与 CH1 的 out 同时 */
```

每样本（`ads1293_raw_popoutput()`，与 CH1 并行）：

```c
ecgfilter.filterraw = ecg_restore_process(ecgdata.ecgraw);        /* CH1，原样 */
const double f2      = ecg_restore_ctx_process(&s_ctx2, ecgdata.ecgraw2);  /* CH2 */
/* 重采样：与 CH1 在同一处、同一时刻各调一次 ⇒ 输出点对齐 */
ecgfilter.ch2_out    = /* 由 out2 产出，见下 */;
```

⚠ **重采样的调用位置必须与 CH1 严格对齐**：CH1 的 `ecg_out_f32_process(&out, ...)` 只在 `_braw853 == 0`
分支里调；CH2 的 `out2` 也只在同一分支调一次，**两边 ready 标志必须一致**。
加一个不一致计数 `s_out_desync`（正常恒 0，用于自证锁步）。

### 3.4 帧结构改动

`ecg_filter_t` 增加一字段：

```c
int16_t ch2_out;    /* ★T237：CH2 在 500 Hz 输出点上的 LSB 值（来自 out2） */
```

帧打包把"复制 CH1"换成真实值：

```c
/* 旧：buff[8+N*2+idx*2+0] = buff[8+idx*2+0];   ← 复制 CH1 */
buff[8+_popoutcnt*2+idx*2+0] = (uint8_t)(ecgpopout[idx].ch2_out & 0xFF);
buff[8+_popoutcnt*2+idx*2+1] = (uint8_t)(((uint16_t)ecgpopout[idx].ch2_out) >> 8);
```

**853 模式**同样要照顾：CH1 走 `ecg_out_codes_to_lsb(filterraw)`；CH2 用 `ecg_out_codes_to_lsb(f2)`。

### 3.5 设置同步（否则两路滤波不同源）

6 处直接调 `ecg_filter_f64_set_notch/mode(&f64, ...)` 的位置，改为统一入口：

```c
void ecg_restore_set_notch(int on);   /* 同时设 CH1 与 CH2 的 flt */
void ecg_restore_set_mode(int mon);   /* 同上 */
```

`ads1293_status_byte()` 仍从 CH1 的实例读 bit0/bit1（两路同步后等价）。

### 3.6 默认双通道

`_bch2` 初值 `0` → `1`。

## 4 预算

| 项 | 增量 | 说明 |
|---|---|---|
| SRAM | **≈ 1.05 KB** | `s_ctx2` 972 B + `out2` ~60 B + `ecg_filter_t.ch2_out` 2 B×队列长度 |
| Flash | ~1 KB | 无新增算法，只是多一套数据 |
| 每样本 CPU | **约 +1 倍滤波量** | 16 节 biquad ×2 实例。按 T76 实测"f64 单节 47 指令 + 9 次库调用"，853 Hz 下仍在预算内（当前 `dtcycles` 留有待观察项，需实测复核） |

🛑 **必须实测**：`ads1293.c` 里已有 `ecgfilter.dtcycles`（DWT 周期计数）但没有硬判据。
本项上线后要测一次每样本耗时，确认没有挤占 DRDY 时基（样本周期 1172 µs）。

## 5 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | 重构把 CH1 改坏（数值变了） | **步 1 只做重构、不改任何输出**，用 MIT 回放**逐峰对账**证明逐位不变（§6.1） |
| R2 | 两路重采样失步 | 同一处、同一时刻各调一次；`s_out_desync` 计数必须为 0 |
| R3 | CH2 幅度与 CH1 差很多（增益/偏置不同） | 帧内 int16 会按 `ecg_out_codes_to_lsb()` 饱和 clamp；**先看实测 min/max**，必要时单独给 CH2 一个显示增益（协议层不动，只影响 ESP32 画布） |
| R4 | CH2 极性与预期相反 | **软件不取反**（保持"真实"）；极性由接线决定，看波形后再说 |
| R5 | 默认双通道让 WinApp 解析错乱 | 已知：WinApp 按 59 B 定长。本轮不测 WinApp；PC 侧脚本 `FRAME_LENS=(52,53,103)` **自适应，无需改** |
| R6 | 伪迹空白对 CH2 的影响未知 | CH2 的 ctx 独立判定（各管各的）；若 CH2 伪迹频发导致长时间输出 0，能看到并能区分 |

## 6 验证方案（每步都有硬判据）

### 6.1 步 1 的硬判据：**CH1 逐位不变**

| 手段 | 判据 |
|---|---|
| FILE 回放 MIT 一条（如 105）+ `rpeak rec` | **peaks 逐峰一致**（不是"数量相近"，是序列相同），对标 `rp_compare.py` |
| `485-stat` 的 `bpm / peaks / fed` | 与改动前同条件复测一致 |

⇒ **这一关不过，后面一步都不做。**

### 6.2 步 2 的判据：CH2 真的是"另一路"

| 判据 | 期望 |
|---|---|
| `ch2 on` 帧长 | 109 B |
| 帧内 CH2 段 vs CH1 段 | **不得逐点相同**（若相同 ⇒ 还在复制，改漏了） |
| 拔 IN3（CH2 的一个端点） | CH2 波形应显著变化，而 CH1 只受共模影响 |
| 拔 IN1（两路共用端点） | **CH1 与 CH2 都应崩** |
| `s_out_desync` | 0 |

### 6.3 两阶段接线对比（你要求的两步观察）

| 阶段 | 接线 | CH1 = IN2−IN1 | CH2 = IN3−IN1 |
|---|---|---|---|
| **① 现在** | IN1←LA、IN2←RA、IN3←N2、IN4←N1 | `RA − LA`（正立 QRS） | **`N2 − LA`**（形态未知） |
| **② 改线后** | IN1←LA、**IN2←N2、IN3←RA**、IN4←N1 | `N2 − LA` | **`RA − LA`**（正立 QRS） |

⇒ 阶段①看的是"CH2 接在参考端子上到底出什么"；阶段②让 CH2 变成有用的正立导联，CH1 变成参考端。
