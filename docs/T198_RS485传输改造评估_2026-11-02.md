```
CDC_Receive_FS (usbd_cdc_if.c:127)
  └→ vcom_recv(buf, len)                    填 VCOM_RxBuffer / VCOM_RxLength
```

⇒ **只要 UART 收满字节后把 `VCOM_RxBuffer/VCOM_RxLength` 填上，上层解析一行不用改**。这是本改造最大的便利。

### 2.3 帧格式（已跨项目验证，**不要动**）

```
AA 55 | TYPE | LEN(2B LE) | SEQ(2) | STA(1) | 样本(int16 LE × N) | CRC8
LEN  = 3 + 2·nch·N      总长 = 6 + LEN
nch=1, N=25 ⇒ LEN=53 ⇒ 59 B（帧头 AA 55 01 35 00）
nch=2, N=50 ⇒ LEN=103 ⇒ 109 B
```

与 CardioLite ESP32 侧 `ecg_frame_parse_raw()` 同一口径 ⇒ **RS485 两端天然兼容**。

## 3. 带宽与时序（量化）

| 项 | 数值 | 依据 |
|---|---|---|
| 上行帧率 | **20 帧/s** | 500 Hz ÷ 25 样本 |
| 单帧长度 / 发送耗时 | 59 B / **5.12 ms** @115200 8N1 | 59×10/115200 |
| 上行占用 | 1,180 B/s ÷ 11,520 B/s = **10.2%** | — |
| 每帧空闲窗口 | 50 − 5.12 ≈ **44.9 ms** | 足以插下行命令 |

### 3.1 🛑 `ascii-1` 调试档会超带宽

25 行 × 约 45 B ≈ 1.1 KB/帧 × 20 帧/s ≈ **22 KB/s**，是 115200 上限（11.52 KB/s）的 **约 2 倍**。

⇒ **RS485 下只能跑二进制档**；ASCII 调试档要么关，要么改更高波特率（460800 才够 2×）。

## 4. 真正的难点：半双工（不是换 API）

USB CDC 是全双工：上位机随时发命令、MCU 随时回文本。RS485 下：

1. 上行占 10%，剩余 90% 理论够插命令；
2. 但上位机**不看时机就发**（`winapp/Core/SerialSource.cs:48` 直接 `Write`），撞上 5.12 ms 发送窗口即丢字节；
3. 现有协议**无重传**。

⇒ 上板会表现为「命令偶尔没反应、重发一次就好」——最难查的随机故障。**必须在协议层处理**：
- 方案甲：MCU 在 DE 释放后开固定接收窗口；
- 方案乙：上位机改成「收到一帧后立刻发命令」（避开 MCU 发送期）。

## 5. 引脚与外设现状

`.ioc` 里**一个 UART 都没有启用**。`Mcu.IPNb=7`：NVIC / RCC / SPI3 / SYS / TIM2 / USB_DEVICE / USB_OTG_FS。

已占用引脚：

| 用途 | 引脚 |
|---|---|
| SPI3（ADS1293） | `PG9` SCK / `PG10` MISO / `PG11` MOSI / `PG12` CS（AF6） |
| DRDY / ALARM | `PC1`（EXTI1）/ `PC0` |
| USB | `PA11` / `PA12` |

封装 **WLCSP72**（`Mcu.CPN=STM32L476JGY6TR`），可用 IO 本就少 ⇒ **USART 引脚组合必须对原理图定，不能猜**。

⚠ 名称不一致：对话中说 **STM32L475**，工程是 **STM32L476JGY6TR**。以实物为准需猛哥确认一句。

## 6. PC 侧：零改动（有证据）

上位机用标准 `System.IO.Ports.SerialPort`：

- `winapp/Core/SerialSource.cs:13` → `new SerialPort(portName, baudRate, Parity.None, 8, StopBits.One)`
- `winapp/Form1.cs:820` → `SerialPort.GetPortNames()` 填下拉框

USB-485 转换器在系统里同样是 COM 口 ⇒ **下拉框选它即可，代码一行不用改**。
这也是「无需像 winapp 那样独立建仓库」的直接依据。

## 10. 🛑 待确认的硬件事实（决定方案能否落地）

> **✅ 2026-11-03 四项已全部结案**：① STM32 侧**没有** 485 收发器，走 `TTL→232→UT-2211(232↔485)`，
> 方向由转换器**自动**完成、固件不写 DE/RE；② 用 **UART5 = PC12(TX)/PD2(RX)**，AF8；
> ③ **115200 8N1**；④ 实为 **STM32L476JGY6TR**（WLCSP72）。实测见 `T200 §5~§7`。

1. **STM32 侧有无 485 收发器**？型号（SP3485 / MAX3485 / 其他）、**DE/RE 接 GPIO 还是硬件自动方向**？
   → 决定要不要写方向控制代码。
2. **用哪个 USART、哪几个引脚**？需对照原理图（WLCSP72 可用 IO 少）。
3. **波特率**：建议沿用 **115200**（带宽余量 9.8×）。
4. （附带）型号确认：**L475 还是 L476**？
