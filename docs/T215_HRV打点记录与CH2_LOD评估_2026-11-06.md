# T215 真机态功能扩展评估：R 峰打点记录 / CH2 真实通道 / LOD

> **日期**：2026-11-06　**场景**：真机态（STM32 + ADS1293 ← RS485 → ESP32）
> **本文性质**：评估与口径定版，不含落码。落码前按 §7 分阶段推进。
> **前置事实**（均已在源码核对）：CH2 寄存器已路由到导联 II；`ecgraw2` 已读到但未进滤波链；
> LOD 整条关闭；STM32 侧无任何 R 峰代码。

---

## 0 结论摘要

| 项 | 能不能做 | 主要风险 | 建议 |
|---|---|---|---|
| R 峰打点开关 | 能，半天 | 无 | 加 **ESP32 本地** CLI `rpeak on\|off`（不是 `485-send`） |
| 5 min 峰序列落 SD | 能 | **落盘时机**，不是算力 | 记录几乎零成本；落盘放 STOP 或显式命令 |
| CH2 真实数据 | 能，**不需改寄存器** | 滤波/重采样链多实例 | 先过重采样验同步，再补滤波 |
| LOD 开启 | 能，但要重建基线 | 输入工作点改变、噪声抬升 | 单独一轮，不要与滤波改动混做 |

## 1 R 峰打点开关

### 1.1 现状

| 事实 | 位置 |
|---|---|
| 屏上打点**没有开关，常开** | `ui_waveform` 的 `draw_rp_marks()` 每帧无条件画 |
| STM32 侧**完全没有 R 峰代码** | 全工程 grep `rpeak/RPEAK/R波` 零命中 |
| R 峰在 ESP32 本地算 | `ecg_rpeak_*`（`main/ecg/`） |
| 现有 `set_rpeak_dump()` 管的是「写文件」，不是「显示」 | `ecg_pipeline.c` |

### 1.2 为什么不该用 `485-send`

`485-send` 是**发往 STM32 的下行命令**（`0x01/0x02/0x04/0x05/0x06/0x10`，见 `vcomcmd.c:646-800`）。
STM32 收到一条「R 波打点」命令也没有任何东西可执行——它压根不做 R 峰检测。
WinApp 上的单选框控制的是 **PC 侧**显示，同样与 STM32 无关。

### 1.3 定版口径

```
rpeak on|off        ESP32 本地命令，控制屏上是否画 R 峰标记
```

只影响 `draw_rp_marks()` 的调用，**不影响检测器本身**（BPM 照算，只是不画点）。
这样「关掉打点」不会让 BPM 掉成 `--`，符合「打点是视觉叠加、不是算法开关」的语义。

## 2 连续 5 分钟峰序列落 SD：成本分析

### 2.1 记录本身：可忽略

| 量 | 数 |
|---|---|
| 单峰写入 | `snprintf` 约 **1~3 µs**（`dump_peak()` → `dump_buf_append()`） |
| 峰值速率 | 60~120 bpm ⇒ **1~2 次/秒** |
| 5 min 数据量 | 600 峰 × 约 7 B/峰 ≈ **4.2 KB** |
| 落盘缓冲 | `DUMP_BUF_SIZE = 32 KB`（`ecg_pipeline.c:129`）⇒ 5 min 只占 **13%** |
| CPU 占用 | 约 **0.001%** 量级 |

⇒ **记录本身不影响显示。** 值得担心的是下一节。

### 2.2 真正的成本：落盘那一下

`dump_buf_flush_to_file()`（`ecg_pipeline.c:209`）做的是 `fopen` + `fwrite` + `fclose`，
SD 卡实测**10~100 ms**，卡内 GC 时可能更久。现有代码只在 **EOF** 调用，注释也写明
"此时已不再喂样本，一次几十 ms 抖动无影响"（`:208`）。

**但 485 实时源永远不会 EOF** ⇒ 必须新加触发点，否则一直不落盘。

### 2.3 会不会影响显示：不会，余量足够

| 缓冲 | 容量 | 折合时间 |
|---|---|---|
| 485 驱动 RX 缓冲 | **4096 B**（`app_config.h:301`） | **≈1.7 s** 实时数据 |
| 环缓 | 5000 样本 | **10 s** |

一次 100 ms 的写卡只吃掉 1.7 s 余量的 **6%**。即使写卡期间生产者完全阻塞，
驱动缓冲也能兜住，且 `485-perf` 的 `ovf` 计数会立刻显形。

⇒ **即使在生产任务里同步写盘也不会丢数据。** 但仍建议放到 STOP：
一是省心，二是写卡期间 SPI 与 ADC 读时序不必再论证。

### 2.4 建议的落盘策略

| 场景 | 触发 | 说明 |
|---|---|---|
| **5 min HRV 采集** | `0x02 STOP` 时落盘 | 与现有 EOF 口径一致，最简单 |
| 长时间连续（>30 min） | 每 5 min 轮转到第二个文件 | 见 2.5 |
| 临时取数 | 显式命令 `dump-flush` | 不打断采集 |

固定文件名：`/sdcard/rpeak_hrv.txt`（每次覆盖）。

### 2.5 一个必须注意的坑：32 KB 溢出是**静默截断**

`dump_buf_append()` 满 32 KB 后只置 `s_dump_overflow = true` 然后**丢弃后续所有峰**
（`:190-193`），不报错、不告警，只有落盘日志末尾一个 `TRUNCATED!`。

- 5 min ≈ 4.2 KB ⇒ 安全
- 120 bpm 连续 30 min ≈ 3600 峰 ≈ 25 KB ⇒ **接近上限**
- 超过即静默丢数据

⇒ 长时间记录必须**轮转**，或把 `DUMP_BUF_SIZE` 提到 PSRAM。

## 3 CH2 真实通道

### 3.1 现状（三句话）

1. **寄存器已经是对的**：`regs_leaderIII` 里 `{0x01, 0x11}` / `{0x02, 0x19}`
   （`ads1293.c:330-331`），按 `tools/_fig_3leader_map.py:42` 的路由图：
   **CH1 = IN2 − IN1 = 导联 I**、**CH2 = IN3 − IN1 = 导联 II**。
2. **原始码已经读到**：`ads1293_ecg_ch(&v1, &v2)` 一次事务读 6 B（`ads1293.c:1016`），
   CH2 值存进 `ecgraw2`（`ads1293.h:112`）。
3. **但它没进滤波链**：`ads1293.c:1340` 注释原话——「本步 `ecgraw2` **只出不进**：
   不进滤波链、不参与重采样」；帧构造处直接复制 CH1（`:1530` 附近）。

⇒ **不需要调寄存器**。要做的是把 `ecgraw2` 接进管线。

### 3.2 🛑 「直通原始码」有个隐藏前提：两路时间轴会错位

CH1 的输出是**重采样后**的 500 Hz（853.33 → 500，`ecg_out_f32_process()`）。
若 CH2 直接塞原始码，拿到的是 **853.33 Hz** 的样本 ——
两列在同一个帧里**时间轴不一致**，屏上两条线会以不同速度漂移。

⇒ 第一版「不滤波」也必须**过重采样器**（只跳过滤波）。否则验的不是"真数据"，是"错位数据"。

### 3.3 分两步，每一步都有独立判据

| 步 | 内容 | 判据 |
|---|---|---|
| **P1** | CH2 过**重采样**（同参数）、**不过滤波** | 两路时间对齐（同一次心搏在两列上位置一致）；导联 II 的 R 波幅度应明显大于导联 I |
| **P2** | 补一套**独立滤波状态** | 两路噪声/基线各自独立；BPM 从两路算出的结果应接近 |

### 3.4 风险清单（回答问题 2）

| # | 风险 | 评估 |
|---|---|---|
| 1 | **CPU 翻倍** | 低。单样本滤波开销在 µs 量级，而 DRDY 周期 2000 µs；以 2000 µs 为预算，余量在 50 倍以上。**用 `dtcycles` 实测坐实**，不靠估算 |
| 2 | **状态必须独立** | 中。滤波系数可共享（常数），**状态（延迟线/积分器）必须各一份**，共用会互相污染且极难排查 |
| 3 | **重采样器状态必须独立** | 中。`y_prev` / `acc_us` 两路各一份；否则一路的插值起点会串到另一路 |
| 4 | **滤波链多实例是否支持** | **未知，是最大不确定点**。API 都带 `ecg_filter_t*` 指针（如 `ecg_filter_f64_mode_is_mon(&f64)`），看起来可行，但要核实模块内有无隐藏全局 |
| 5 | **输入耦合**：CH1 = IN2−IN1、CH2 = IN3−IN1 **共用 IN1(RA)** | 中。RA 电极脱落时**两路同时坏**；IN1 的噪声会同时进入两路 ⇒ 两路噪声相关，不能当独立通道做加权平均 |
| 6 | **共模与 RLD 共用** | 低。两路共用 CMOUT/RLD，共模抑制相互影响，但不改变单路算法 |
| 7 | **标定** | 低。两路同增益同码值量纲，µV/code 一致 |

## 4 LOD 开启对滤波链的影响

### 4.1 现状：不是"没做"，是**整条关着**

| 项 | 现状 | 位置 |
|---|---|---|
| 总开关 | `ECG_LOD_EN = 0` | `ads1293.c:11` |
| `0x06` LOD_CN | `0x08` ⇒ **SHDN_LOD = 1（关断）** | 寄存器表 `#else` 分支 |
| `0x07` LOD_EN | `0x00` ⇒ 全关 | 同上 |
| `0x08` LOD_CURRENT | `0x00` ⇒ 0 µA | 同上 |
| STA bit4 | **写死 0**（注释明说"恒 0"） | `ads1293.c:1221` |

⇒ `485-stat` 里的 `lod=0` 是常量，**不是判据**。

### 4.2 会不会影响滤波链：算法不变，**工作点全变**

滤波器系数、结构、阶数一个字节都不用改。变的是**输入信号本身**：

| 影响 | 机理 | 定量 |
|---|---|---|
| **DC 偏置** | 2.04 µA × 电极-皮肤阻抗 | 10 kΩ → **20 mV**；100 kΩ → **204 mV** |
| **基线漂移** | DC 阶跃经 0.05 Hz 高通（τ ≈ 1/(2π×0.05) ≈ **3.2 s**） | 收敛期数十秒内基线持续移动 |
| **噪声抬升** | 电流源噪声 × 阻抗 | 与阻抗成正比 |
| **饱和风险** | 高阻抗时偏置接近满量程 | ADC 削顶 ⇒ 波形平顶，且**高通前**就丢了信息 |

⇒ **LOD 打开后，现有波形基线、噪声底、幅度判据全部作废**，必须另立一组 LOD-ON 基线。
这一点 `stm32/tools/INDEX.md:301-302` 已有同样的结论（当时判为"S4 不可判"就是因为 LOD 关着）。

### 4.3 改动三件套

1. `ECG_LOD_EN = 1` ⇒ 寄存器切到 `0x06=0x00` / `0x07=0x0f` / `0x08=0xff`
2. `ads1293_status_byte()` 的 bit4 改为**运行期读** `TI_ADS1293_ERROR_LOD_REG`
3. **重建基线**：上电后静置，记录基线漂移曲线与噪声底，作为新判据

### 4.4 实践警告

DC 电流法对**湿电极/极化电压**敏感，容易误报「脱落」。上板后要先确认：
- 电极贴好时 `lod` 必须稳定为 0（不能随机跳 1）
- 拔掉任一电极时 `lod` 必须为 1，且**能分辨是哪一路**（若只给一个 bit，就分不出）

后者可能需要 AC 法或分时注入 —— 属后续议题。

## 5 HRV 通道选择（结论，不展开）

- **导联 II（CH2）通常更适合**：心电轴约 +60°，与导联 II 轴平行 ⇒ R 波最高、QRS 斜率最陡。
- **前提**：电极贴法固定为 `IN1=RA / IN2=LA / IN3=LL`；换贴法结论不成立。
- **判据**（用实测数选，不靠感觉）：同一段信号两路各算 ① R 波峰-峰幅度 ② QRS 最大斜率 ③ 5 min 内 Se/PPV。
- **两条硬约束**：
  - 采样率：500 Hz ⇒ 2 ms，够用；若处 raw853 而下游按 500 Hz 解释，所有间期**偏 1.7 倍**。
  - 漏检比抖动更致命：一次漏检产生 ≈2×RR 的假间期，RMSSD 直接失真。

## 6 五项指标的优先级（供测试排期）

| 优先 | 指标 | 为什么 |
|---|---|---|
| P0 | **Se / PPV**（漏检率、误检率） | 直接决定 HRV 可用性 |
| P0 | **RR 间期抖动 σ** | RMSSD 的误差来源，500 Hz 下 1 样本 = 2 ms |
| P1 | R 波幅度、QRS 斜率 | 用于选通道 |
| P1 | 基线漂移、噪声底 | LOD 开启后必须重测 |
| P2 | 频响、输入阻抗 | AFE 属性，换链路不变，**不必重测** |

## 7 分阶段计划

| 阶段 | 内容 | 依赖 | 预估 | 风险 |
|---|---|---|---|---|
| **P1** | `rpeak on\|off` 本地命令 | 无 | 半天 | 低 |
| **P2** | 峰序列 dump + STOP 落盘 + 分析脚本（Se/PPV/σ） | P1 | 1 天 | 低（复用现有 dump） |
| **P3** | CH2 过重采样（不滤波） | 无 | 半天 | 低，用来验路由与同步 |
| **P4** | CH2 独立滤波状态 | P3 | 2~3 天 | **中**，滤波链多实例是未知点 |
| **P5** | LOD 开启 + 基线重建 | 无 | 2 天 | 中，输入工作点改变 |
| **P6** | HRV 通道选择实测 | P2 + P4 | 1 天 | 低 |

建议顺序：**P1 → P2 → P3 → P4 → P5 → P6**。
P1/P2 完全不碰 STM32，先拿到 HRV 的测量手段；P3 成本最低、能立刻验证"导联 II 是不是真的在"。

## 8 待确认项

1. **滤波链能否多实例**（`Filter/` 模块是否有隐藏全局）—— P4 的前置调查，不动代码
2. **LOD 是否只给一个 bit**：分不出是哪一路脱落，是否可接受
3. **峰序列格式**：现有 `P <idx>` 只记位置；判「这一点是 R 峰」需要邻域值，格式要定
   （建议 `P <idx> <滤波值>` 或 `P <idx> <v-5..v+5>`）
4. **固定文件名**：`/sdcard/rpeak_hrv.txt` 是否合适（覆盖写 ⇒ 只能存最近一次）
