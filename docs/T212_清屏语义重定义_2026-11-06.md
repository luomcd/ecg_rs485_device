# T212 清屏语义重定义（2026-11-06）

> **一句话**：「清屏」从「清空 + 回放位置归零 + 改变播放状态」改为**纯视觉动作** ——
> 只清画面（波形缓冲 / R 峰队列 / BPM），**播放进度与播放状态一概不动**。
>
> **拍板**：猛哥 2026-11-06 14:40，方案 B。
> **前置任务**：T211 的补丁已整段撤掉，沿革见 §5。
> **代码**：`1eb1491`（语义改动）、`c525c79`（`ui-clear` 入口 + 探针两套口径）。

## 1 起因：同一个键，两次点击行为相反

猛哥 2026-11-06 上午在真机上连续操作，上报 5 条现象：

| # | 操作 | 现象 |
|---|---|---|
| 1 | 点「回放」 | 按钮变「暂停」，开始播放 ✓ |
| 2 | 点「暂停」/ 再点「播放」 | 暂停 / 继续 ✓ |
| 3 | **第一次**点「清屏」 | 画面清空，**新波形重新滚动出现**，按钮变回「回放」 |
| 4 | **第二次**点「清屏」 | 画面清空，**不再滚动**，基线只漏出一点头 |
| 5 | 第三次点「清屏」 | 擦掉漏出的基线；BPM 值被刷新 |

第 3 条与第 4 条**互斥**：同一个键、同样的手法，一次"继续播"、一次"停住"。
这不是操作问题，是状态机问题。

---

## 2 根因：两套状态机互不通信

工程里有两个"播放状态"，各管一摊，谁也不看谁：

| 状态 | 位置 | 谁读它 | 谁写它 |
|---|---|---|---|
| `app_state.play` | `app_state.c` | **按钮文字**（`ui_button_bar.c:505` 的 switch） | 按钮动作（回放 / 清屏 / 文件变化） |
| `s_paused` | `ecg_pipeline.c:53` | 生产者（`:549` 决定推不推样本） | `ecg_pipeline_pause()` / `resume()` / `restart()` |

T211 之后的清屏分支同时碰这两边，但**碰法不一致**：

```c
app_action_clear()          →  s_st.play = APP_PLAY_IDLE;     // ← 强改成 IDLE
ui_waveform_clear();
ecg_pipeline_restart();     →  s_restart = true; s_paused = false;
if (prev_play != APP_PLAYING) ecg_pipeline_pause();           // ← 按"改之前"的 play 决定
```

于是：

- **播放中点清屏**：`prev_play == PLAYING` ⇒ 不补 `pause()` ⇒ `restart()` 的
  `s_paused = false` 生效 ⇒ **继续播（且位置归零）**；但 `play` 已被改成 `IDLE`
  ⇒ 按钮跳成「回放」。**画面在跑，按钮说没在跑。**
- **第二次点清屏**：`play` 已残留为 `IDLE` ⇒ `prev_play != PLAYING` ⇒ 补 `pause()`
  ⇒ **停住**。

同一段代码、两个分支，取决于上一次点击留下的残留值 —— 这就是第 3/4 条互斥的全部原因。

### 2.1 附带发现：那"一点头"基线是 25 个样本

`push_sample` 的**每帧循环不检查 `s_paused`**（`ecg_pipeline.c:648-651`），
只有 `while` 顶部才检查（`:549`）。所以 `restart()` 到 `pause()` 之间若有样本正在推，
最多**一帧 25 个样本**会穿过去：

| 量 | 值 |
|---|---|
| 单帧样本数 | 25 / 通道（LEN=53：SEQ+STA+25×int16+CRC8） |
| 对应时长 | 25 / 500 Hz = **0.05 s** |
| 占屏宽 | 25 / `APP_RING_SAMPLES(5000)` = **0.5%**（约 3~4 px） |

这就是第 4 条"基线只漏一点头"。属竞态，不是损坏数据。

## 3 三个方案与拍板过程

| 方案 | 做法 | 结果 |
|---|---|---|
| **A** 只修按钮 | `app_action_clear()` 不再改 `play`，保留 `restart()` 归零 | 按钮不再乱跳；但播放中点清屏仍会**回到文件头重播** |
| **B** 纯视觉 | 删 `restart()`、删 `play` 赋值 ⇒ 不归零、不改状态 | 进度不倒退，清屏后面从当前位置接着铺 |
| C 只修显示 | 按钮文字改用 `ecg_pipeline_is_paused()` | 只治显示，不治"第二次变暂停" |

**拍板过程**（很关键，记录了判断依据）：

1. 11:40 猛哥先选 **A**；
2. 11:42 追问：「5 分钟数据播到 1 分钟点清屏，从头滚的是**1 分钟处**的数据吧？」
   —— 这说明他要的是"**抹掉已画的、进度不动**"，不是"回到开头重画"；
3. 解释 A 仍然 `fseek(f,0)`、会重看 1 分钟，B 才是"进度不倒退"；
4. 猛哥：「那就是方案 B」。

> 一句话判据：**清屏 = 重画这一屏**（选 A） vs **抹掉已画的、接着画**（选 B）。
> 临床习惯取后者 —— 「清屏」是清视觉，不该把播放进度往回拨；要重来用「回放」键。

## 5 沿革：T211 做对了什么、又错在哪

### 5.1 T211 要解决的（真 bug）

暂停态点清屏 ⇒ 波形自己跑出来。根因是 `ecg_pipeline_restart()` 里有
`s_paused = false`（"重播隐含恢复"），再配合生产者看到 `s_restart` 就 `fseek(f,0)`。

T211 的思路：先记 `prev_play`，清完按需补一次 `pause()`。

### 5.2 T211 错在哪

它**同时保留**了 `restart()` 与 `play = IDLE` 两件事，而这两件事各自都能改变状态：

- `restart()` 改 `s_paused`（真实播放）
- `app_action_clear()` 改 `play`（按钮显示）

于是"多留一个状态下不来"的经典问题出现：第二次点击的分支被上一次的残留值决定。
T211 的补丁在 T212 里**整段删除**，但那两条认知保留：

1. **不能改 `restart()` 本身** —— 回放键靠它起播；
2. **`if(s_restart)` 必须排在 `if(s_paused)` 之前** —— 否则暂停态下 restart 永不被消费。

### 5.3 为什么不留 T211 文档

T211 的口径已被推翻。单独写一份会让后来人读到**错误的当前行为**。
本文保留其沿革，是唯一正确的落点。

## 7 `ui-clear`：为什么加、边界在哪

### 7.1 动机

清屏只能点屏 ⇒ 自动化验收触发不了 ⇒ 回归只能靠人手点，不可重复。

### 7.2 实现

把清屏那段从 `on_btn_click` 里抽成 `ui_clear_apply()`，**屏上键与 CLI 调同一段**：

```c
void ui_clear_apply(void)
{
    if (!app_action_clear()) return;      /* 无文件 ⇒ 与灰键一致，什么都不做 */
    ui_waveform_clear();
    ui_waveform_set_frozen(false);
    ecg_pipeline_rpeak_reset();
    ui_bpm_reset();
    ui_button_bar_refresh();              /* 冻结被解除 ⇒ 冻结键文字要变回「冻结」 */
}
```

### 7.3 边界（🛑 必须记住）

| 覆盖 | 不覆盖 |
|---|---|
| 清屏**动作本身**（清缓冲 / 清 R 峰 / BPM 归 `--`） | **LVGL 事件分发**（`on_btn_click` 的 `case BTN_CLEAR`） |
| 可无人值守、可重复回归 | 按钮是否可点、文字是否显示正确 |

⇒ **事件层改动过，必须人手点一次确认**，别拿 `ui-clear` 的通过去证明"按钮也能用"。

### 7.4 锁的约束

`ui_bpm_reset()` / `ui_button_bar_refresh()` 都会动 LVGL 对象：

- 按钮回调在 LVGL 任务里 ⇒ **已持锁**，直接调；
- `ui-clear` 在 console 任务里 ⇒ 必须 `esp_lv_adapter_lock(-1)` / `unlock`。

`ui_clear_apply()` 内部**故意不加锁** —— 加了会形成二重加锁，是否安全取决于适配层
互斥量是否递归，不去赌。

## 8 已知限制与遗留

### 8.1 CLI `play` 不碰 `app_state.play`

`start_replay()` 只改管线（`s_change` / `s_paused`），`app_state.play` 仍是 `IDLE`
⇒ 命令行起的播，按钮显示「回放」。属**测试路径错位**，真实用户只按屏，不会遇到。

根治办法是让按钮文字改读 `ecg_pipeline_is_paused()`，但会牵动四态显示（IDLE / PLAYING /
PAUSED / ENDED），风险大于收益，**本次不做**。

### 8.2 清屏后 BPM 闪回约 220 ms

```
I (14932) ui_bpm: bpm -> 120      ← 清屏后 2 ms
I (15155) ui_bpm: bpm -> --       ← 223 ms 后才归 --
```

`ui_bpm_reset()` 与 UI 侧 200 ms 刷新周期在打架。猛哥 2026-11-06 判定
「实测目测不明显，不用管」⇒ **不修**。

### 8.3 485 源下 `s_restart` 残留（已被 B 顺带消除）

T211 时期，485 源下点清屏会把 `s_restart` 留成常真（485 生产者不消费它），
直到切回 FILE 源才被消费一次。T212 不再调 `restart()` ⇒ **该问题自动消失**。
