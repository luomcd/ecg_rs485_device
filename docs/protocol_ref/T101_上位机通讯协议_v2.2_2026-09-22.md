## 0. 一句话

协议从「只读单向 1 条帧」扩成「**上行 2 条 + 下行 8 条**」：上行给显示帧加 **1 字节 STA**（状态自证）、新增 **寄存器快照帧**；下行新增**二进制命令帧**（`0x80` 段，与上行天然分离）。所有命令**不等同步回复**，生效与否一律靠 **STA 位 / 快照帧**判定。

## 2. 外层帧结构（不变）

```text
AA 55 | TYPE(1B) | LEN(2B, u16 小端) | PAYLOAD(LEN 字节) | CRC8(1B)
```

| 元素 | 规则 |
|---|---|
| 帧头 | `0xAA 0x55` |
| TYPE | 上行 `0x00–0x7F`，**下行 `0x80–0xFF`** ⇒ 抓包日志一眼看出方向 |
| LEN | PAYLOAD 字节数（不含头/型/长/CRC） |
| 字节序 | 多字节一律**小端** |
| CRC8 | 多项式 `0x07`、初值 `0x00`，范围 = **TYPE + LEN + PAYLOAD** |
| 帧总长 | `6 + LEN` |

### 2.1 上行发送路径（★ 既定实现 · 本次**不改** · 猛哥 2026-09-22 提醒后核证）

**结论先说：上行协议帧不走 `printf_msg`，因此不吃 `HAL_Delay(5)`、不阻塞主循环、不影响采样。** 这是上一版与上位机联调顺畅的基础，本次扩展**保持这条路径不动**。

| 分支 | 位置 | 打包方式 | 发送 | 阻塞 |
|---|---|---|---|---|
| **二进制**（`_bdispascii==0`，**上电默认、投产档**） | `Ads1293/ads1293.c:697-722` | **逐字节填充** `buff[]`（`buff[0]=0xAA`、`buff[1]=0x55`…）**不用 `sprintf`** | `CDC_Transmit_FS(&buff[0], 7+_popoutcnt*2+1)`（`:721`） | **无** |
| ASCII（`_bdispascii==1`，调试档） | `Ads1293/ads1293.c:669-695` | `sprintf` 打文本行 | `CDC_Transmit_FS(&buff[0], len)`（`:695`） | **无** |

> ⚠ 这两条分支**都不经过 `printf_msg`**。`printf_msg`（`Core/Src/demo.c:23-43`）是**命令回显专用**（走 `vsprintf` + `CDC_Transmit_FS` + **`HAL_Delay(5)`**）。
> ⇒ **切勿把「命令回显会阻塞」误当成「协议帧上传会阻塞」**——两者是**两条独立路径**，只是**共用同一个 USB CDC 物理端点**（所以文本回显会混进上行流，被上位机 `FrameParser` 当垃圾丢弃，见 §8）。

**由此得出一条设计收益（量化）**：

| 路径 | 样本损失 | 说明 |
|---|---|---|
| ASCII 命令（现状，保留） | **−4.27 个 DRDY/条** | `vcomcmd.c` 每条命令分支末尾都打回显（`notch` `:196/202`、`mode` `:241/247`）⇒ 调 `printf_msg` ⇒ `HAL_Delay(5)`; 而 `_bconvint` 是单标志（`demo.c:15,53`）⇒ 中间样本永久丢失。**既有行为，本次不改** |
| **新二进制命令（`0x80`）** | **0** | 命令处理**不打回显**（§5.3 硬约束）。切 mode/notch 本体（`ecg_filter_f64_set_notch/set_mode`，`Filter/ecg_filter.c:803/845`）**本就无任何打印** ⇒ 只花写标志 + 1 节系数重算的时间 |

⇒ 「禁调 `printf_msg`」这条约束**不只是防坑，它是运行态命令零样本损失的实现路径**。这是 v2.1 相对 v2.0 的**结论升级**。

## 3. 上行帧

### 3.1 Type `0x01` 显示帧（改）

| 字段 | 类型 | 字节 | 说明 |
|---|---|---|---|
| SEQ | uint16 LE | 2 | 帧序号，每帧 +1，允许回绕 |
| **STA** | uint8 | **1** | **状态字节（新增）**，定义见 §4 |
| SAMPLES | int16 × N | 2N | 见下表 |

| 通道模式 | N | LEN | 帧总长 | 备注 |
|---|---|---|---|---|
| channel = I（默认） | 25 | 2+1+50 = **53** | **59 B** | ≈ 1.18 KB/s @ 500 Hz |
| channel = I&II（**本轮做**） | 50（CH1 25 + CH2 25） | 2+1+100 = **103** | **109 B** | ≈ 2.18 KB/s |
| v1.1 旧固件 | 25 | 52 | 58 B | **上位机必须继续认**（见 §8） |

> **双通道字节序**：先把 CH1 的 25 个点放完，再放 CH2 的 25 个点（不与 CH1 交错）。
> ⚠ **本轮验收口径（v2.2 第 4 条）**：只验收 **`channel=I`（59 B）** 的端到端；`channel=I&II`（109 B）的**打包能力与界面切换都做**，但**「数据上传 → 显示」不验收**（无输入源，见 §10）。
> **上位机不得靠 STA.channel 猜样本数**——一律按 **LEN** 反推（`N = (LEN-3)/2`）。LEN 是硬事实，STA 是软标志。

### 3.2 Type `0x03` 寄存器快照帧（新）

用途：① 连接时的一次快照；② `REQ_SNAPSHOT` / `RESET` / `SET_REGS` / `SET_CHANNEL` 的回执。
**只在 STOP 态发送**（此时无显示帧，不存在混流与带宽竞争）。

| 字段 | 类型 | 字节 | 说明 |
|---|---|---|---|
| REQID | uint8 | 1 | 触发本帧的下行命令 CMD 码（`0x03`=Reset、`0x06`=SetChannel、`0x10`=ReqSnapshot、`0x11`=SetRegs；上电主动上报填 `0x00`） |
| COUNT | uint8 | 1 | 随后的 (REG,VAL) 条目数 |
| ITEMS | (uint8 REG, uint8 VAL) × COUNT | 2×COUNT | 按 REG 升序排列 |

* 全表 COUNT = 36 ⇒ LEN = 74，帧总长 **80 B**
* ⚠ COUNT 上限 **60**（一帧装不完时分**多帧**，REQID 相同；本期 36 项一帧够）
* ⚠ 快照按 **`ads1293_read_reginc` 分 3 段读**（一次最多 16 字节，见 `Ads1293/ads1293.c:106` 的 `tx_buf[16+1]`）：`0x00`/`0x10`/`0x20` 各 16 字节，然后**只挑表内 36 个地址**打包（数据/状态寄存器不传）

### 3.3 Type `0x02` 调试帧（保持不变 · 本期不做）

§3.2 原文规格保留（368 B，raw24/y_code）。⚠ 若要实现，需先定 **K 与 `_popoutcnt` 的关系**：现状 `test ascii-1` 会把 `_popoutcnt` 改成 4（`Core/Src/vcomcmd.c:132`），与规格的 K=20 冲突。

## 4. STA 状态字节定义

| bit | 名称 | 取值 | 运行期读取来源 |
|---|---|---|---|
| 0 | `mode` | 0 = diag／1 = mon | `ecg_filter_f64_mode_is_mon(&f64)` |
| 1 | `notch` | 0 = off／1 = on | `ecg_filter_f64_notch_is_on(&f64)` |
| 2 | `channel` | 0 = I／1 = I&II | 新增软件标志（与 `0x2F`/`0x01`/`0x02` 的期望值绑定） |
| 3 | `raw853` | 0 = off／1 = on | `ads1293_raw853_is_on()`（`Ads1293/ads1293.c:514`） |
| 4 | `LOD` | 0 = 正常／1 = **有输入脱落** | `(s_lod_stable & ECG_LOD_MASK) != 0`（`ads1293.c:1323`）——**任意启用输入**脱落（含 IN3、含 RLD 回流断）。⚠ 旧版写的 `vlod` 是 **ASCII 通道**变量，不是本字节的来源 |
| 5 | `CH1_INVALID` | 0 = CH1 可用／1 = **CH1 不可用** | `(s_lod_stable & ECG_LOD_GATE_CRIT) != 0`（`ads1293.c:1326`）；判据由 `ECG_LOD_GATE_POLICY` 决定（见 §4 约束 2） |
| 6–7 | 保留 | 0 | — |

### 🛑 三条硬约束（都是实测/查证结论，不是推测）

1. **STA 必须运行期读取，不得用编译期宏。**
   `profile:` 打的是 `ECG_PROFILE_NAME`（宏），T92b 已栽过一次：diag/mon 两态回显**逐字相同**，判不出档（`vcomcmd.c:227-231` 的注释就是这条教训）。mode/notch 的现成访问器已经存在，直接用。

2. **`LOD` 位已使能（2026-11-11 起），且拆成 bit4 / bit5 两位。**
   旧版这条写「`ECG_LOD_EN = 0` ⇒ 恒 0，位置先留」——**已作废**。现行配置：
   `ECG_LOD_EN = 1`（`Ads1293/ads1293.c:17`）⇒ `0x06=0x00`（DC 模式）／`0x07=0x07`（IN1~IN3）／`0x08=0x01`（**8 nA**，不是 2.04 µA）。
   🛑 **IN4 不在掩码内**：它被 RLD 输出驱动（`0x0C=0x04` ⇒ `SELRLD=100`），不是待检测电极。
   🛑 **两位语义不可混用**：

   | 位 | 语义 | 用途 | 拔 IN3 时 | 拔 IN1/IN2 时 |
   |---|---|---|---|---|
   | `bit4` | 任意启用输入脱落（**完整性提示**） | 界面出红叉／工况栏标 `·LOD` | **1** | 1 |
   | `bit5` | `CH1_INVALID`（**门控**） | 停打点／BPM `--` | **0**（CH1 仍有效） | **1** |

   ⇒ 上位机：「脱落提示」看 bit4；「是否停测」看 bit5。**不要拿 bit4 去停测**（拔 IN3 会误停）。

3. **`raw853` 位必须有，但只做"识别 + 降级"，不做 853 Hz 解析。**
   你会用串口助手打开它（`test raw853 on`），上位机不知道时的后果**全是静默错显**：

   | 触点 | 位置 | raw853 on 下的后果 |
   |---|---|---|
   | 时窗样本数 | `Form1.cs:341` 的 `TimeWindowSeconds * 500` | 5 s 实显 **2.93 s** |
   | BPM 换算 | `Processing/HeartRateDetector.cs:23` 的 `SampleRate = 500` | **×1.7065 虚高**（60 → **102**） |
   | R 波检测窗 | `HeartRateDetector.cs:24-26`（不应期 80 点、积分窗 60 点，按 500 Hz 定标） | 两者**缩短 41%** ⇒ 漏检/误检 |
   | 采样率显示 | `Form1.cs:407` | 自动测量，会自己变 853.2 Hz ✅ 无需改 |

   ⇒ `STA.bit3 = 1` 时：**挂横幅「raw853 模式：波形时基未经标定」+ 冻结 BPM / R 波标记 / 时窗标定**，只画波形。这比"支持 853 解析"（4 处触点 + R 波检测器重新设计）便宜得多，也更安全。

## 5. 下行帧 Type `0x80`（新）

```text
AA 55 | 80 | LEN(2B LE) | CMD(1B) | ARG(N) | CRC8
LEN = 1 + N        帧总长 = 6 + LEN = 7 + N
```

### 5.1 命令表

| CMD | 名称 | ARG | LEN | 总长 | 允许态 | 生效证据（隐式 ACK） |
|---|---|---|---|---|---|---|
| `0x01` | **START** | — | 1 | **7 B** | STOP 且配置放行（§7） | `0x01` 帧开始上行 |
| `0x02` | **STOP** | — | 1 | **7 B** | RUN | `0x01` 帧停止上行 |
| `0x03` | **RESET** | — | 1 | **7 B** | 任意 | 上行 `0x03` 快照帧 |
| `0x04` | **SET_MODE** | 1 B：0=diag／1=mon | 2 | **8 B** | RUN | 下一帧 `STA.bit0` |
| `0x05` | **SET_NOTCH** | 1 B：0=off／1=on | 2 | **8 B** | RUN | 下一帧 `STA.bit1` |
| `0x06` | **SET_CHANNEL** | 1 B：0=I／1=I&II | 2 | **8 B** | **仅 STOP** | 上行 `0x03` 快照帧 + 后续帧长 53↔103 |
| `0x10` | **REQ_SNAPSHOT** | — | 1 | **7 B** | STOP | 上行 `0x03` 快照帧 |
| `0x11` | **SET_REGS** | `(REG,VAL) × N`，2N B | 1+2N | **7+2N** | **仅 STOP** | 上行 `0x03` 快照帧 |
| `0x12` | **SET_REGS_FORCE**（实验写） | `(REG,VAL) × N`，2N B | 1+2N | **7+2N** | **仅 STOP** | 上行 `0x03` 快照帧（REQID = `0x12`） |

> 📌 **v2.3 新增 `0x12`（猛哥 2026-09-24 拍板①「保持硬拒 ＋ 加显式实验开关」）**：与 `0x11` 的差别**只有一处** —— 白名单。
> `0x11` 拒 7 条（`0x11` `0x12` `0x13` `0x21`–`0x24`）；`0x12` **全部放行**。两条的**预扫语义相同**（任一项非法地址 ⇒ 整批不写、零副作用）、**纪律相同**（无 `printf_msg`、成功才回快照）。
> 🛑 **为什么不给 `0x11` 的 ARG 追加 flag 字节**：`vcomcmd.c` 的 per-CMD 长度门要求 `LEN = 1 + 2N`（**奇**且 ≥ 3）；追加 1 B 会让 LEN 变偶，把一处校验口径劈成两条 —— 那正是当初从严校验要防的坑。
> 🛑 **旧固件兼容性**：旧固件收到 `0x12` 走 `default:` **静默丢弃** ⇒ 上位机表现为「等满 1.0 s 超时」，可识别、无副作用。

> 🛠 **2026-09-22 订正（U5 落码自检抓出）**：本表「总长」列原写 `8 B / 9 B / 9+2N`，**比 `6 + LEN` 多 1~2 B**，是笔误。
> 依据：本协议上下行**同构** —— 上行 `LEN = PAYLOAD 长度`、总长 `= 6 + LEN`，`LEN=52 ⇒ 58 B` 已由 **723 帧真实 v1.1 抓包**坐实；
> 下行把 `CMD + ARG` 视作 payload ⇒ `LEN = 1 + N`、总长 `= 6 + LEN = 7 + N`。
> ⇒ START 为 **7 B**（含 CRC：`AA 55 80 01 00 01 CR`），SET_REGS 36 项为 **79 B**。
> 🛑 **LEN 字段本身自始正确，未改动 ⇒ 固件解析不受影响**（按 `LEN` 取整帧即可，不要用"总长"列的旧数字推算）。
> 逐项断言见 `tools/_t101_parser_selftest/` 的 **T13**（17 条）。

> **为什么 STOP 态命令也要回一帧快照**：STOP 态没有显示帧，"看 STA"这条路是断的。回一帧快照等于把**回执与配置校验一次做完**，且不引入新帧型。
> **SET_REGS 帧长上限（v2.2 **订正** · T128 2026-09-23）**：
> 旧文写"CDC 接收缓冲 `msg.data[128]`（`Core/Src/vcomcmd.c:34`）⇒ 单帧 ARG ≤ 100 B（即 **N ≤ 50**）。36 项一次性下发 **LEN = 73**，安全。" ——
> 🛑 **该口径是错的**（T127 查出、T128 订正）：`msg` 是 **ASCII 通道**的局部结构体（就是 `:287` 那条"`msg.data[s0_index]` 无边界检查"里的那个），**二进制通道根本不用它**。
> 二进制下行帧的真闸是固件里的 **`VCOM_BIN_MAX_LEN = 58u`**（`Core/Src/vcomcmd.c`）：`LEN = 1 + 2N ≤ 58` ⇒ **`N ≤ 28`**；
> 帧总长 `7 + 2N ≤ 63 B`，落在 CDC 单包上限（64 B）之内 ⇒ **天然单包落地**。
> ⇒ **36 项必须分 2 批下发（28 + 8）**。
> ⚠ 两个**互相独立**的约束给出**同一上限**（互为印证）：固件上限 `LEN ≤ 58 ⇒ N ≤ 28`；CDC 单包 `7+2N ≤ 64 ⇒ N ≤ 28`。
> 🛑 误发 N=36（LEN=73／**79 B**）的表现是**静默丢弃 + 1.0 s 超时**（不崩、不误写）；`7+2N` **恒为奇数** ⇒ 永不撞 64 B 整包边界。
> 依据：T127 预检卡 ＋ T128 落码；边界已断言化（`tools/_t128_g10_sim.py` §3）。

### 5.2 各命令的确切语义

#### `0x01` START
固件原子序列（**重要：必须内建写表**）：
```
1. 若 AFE 未配置 → 写 regs_leaderIII 全表（36 条，逐条回读校验）
2. ads1293_conversion(true)
     → ecg_dc_block_init / ecg_filter_f64_init / ecg_out_f32_init
     → 复位计数器（ecgfilteridx / seQidx / gdtover）
     → demo_ads1293_start()：_bconvstart = true
     → CONFIG(0x00) = 0x01（START_CON）
```
> 🛑 **为什么 START 必须内建写表**（新查出来的事实）：
> `Core/Src/main.c:99` 只调了 `demo_ads1293()`，它只做 `ads1293_raw_queueinit()`（队列初始化）然后进 `while(1)`；
> `ads1293_afe_test()` 写表的唯一入口是串口命令 `test afe`（`vcomcmd.c:156-161`）。
> ⇒ **上电后 ADS1293 一直是芯片默认配置，regs_leaderIII 从未被写过**。
> 现在你能出波形，是因为每次试验都先敲了 `test afe`。
> 上位机的 Start 按钮如果只发 START、不写表，**波形会是错的（或全 0），而且是静默的**。
> ⇒ 这是本方案里**唯一一处会静默出错**的地方，必须钉死。

#### `0x02` STOP
```
ads1293_conversion(false)
  → demo_ads1293_stop()：_bconvstart = false
  → CONFIG(0x00) = 0x02（STANDBY ⇒ 同时解除 0x11/0x12/0x13/0x21–0x29 的写锁）
  → queue_reset(&EcgQueueRaw)
🛑 补 queue_reset(&EcgQueueFilter)   ← 现状漏了，见 §5.3 缺口 ③
```

#### `0x03` RESET —— **本协议最需要说清的一条**

**先纠正一处口径**：ADS1293 **没有软件复位命令**。
- 手册只给出 **RSTB 引脚**（TI ZHCSA21C p3 引脚表：`RSTB 25 Digital Input Reset bar`；p8：`SYNCB and RESETB pins, with 1-MΩ internal pullup`）
- 本项目固件**只接了 CS/CLK/MISO/MOSI/DRDY**（`Core/Inc/main.h:60-68`），**没有 RSTB 的控制线** ⇒ 固件**无法**用硬件复位 AFE

⇒ "复位 AFE"在固件层面只能是 **STANDBY → 重写配置 → START** 这条路。

**RESET 命令的原子序列（固件内部）**：
```
1. STOP：CONFIG(0x00) = 0x02        → 解锁保护寄存器 + 停 DRDY
         queue_reset(&EcgQueueRaw) ＋ queue_reset(&EcgQueueFilter)     ← 两个都要
2. 软件复位：ecg_dc_block_init / ecg_filter_f64_init（⇒ mode=diag、notch=on，fail-safe）
             / ecg_out_f32_init / ecgfilteridx=0 / seQidx=0 / gdtover=0 / _ecgrawidx=0
3. 重写 regs_leaderIII 全表（36 条，逐条回读校验）
4. ★★ 停在 STOP 态（不自动 START）
5. 上行 Type 0x03 快照帧（REQID = 0x03）—— 这既是回执，也是让上位机复核的凭据
```

> ### 🛑 这一条决定你第 2 条的**顺序**对不对
>
> 手册 p43 Note：**`Programming START_CON = 1 locks write access to registers 0x11, 0x12, 0x13 and 0x21–0x29.`**
>
> | 你给过的两种顺序 | 判定 | 原因 |
> |---|---|---|
> | 上一轮：「**先全部下发，再下发复位命令**」 | ❌ **错** | RESET 内建写全表 ⇒ 把你刚下发的值**覆盖回默认**（而且静默） |
> | 本轮：「**reset 然后下发 JSON 表**」 | ✅ **对** | RESET 后仍停在 STOP ⇒ `START_CON = 0` ⇒ 锁是开的 ⇒ 表写得进去 |
>
> **本轮的顺序是对的，我按后者落文档。** 但它成立有一个前提：**RESET 必须停在 STOP，不能自动 START**——否则 START 一置位，`0x13/0x21–0x24` 立刻锁死，JSON 表照样写不进去。
>
> **一处口径要说死**：你说"reset 是下位机整机复位，只复位 AFE"。这两句字面矛盾（"整机复位"通常含 MCU 复位，USB 会一起断、上位机要重连）。本方案取**后者**：**只复位 AFE 与滤波软件状态，MCU/USB 不动**。若你要的是真整机复位（`NVIC_SystemReset`），那是另一条命令（`0x07`，暂不定义），代价是 USB 重新枚举、上位机必须自动重连——请明示。

#### `0x04` SET_MODE / `0x05` SET_NOTCH
```
SET_MODE  : ecg_filter_f64_set_mode(&f64, arg)
SET_NOTCH : ecg_filter_f64_set_notch(&f64, arg)
```
* **RUN 态才允许**。STOP 态设了白设——`ads1293_conversion(true)` 会经 `ecg_filter_f64_init()` 把两者复位成 **diag + notch on**（`Ads1293/ads1293.c:376`，fail-safe）。

## 7. 配置校验与 Start 放行判据

按你的放宽要求（2026-09-22 第 3 条拍板）：**只看"滤波相关的寄存器"**，三档口径见 §6.1。

| 组 | 寄存器 | 不一致时 | 为什么 |
|---|---|---|---|
| 🔴 **H 硬闸** | **11 条**（§6.2） | **阻止 Start** | 静默改变数据口径：电极映射 / fs / 参考 / 读回通道 / DRDY 源 |
| 🟠 **W 强告警** | **4 条**（§6.3） | 允许 Start，**红色**醒目标注 | 口径或关键指标变，但现象肉眼可见 |
| 🟡 **G 一般告警** | **20 条**（§6.4） | 允许 Start，黄色提示 | 只影响性能 / 功耗 / 裕度 |
| ⚪ **D 软件标志** | mode / notch / channel | 快照验不了（**不在寄存器里**） | 靠 Start 后补发命令 + STA 确认（§8） |

**比对时必须掩掉的易变项**：
| 寄存器 | 原因 |
|---|---|
| `0x00` `CONFIG` | bit0 `START_CON`、bit1 `STANDBY` 随运行态变 |
| `0x30` 及 `0x31–0x3F` | DRDY 一来自变 |
| `0x18–0x1E` | 随信号/导联变 |
| `0x40` `REVID` | 只读，芯片版本 |

⇒ 上位机的比对集合 = **表内 36 条 − `0x00`** = **35 条 = 11(H) + 4(W) + 20(G)** ✓

> 🛠 **修掉 v2.0 的一处自相矛盾**：v2.0 这里写「C 其余 **29** 条」，而 §6 又写「36 − `0x00` = **35** 条，A+B = 7 条硬闸」⇒ `35 − 7 = 28 ≠ 29`。**以 v2.2 的 `35 = 11 + 4 + 20` 为准**（29 是把 `0x00` 算进 C 又没扣掉所致）。

**Start 使能逻辑（效果图里的状态机）**：
```
打开串口 ──→ 自动 REQ_SNAPSHOT ──→ 收 0x03 帧
                                    │
        ┌───────────────────────────┴───────────────────────────┐
        │ H 组全一致                                              │ H 组有差异
        ▼                                                         ▼
  Start 使能 ✅                                          Start 禁用 🔴
  （W 组红色 / G 组黄色告警，不阻止）                     「Reset」/「一键下发差异」可用
                                                          → SET_REGS → 收新快照 → 复判
```

### 7.1 Reset 按钮的定位（v2.1 重写 · **v2.2 定：与「一键下发差异」并存**）

> **仅在 STOP 态可点** —— 它是**上电初期的寄存器检修动作**，此时必然不在 START 态（且配置不一致时 START 本就禁用）。
> **作用序列**：① 内建 `CONFIG=0x02`（STANDBY，解锁 `0x11/0x12/0x13/0x21–0x29`）→ ② 重写投产表 `regs_leaderIII` 36 条 → ③ 逐条回读校验 → ④ **停在 STOP**（**不自动 START**）→ ⑤ 上行 `0x03` 快照。
> **重点不是"复位"，而是「把不一致的寄存器写回期望值」** ⇒ 因此它与「一键下发差异」是**同一族动作**，差别只在范围：`Reset` = 全表回投产默认；`一键下发差异` = 只写不一致项。

> ✅ **v2.2 定（第 2 条）：两个按钮并存，不合并。** 分工：
> | 按钮 | 何时用 | 写什么 | 结果 |
> |---|---|---|---|
> | **Reset** | 怀疑配置被人改乱 / 换了板子 / 首次调试 | **全表 36 条**回投产默认（`regs_leaderIII`） | 已知好态；**有意改动会丢** |
> | **一键下发差异** | 明知改了哪几项、只想补齐 | **只写不一致项**（G 组；见 §6 JSON 约定） | **保留有意改动** |
> 两个都得**仅在 STOP 态可点**（写入前内建 `CONFIG=0x02` STANDBY 解锁，见上方序列）。

> 🛑 **"复位 AFE"在硬件上做不到**：ADS1293 **无软件复位**，只有 `RSTB` 引脚（手册 p3 引脚表、内部 1 MΩ 上拉），而本板**未接** —— `Core/Inc/main.h:60-68` 只有 `CS / CLK / MISO / MOSI / DRDY`。⇒ 所谓复位只能落成「**STANDBY + 重写表**」。
> 🛑 **Reset 覆盖不到 mode/notch**：它们是 `ecg_filter_f64` 的**软件标志**（`ads1293.c:376` 的 `ecg_filter_f64_init()` 会把它们复位成 **diag + notch on**）⇒ Reset 之后**必须补发**，否则出现"全表写成功、状态却回默认"的错觉。
> ⚠ **队列残留**：`ads1293_conversion(false)` 只 `queue_reset(&EcgQueueRaw)`（`ads1293.c:389`），**不清 `EcgQueueFilter`** ⇒ 切 channel / Reset 后队列里最多残留 25 个**旧配置**样本（853 下 ≈29 ms），会以新配置发出去。范例：`ads1293_set_raw853()` 里带着 `queue_reset(&EcgQueueFilter)`（`ads1293.c:511`）—— Reset/START 也要照做。

## 8. 命令生效判据（隐式 ACK）

你选"下行不需要回复"——**对**，但不能没有确认手段。既然 STA 每帧都带：

| 命令 | 判据 | 超时 |
|---|---|---|
| START | `0x01` 帧开始上行（或 500 ms 内见任意 `0x01`） | 1 s |
| STOP | `0x01` 帧停止上行 | 1 s |
| RESET | 收到 `0x03` 快照帧（REQID=0x03） | 1 s |
| SET_MODE | 后续帧 `STA.bit0` == 期望值 | 1 s（500 Hz ⇒ 20 帧） |
| SET_NOTCH | 后续帧 `STA.bit1` == 期望值 | 1 s |
| SET_CHANNEL | 收到 `0x03` 快照帧 且 `0x01/0x02/0x2F` 与期望一致 | 1 s |
| SET_REGS | 收到 `0x03` 快照帧 且目标项回读 == 期望值 | 1 s |

未在超时内观察到 ⇒ **状态栏红色告警「命令未生效：SET_NOTCH(off)」**，并在日志记一条。
🛑 **必须加**：本项目"静默失效"已坑过 **两次**——T92b（回显逐字相同判不出档）、T71/T72（宏名拼错静默变档）。命令帧丢了、CRC 错了、顺序反了，**没有这个机制你永远不知道**。
