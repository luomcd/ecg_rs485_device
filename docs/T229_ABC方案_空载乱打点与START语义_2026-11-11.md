# T229 A+B+C 方案：空载乱打点 / 启动伪影 / START 语义

> **日期**：2026-11-11　**状态**：**方案待评审，未动代码**
> **上游**：`T227` §2.3（首秒伪影三层根因）、§6.2（P4-e/P4-f）、`T228` §9（三状态实测）
> **一句话**：三个问题、三个改动，**必须 A+B 同时上、C 随后**，因为它们互为前提（见 §5）。

---

## 0 结论摘要

| 项 | 改什么 | 解决 | 风险 |
|---|---|---|---|
| **A** | ESP32：`485-start` / 清屏**不再清零检测器** | 去掉"零初值 + 无信号"这个自激前提 | 低（局部改动） |
| **B** | ESP32：阈值加**绝对下限**（≈200 µV 等效） | 兜底：即使零初值且无信号，也不许在噪声上打点 | 低（可用 48 条 + 11 份采集回归验证） |
| **C** | STM32：`0x01/0x02` 改为**纯输出开关**（滤波链常跑） | 去掉 START 时 0.05 Hz 阶跃尾巴 ⇒ 无启动伪影 | 中（动 ADS1293 状态机与队列语义） |

**依赖关系（关键）**：**C 会让首样本变 ≈0**（0.05 Hz HPF 把 DC 去掉），而"首样本≈0"正是自激最强的条件
（DC 偏置表 0/100/500/2000/8000 ⇒ 峰数 46/36/1/1/1）。**所以 C 必须排在 B 之后**，否则会把"1 个启动伪峰"换成"4 拍/秒"。

## 1 问题归因（先对齐事实，避免方案打偏）

| 现象 | 实测 | 根因 |
|---|---|---|
| 空载时屏上乱打点 | AECG 上电未输出 **3.7~4.5 拍/秒**（4 次）；下电 0~4.15（5 次随机）；悬空 ≈0（3 次） | 阈值 `thr = noise + 0.25(signal−noise)` 在 `signal≈noise≈0` 时 ⇒ `thr≈0`；伪峰自我维持 |
| 打点强度 | 峰处 **±170 LSB（±26 µV）**，真实 R **≈9,923 LSB（≈1,514 µV）** ⇒ **差 58 倍** | 同上（噪声被当 R 峰） |
| START 后头几拍不对 | 48/48 条 MIT 首个检出峰都在 **sample 3** | 首样本相对 `baseline=0` 的 DC 台阶 ⇒ 一击过阈 ⇒ 伪峰，并把 `last_slope` 污染 ⇒ 紧邻真 R 被判 T 波 |
| 测量重复性差 | 同一状态 4 次起流：0.00 / 0.11 / 1.08 / 4.15 拍/秒 | **每次 `485-start` 都 `ecg_rpeak_init()` 清零**（`ecg_pipeline.c:926`，在 `pipeline_launch()` 内），零初值 + 首帧台阶随机 ⇒ 结果随机 |
| 清屏后计数突变 | 日志 `app_state: clear` → `rpeak detector reset (epoch++)` | 清屏也清零检测器（与 T212「纯视觉」的字面不符） |

## 2 A 方案：去掉"清零检测器"的错配

### 2.1 现状

```c
/* ecg_pipeline.c:926（pipeline_launch 内）—— 无条件清零 */
ecg_rpeak_init(&s_rp, APP_SAMPLE_RATE_HZ);
```

调用者：`485-start`（每次）、`mit-run`/`play`（换文件）、清屏（`ui-clear` / 屏上键，经 `s_rp_reset_req`）。

### 2.2 改法

| 场景 | 现在 | 改为 | 理由 |
|---|---|---|---|
| **`485-start`（RS485 源）** | 清零 | **不清零**，沿用现有状态 | 同一路连续信号只是断了一段，清零等于人为制造零初值 |
| **FILE 源换文件 / 从头播** | 清零 | **保留清零** | 换了数据源，旧状态无意义 |
| **改采样率** | 清零 | **保留清零** | 滤波器系数与积分窗都变了 |
| **清屏** | 清零 | **不清零**（只清已绘制的点） | 与 T212「清屏＝纯视觉」一致；且清屏后 BPM 不该从 `--` 重新收敛 |
| 人工强制复位 | 无 | **新增 `rpeak reset`** | 排查/验收时需要可重复的干净起点 |

### 2.3 风险与对策

| 风险 | 分析 | 对策 |
|---|---|---|
| 长时间断流后 `signal_peak` 偏高 ⇒ 前几拍被抑制 | 真实 R 的积分 ≈10⁵，`thr = 0.25×signal_peak`；只有 `signal_peak > 4×10⁵` 才会挡住真 R，实际不会 | 可接受；B 落地后阈值有下限、上限由 `signal_peak` 决定，行为不变 |
| 换导联/换增益后沿用旧状态 | 增益变化 ⇒ 幅度尺度变化 ⇒ 旧 `signal_peak` 失配 | **改增益必须清零**（并入"改采样率"那一行） |
| 清屏不清零后，屏上旧打点与新打点混在一起 | 只是视觉 | 清屏本来就清绘制点，BPM 继续——这更符合直觉 |

## 3 B 方案：阈值绝对下限

### 3.1 现状与改法

```c
/* ecg_rpeak.c:236 —— 现在 */
thr = fmaxf(TINY, noise_peak + 0.25f * (signal_peak - noise_peak));

/* 改为（一行改动 + 一个标定常数） */
thr = fmaxf(ECG_RP_THR_FLOOR, noise_peak + 0.25f * (signal_peak - noise_peak));
```

`ECG_RP_THR_FLOOR` 是**积分域**的门限（与 `signal_peak`/`noise_peak` 同量纲），不是 µV。

### 3.2 标定：从 µV 换算到积分域

积分定义（Pan-Tompkins 式）：`integ = mean(d²)`，`d` 是带通输出的差分/8，窗长 60 样本。
⇒ **`integ ∝ 幅度²`**，所以门限必须按"等效 QRS 幅度"标定。

实测锚点（今天 replay 日志，记录 100）：

| 项 | 值 |
|---|---|
| 真实 R 波峰处积分 | **98,220 / 98,775 / 98,487**（三次连续） |
| 对应幅度 | 9,923 LSB ≈ **1,514 µV**（1 LSB = 0.1526 µV） |
| ⇒ 系数 `k = integ / A²` | 98,500 / 1514² ≈ **0.0430 /µV²** |
| 噪声（±26 µV）预期积分 | 0.0430 × 676 ≈ **29**（与实测 `thr` 3~13、`noise_peak` 8~14 同量级 ✓ 模型自洽） |

**候选门限**：

| 等效幅度 | `ECG_RP_THR_FLOOR` | 能挡噪声吗 | 能过 0.3 mV QRS 吗 |
|---|---|---|---|
| 150 µV | 970 | ✅（噪声 29，33 倍余量） | ✅（0.3 mV ⇒ 3,870） |
| **200 µV（推荐）** | **1,720** | ✅（59 倍余量） | ✅（22 倍余量） |
| 300 µV | 3,870 | ✅ | ⚠ 0.3 mV 恰好卡线，无余量 |

> 🛑 **这个门限的物理含义是"等效 200 µV 的 QRS 形状"，不是"任意波形的绝对幅度"**：
> `integ ∝ (dV/dt)²` 对形状敏感 —— 同样 200 µV，窄尖峰积分远大于宽波。
> 所以它是"QRS 形状的等效门限"，标定必须在 **QRS 波形**上做，不能拿正弦外推。

### 3.3 增益相关性（必须处理）

`integ` 随增益变化（增益 ×2 ⇒ 幅度 ×2 ⇒ integ ×4）。三个选项：

| 选项 | 做法 | 取舍 |
|---|---|---|
| **B1（推荐）** | 门限按**当前增益档**换算：`FLOOR = k × (200µV → LSB(增益))²` | 一次标定每档一个常数，最简单 |
| B2 | 用 `UV_PER_LSB` 运行期换算成 LSB，再平方 | 需要固件知道当前 µV/LSB，与 STM32 增益档耦合 |
| B3 | 不改门限，改在"喂检测器之前"把样本归一化到固定 µV/LSB | 改动面大，会影响 MIT 重放口径（不可接受） |

**B1**：在 `ecg_rpeak.h` 里放一张小表（增益档 → FLOOR），或直接给宏，按当前档编译/运行期选择。

### 3.4 ⚠ 这个门限**挡不住**启动伪影

首样本 DC 台阶的积分是 **13,487**（记录 100 实测），**远高于 1,720** ⇒ 仍然会被接受。
⇒ **B 只治"无信号自激"，不治"启动伪影"。** 后者要靠 A（不清零）+ C（无阶跃）。

两者互补，这也是为什么必须一起做：

| 方案 | 治自激 | 治启动伪影 |
|---|---|---|
| A（不清零） | ✅ 去掉零初值 | ➖ 部分（没有"人为清零"就没有零状态可比） |
| B（绝对门） | ✅ 兜底 | ❌ 挡不住（13,487 ≫ 1,720） |
| C（无阶跃） | ❌ | ✅ 首帧无台阶 |

## 4 C 方案：`0x01/0x02` 改为纯输出开关

### 4.1 现状

实测调用链（`ads1293.c:847` `ads1293_start()`）：

```
0x01 → ads1293_start()
  ① ads1293_conversion_run(false)   // 停流 + STANDBY + 清 Raw 队列
  ② queue_reset(&EcgQueueFilter)     // 清 Filter 队列
  ③ ads1293_write_table(...)         // 写全表 + 逐条回读
  ④ 成功 → ads1293_conversion_run(true)
        └─ 内含 ads1293_filter_chain_init()（ads1293.c:467）← ★ 滤波链在这里被复位
0x02 → ads1293_stop() = conversion_run(false) + queue_reset(&EcgQueueFilter)   // 停流
```

⇒ **START 同时做了四件事：停流、清两队列、写全表、复位滤波链**。要"纯开关"必须把 ①③④ 拆出去。

### 4.2 目标语义（猛哥 11-11 定）

> **STM32 上电即复位滤波链并开始转换；`0x01` 只是"输出开关"打开，`0x02` 只是关上。
> 滤波链与 ADC 一直在跑，STOP 态不停止转换（功耗暂不考虑）。**

### 4.3 改法要点

| # | 要点 | 说明 |
|---|---|---|
| 1 | **上电路径**：`reset_afe()` + `conversion_run(true)` + `output_enable = true` | 与现在"上电即 RUN"一致（如果现在就是），关键是**之后不再复位** |
| 2 | **`0x01`**：只置 `output_enable = true`，**不** stop/standby/写表/复位滤波链 | 幂等；重复 START 无副作用 |
| 3 | **`0x02`**：只置 `output_enable = false`，**不停转换、不复位** | 队列必须继续被消费（见 #4） |
| 4 | 🛑 **STOP 态必须继续排空队列** | 否则 ADC 继续产生样本 ⇒ 队列溢出 ⇒ 恢复发送时先吐一堆旧数据（比不改更糟） |
| 5 | 保留显式重初始化命令（`0x03 RESET` 已有） | 换导联、改增益、切诊断档时用 |
| 6 | 协议不变，`0x01` 的 ACK 语义仍是"显示帧流起" | 上位机侧无需改动 |
| 7 | 可选：`STATUS` 增加一位"采集中/仅输出关" | 否则上位机分不清"没数据"与"停止发送" |

### 4.4 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| STOP 态队列溢出 | 恢复时吐出旧数据 | #4 强制排空；加一个"队列深度告警" |
| 长期 STOP 后滤波链漂移 | 0.05 Hz HPF 一直工作，DC 稳态为 0 | **这是目标**，但 ⇒ 首样本≈0 ⇒ **必须等 B 到位**（见 §5） |
| 上位机假设"START 后从零开始" | WinApp 可能按"数据重新开始"处理 | 需确认（§8 待拍板③） |
| 掉电/复位后行为变化 | 上电即转换 ⇒ 功耗上升 | 猛哥已确认可接受 |

## 5 实施顺序与依赖（这条最要紧）

```
      ┌───────────────────────────────────────────────┐
      │ 第一步：A + B（都在 ESP32，可同一次构建验证）  │
      └───────────────────────────────────────────────┘
                          │
                          ▼
      ┌───────────────────────────────────────────────┐
      │ 第二步：C（STM32 纯开关）                      │
```

**顺序不能颠倒**：先做 C 会让"启动伪影"变成"持续 4 拍/秒"，症状更严重且更容易被误判成"C 做坏了"。

## 6 验证方案（每个方案各自的判据）

### 6.1 A（不清零）

| 检查 | 判据 |
|---|---|
| `485-start` 后 `peaks` 计数**不归零** | 连续两次 `485-start`，第二次之前 `peaks` 保持、`fed` 继续累加 |
| 清屏后 BPM 不回到 `--` | 清屏前后 `bpm` 连续（允许小幅波动） |
| FILE 源换文件仍清零 | `mit-run` 换文件后 epoch 递增 |

### 6.2 B（绝对门）

| 检查 | 判据 |
|---|---|
| **MIT 48 条回归**（最重要） | Se/+P/DER **与 T227 §2 主口径完全不变**（99.0867 / 99.0252 / 1.8887）；逐峰序列一致 |
| 11 份 AECG 采集重放 | σ(e) 不变；峰数不变 |
| 空载（三状态 × 5 次起流） | 打点密度 **从 ~4 拍/秒 → 0** |
| 低幅不误杀 | 用 1 mV 与 2 mV 两套采集确认灵敏度无变化；另需一份低幅（≤0.5 mV）样本做专项 |

### 6.3 C（纯开关）

| 检查 | 判据 |
|---|---|
| START 后首帧质量 | 首样本**不出现** DC 台阶（对比改造前后 100 号等价数据） |
| STOP→START 连续性 | 恢复后首帧的时间戳紧接 STOP 前（无旧数据吐出） |
| 队列不溢出 | STOP 态持续 60 s 后 START，首帧样本值接近实时值（不是 60 s 前） |
| 板端逐峰对账 | MIT 48 条 batch 与 PC 一致（沿用 T228 流程） |

### 6.4 回归口径

- **MIT 48 条**：`mitbih_compare.py --skip-run` 与 `--no-trim` 两套都要跑，确认零变化；
- **HRV 6 心率**：σ(e) 不劣化（60/150/180/210 ≤0.35，90/120 不应变差）；
- **板端**：`mit-set` batch 3 条逐峰对账。

## 9 不做的事（避免走偏）

- 🛑 **不做 STM32 侧"预热 N 秒丢弃数据"**：C 已能零延迟达到同样效果，预热还要背 10~15 s 的延迟（0.05 Hz，τ=3.18 s，到 5% 需 3τ≈9.6 s）。
- 🛑 **不用 `K × noise_peak` 做闸门**：无信号时 `noise_peak` 会被伪峰自己抬高，闸门跟着水涨船高（10-29 已实测）。
- 🛑 **不靠 LOD**：三状态（上电未输出/下电/悬空）`lod` 全为 0，当前配置下完全不可用。
- 🛑 **不改 MIT 重放口径**：不在"喂检测器之前"做归一化（B3），否则 48 条基线与历史 W1 全部失去可比性。

### 11.3 `SET_REGS_FORCE` 的复位落点（待补，非本轮）

### 12.2 只拿到 2 次的原因（与 B 无关）

同一会话内跑 `stop→start` 循环：**每次上电后约能成功 2 次，第 3 次起必失败**（两次独立复现：
首轮会话 1 成 4 败、重上电后 2 成 3 败）。
失败特征：`485-send start` 后 `Δrx` 为 **63/64 B 且全是 resync**，`frames` 不涨。

- 63 B = 失败回显里 `idx` 为**一位数**；64 B = `idx` 为**两位数** ⇒ **失败的寄存器下标不固定**
  ⇒ 不是某个寄存器坏，而是**写后回读的一致性/时序**问题；
- 同一时刻 `0x10` 快照能回 **80 B** ⇒ **读通、写失败**；
- ESP32 侧无重启（单会话 uptime 连续）。

### 12.3 测量陷阱（11-11 11:50 已订正：原先的"关串口即复位"是错的）

**先纠正结论**：我曾判断"每关闭一次 COM35，ESP32 就复位一次"。**实测推翻**：

| 步骤 | 源 | UART | frames |
|---|---|---|---|
| 起流后 | RS485 | ready | 0 |
| 关闭 → 用 **DTR=0/RTS=0** 重开（不 `485-start`） | **RS485** | **ready** | 0 |
| 关闭 → 用 **默认 DTR=1/RTS=1** 重开 | **RS485** | **ready** | 0 |

⇒ **关端口、动 DTR/RTS 都不复位。**

**真正的现象与原因**：每次新会话 `485-stat` 都是 `frames=0`，因为
**`485-start` 内部会调 `rs485_reset_stat()` 把计数器清零**（`ecg_pipeline_start_rs485()`）；
而 `源=FILE` 是因为上一轮结束时源已非 RS485。**这两条都不是复位。**

⇒ **测量纪律（仍然有效，但理由变了）**：需要连续状态/多轮统计的测试要
**在同一会话内一次做完**，因为每轮 `485-start` 都会清零计数器、重建源，
跨会话难以区分"板子出事"与"我自己清了它"。

## 13 结案：START 随机失败 = ADS1293 供电不足（2026-11-11 14:20）

### 13.1 结论

**根因是 ADS1293 的供电电池电压不足**，与固件无关。换满电电池后同一测法：

| 状态 | 固件 | `stop→start` 成功率 |
|---|---|---|
| 欠压 | 基线 | **3/6** |
| 欠压 | A（CONFIG 后 1 ms 延时） | 1/8 |
| 欠压 | B（回读确认 CONFIG==0x02） | 0/8 |
| 欠压 | C（预写 LOD_EN 再写表） | 0/8 |
| **满电** | **基线** | **8/8 ✅** |

满电复测 8 轮：`frames` 累计 56 → 707（每轮 +90~95，连续流不断），**`peaks` 全程 0**，`lod` 全程 0。

### 13.2 欠压时的所有表征（供以后快速识别）

| 表征 | 说明 |
|---|---|
| 写表校验失败，回显 `start FAIL: idx=N reg=0x.. want=0x.. got=0x..` | `got` 常见 `0x00`（未上电/掉电时 SPI 读为 0） |
| **失败 idx 随机漂移**（idx=2 → idx=3） | 不是寄存器语义问题，是时序/电平 |
| 偶发**数据错位**：`reg=0x02 got=0x11`（0x01 的值跑到 0x02） | 边缘供电下的 SPI 错位 |
| 成功率**随时间单调下滑** | 电池持续放电 |
| `snap` 仍回 80 B | 🛑 **不能据此判"读通"**（见 §13.3） |

### 13.3 🛑 一条必须记住的判据修正

**「`485-send snap` 回 80 B」不等于"读通"。**
80 B 只证明 **STM32 把快照帧构造并发出去了**，不证明 ADS1293 应答；
芯片未上电/欠压时快照照样是 80 B（内容全 0 或全 FF）。
⇒ 判"读通"必须看**快照内容是否等于期望值**，不能只看帧长。本报告 §12.2 曾据此误判"读通、写不通"。

### 13.4 A / B / C 三次尝试的最终定性

| 方案 | 是否解决 START 失败 | 处置 |
|---|---|---|
| A（CONFIG 后加 1 ms） | ❌ 反而更差（1/8） | 已撤销 |
| B（回读确认 CONFIG==0x02） | ❌ 更差（0/8） | 已撤销 |
| C（预写 LOD_EN 0x02） | ❌ 失败点从 idx=2 漂到 idx=3 | 已撤销 |

**三者都基于"停流未生效/寄存器语义"的推断，而真实原因是供电** ⇒ 全部作废，固件回到基线。

> ⚠ **遗留观察（供电正常后仍值得记一笔）**：`ECG_LOD_EN = 0`（LOD 未使能）但表里仍写
> `{0x01, 0x11}`(LOD_CN) 与 `{0x02, 0x19}`(LOD_EN)。满电时能通过，但这是一处**配置不自洽**，
> 若将来启用 LOD 需一并梳理。
