## 0.1 名词：`trigger` / `fid` / `fid_delta` 到底是什么

后文反复出现这三个词，先把它们钉死。**本文的「新旧固件」差别就落在这三个量的关系上。**

### fid = fiducial point（基准点 / 定位点）

指**这一拍最终被认定的样本位置** —— 也就是写进 `last_peak`、参与 RR / BPM 计算、
屏上打点、HRV 记录的那个下标。**"fid" 就是 fiducial 的缩写**，工程上常说"基准点"或"落点"。

它不是"检测到的那一下"，而是"事后在这个峰附近挑出来的、最能代表这一拍的位置"。
挑法见 §3.2：在 `[trigger−40, trigger+40]` 窗口里，取**滤波值绝对值最大**的那一个样本
（`|value|` 而不是 `value`，所以负向极值也参与竞争）。

### trigger = 触发坐标（粗定位）

积分包络（`∫(dv/dt)² dt`，60 样本窗）出现局部极大时，把该极大回退
`1 + 60/2 = 31` 个样本，得到 `trigger`。它回答的是"**这一拍大概在哪**"，
精度只有 ±几十样本，**不能直接拿去算 RR**。

`trigger` 只用于三件事：**搜索窗口的中心、不应期比较、候选池筛选与删除**。

### fid_delta = fid − trigger（偏移量）

P3A 真正存进候选池的就是这个偏移量，`int16_t`。范围受搜索半径约束：
`|fid_delta| ≤ ECG_RP_LOCATE_HALF = 40`。

实测它**不是一个常数**：主路径上取值从 **−32 到 +31** 都有。原因见 §4：
同一拍的积分包络常有 2~3 个局部极大（弱的前沿极大 → `fid_delta ≈ +30`；
强的顶点极大 → `fid_delta ≈ −9`），**哪一个先过阈值就由哪一个决定 trigger**，
但 `locate_rpeak()` 最后都能找到同一个 R 顶。

### 新旧固件的关键差别（一句话）

| | 旧固件（`ECG_RP_USE_STORED_FID=0`） | 新固件（`=1`，P3A） |
|---|---|---|
| fid 什么时候算 | **接受峰的那一刻才现算** | **候选入池那一刻就算好并存下** |
| 回溯路径怎么拿 fid | 事后重新 `locate_rpeak(trigger)` —— 此时 `[trigger±40]` 可能已滑出 `filt_hist`(140) ⇒ 拿不到就**原样返回 trigger** | 直接 `trigger + fid_delta`，**不需要历史** |
| 后果 | 回溯拍的 fid 退化成 trigger，比相邻拍偏 ~9 样本（部分覆盖时可达 27） | 回溯拍与主路径拍用同一套落点，fid 稳定 |

**一个类比**：`trigger` 是"**大概在第 3 秒附近**"，`fid` 是"**精确到第 3012 个样本**"。
旧固件在回溯时把"精确位置"丢了、退回到"大概位置"，于是这一拍与前后拍的间隔
突然多出或少了 9 个样本 —— 这就是 σ(e) 从 0.35 恶化到 2.5 的全部来源。
（"回溯"= backtrack：某拍积分能量低于主阈值没被接受，等过了 1.66×RR 还没等到下一拍，
检测器回头去候选池里把它捞回来。）

## 2 数据结构与内存（实测，非估算）

### 2.1 为什么用并列数组

`ecg_rp_cand_t` 是 `int64 + float + float` = **16 B**。在 8 字节对齐下，
直接往结构体里塞一个 `int16_t fid_delta` 会被撑到 **24 B** ⇒ 64 项白涨 **512 B**。

因此按 T225 §4.1 改为并列数组：

```c
ecg_rp_cand_t cand[ECG_RP_CAND_MAX];              /* 原样 */
#if ECG_RP_USE_STORED_FID
int16_t  cand_fid_delta[ECG_RP_CAND_MAX];         /* fid - trigger，+128 B */
#if ECG_RP_DIAG
uint8_t  cand_win[ECG_RP_CAND_MAX];               /* 入池时窗口覆盖量，+64 B */
#endif
#endif
```

### 2.2 实测预算（host 打印 `sizeof(ecg_rpeak_t)`）

| 配置 | `sizeof` | 增量 |
|---|---|---|
| `USE_STORED_FID=0`，`DIAG=0` | 3888 B | — |
| `USE_STORED_FID=1`，`DIAG=0` | 4016 B | **+128 B** |
| `USE_STORED_FID=0`，`DIAG=1` | 3920 B | （诊断 +32 B） |
| `USE_STORED_FID=1`，`DIAG=1` | 4112 B | **+192 B** |

- `fid_delta` 用 `int16_t` 的安全边界：`|fid - trigger| ≤ ECG_RP_LOCATE_HALF = 40`。
- 🛑 **运行时仍有范围保护**（不靠"应该不会溢出"）：

```c
fid = c->index + (int64_t)rp->cand_fid_delta[cslot];
if (fid < c->index - ECG_RP_LOCATE_HALF || fid > c->index + ECG_RP_LOCATE_HALF) {
    fid = c->index;              /* 宁可退回 trigger，也不跳出去读陈旧槽位 */
}
```

若将来把 `ECG_RP_LOCATE_HALF` 放大到 >32767 才需要换类型（实际不可能，但留了判断）。

## 3 统一候选解析数据流（T225 §4.2）

```
本拍积分峰 local max
        │
   prev_integ > sec_thr ?
        ├─ 否 ──────────────────────────────┐
        └─ 是                                │
             ├─ locate_rpeak(trigger,&win) ← 只在这里算一次
             ├─ cand[] ← (trigger, value, slope)
             ├─ cand_fid_delta[] ← fid - trigger
             └─ fid_ready = true              │
                                              │
   prev_integ > thr 且 !is_twave 且 spacing≥REFRACTORY ?
        ├─ 否 → 记 noise_peak                │
        └─ 是 → fid = fid_ready ? fid_now : locate_rpeak(trigger,&win)
                 accept_peak(fid)
```

**关键点（T225 §4.2 第 2 条）**：主路径**不再单独调一次** `locate_rpeak()`。
入池那一刻的窗口覆盖与主路径接受时**完全相同**（同一 `sample_index`、同一 `rp` 状态），
所以复用是精确等价的，不是近似。

**回溯分支**：

```c
fid = c->index + cand_fid_delta[cslot];      /* 不用窗口、不依赖 lag */
accept_peak(fid, ...);
/* 丢弃 <= c->index 的候选 —— 仍按 trigger 判，P3A 不混坐标 */
```

### 3.1 P3A 冻结了什么（T225 §4.3）

| 语义 | 用的坐标 | P3A 是否改动 |
|---|---|---|
| 触发判定（积分 local max） | trigger | 不变 |
| `spacing` / T 波判别 | `peak - last_peak` | 不变 |
| 不应期 `ECG_RP_REFRACTORY` | 峰间（现为 fid 与 trigger 混合） | 不变 |
| 回溯候选筛选 `c->index` 比较 | trigger | 不变 |
| 候选删除条件 | trigger | 不变 |
| 输出峰 / RR / BPM / 打点 | **fid** | 只在回溯分支改（这正是目的） |

> 🛑 `spacing` 的「当前 trigger 减上一条 fid」混合坐标语义**留到 P3B**。
> P3A 刻意不碰它——碰了「主路径逐峰不变」这条验收口径就失去意义。

## 4 诊断字段（T225 §6.3）

```c
typedef struct {
    int64_t trigger;   /* 粗触发坐标 */
    int64_t fid;       /* 最终落点 */
    int64_t lag;       /* 回溯触发时 trigger 距当前样本的距离；主路径为 0 */
    int16_t win;       /* 本次窗口真正扫到的样本数（满窗 72） */
    int8_t  src;       /* 0=主路径 1=回溯 */
    int8_t  win_short; /* 1=窗口不满 */
} ecg_rp_diag_t;
```

- 访问器：`const ecg_rp_diag_t *ecg_rpeak_last_diag(const ecg_rpeak_t *rp);`
- **不参与任何判据**，只写字段；`ECG_RP_DIAG=0` 可整体省掉。
- 为什么值得占这 32 B：**T224 形态②（部分覆盖、静默选错）在 `loc != trigger` 时完全隐身**，
  板端唯一能观测到的物理量就是 `win`。这次要是没有它，P4 上板再出同类问题还是要靠 PC 抓包重放。

**90 bpm 实测**（`rp_fid1.exe ... _rp_cmp/90diag.csv`）：

| 项 | 值 |
|---|---|
| 总峰 | 271 |
| 回溯峰 | 22 |
| 回溯峰 `lag` | 212（首拍 134） |
| 回溯峰 `fid_delta` | **全部 −9** |
| 回溯峰 `win` | 72（满窗，全部精修） |
| 主路径 `fid_delta` 取值集合 | {−32, −9, −8, 4, 29, 30, 31} |

> **这张表里藏着一个重要发现**：主路径的 `fid_delta` **不是恒定的 +30**，而是从 −32 到 +31 散布。
> 原因是同一拍的积分包络常有 2~3 个局部极大（弱的前沿极大 → `fid` 在 `trigger+30`；
> 强的顶点极大 → `fid` 在 `trigger−9`）。**入池即存 fid 的真正价值不只是"补上滑出历史的窗口"，
> 而是让落点与"哪个局部极大触发了它"解耦** —— 同一物理 R 顶，不管被哪个极大触发，`fid` 都落在那里。
> 这也解释了为什么修完以后 σ 能压到 0.35：抖动的根源是「触发特征切换」，不是「窗口精度不够」。

## 6 实施过程中发现并修掉的三个夹具缺陷

这三个不修，"回归通过"本身就不可信，所以单列。

### 6.1 `rpeak_host` 无重同步 ⇒ 4 份采集被判 0 峰

原实现「帧头不对就 `break`」。485 直抓的文件开头常常是**半帧**（抓包从流量中间开始），
于是 `_raw_60bpm_2mv_c.bin` / `150` / `210` / `300` 四份直接 0 峰 0 样本。

> 这个症状极具误导性：看起来像"检测器不工作"，实际是夹具读不到数据。
> **判据**：夹具输出的 `frames=` 一栏若为 0，先查重同步，别查算法。

已改为逐字节扫 `AA55` + `LEN ∈ {52,53,103}` + CRC8 校验，与 `cap485_quality.py` 完全同口径。

### 6.2 CRC 覆盖范围写错 ⇒ 每一帧都被判坏

补 CRC 校验时把范围写成「`TYPE` + payload」，**漏了 `LEN` 两个字节**（`LEN` 在 `h[1]/h[2]` 里
而不在 payload 里）。结果 3610 帧全判 `bad`，`frames=0`。

> **判据**：`bad` 与 `frames` 同量级 ⇒ 是**校验范围**错，不是数据坏。
> 正确范围：`TYPE + LEN(2) + payload`，与 `ecg_frame.c:18 ecg_crc8()` 一致。

### 6.3 Python 夹具缺候选删除（T225 §4.4）

已在 `replay_rpeak.py` 补上「回溯接受后丢弃 `index <= best_trigger` 的全部候选」。
补完后 11/11 份与 C 逐峰一致 —— 说明这个差异在本批数据上**不影响结论**，
但作为长期 oracle 必须补（否则将来某份数据恰好在删除逻辑上分叉，会误判成"固件改坏了"）。

### 10.3 结论

1. **板上复现的现状值与离线几乎一致**：σ 2.50（离线 2.59 / 2.53）、P95 9.0（离线 9.0）、
   异常率 7.69%（离线 8.05% / 8.05%）。
2. **修法在板端效果与离线一致到小数点后两位**：σ **0.35**（离线 0.35 / 0.35），
   P95/P99/最大全部 = 1.0，异常 **0**。
3. ⇒ **Xtensa 单精度 float 与 host x86 的行为差异、以及实时链的时序，均未引入可观测分叉。**
   P4-a 目的达成。
