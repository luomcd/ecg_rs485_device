## 1 原理层：DC 导联脱落检测到底在测什么

### 1.1 一句话

**往电极注入一个已知的极小直流电流，看这个电流能不能流回去。**
能流回去 ⇒ 回路通 ⇒ 导联接着；流不回去 ⇒ 电流把电极节点电压顶到电源轨 ⇒ 比较器翻转 ⇒ 判脱落。

它不是测"有没有心电信号"、也不是测"信号幅度"，而是测**直流电流通路是否存在**。

### 1.2 手册给的判据（§8.3.16 原文要点）

| 项 | 内容 |
|---|---|
| 注入 | `LOD_CURRENT`(0x08) 编程，0~255 码 ⇒ **0~2.040 µA，步进 8 nA** |
| 注入点 | `LOD_EN`(0x07) 的 `EN_LOD[x]` 逐脚使能，注入该输入脚 |
| 比较对象 | 该脚电压 vs **VDD − 0.5 V**（施密特比较器） |
| 判定 | 脱落 ⇒ 电流无接地点 ⇒ 脚电压**向 VDD 抬升** ⇒ 越过 VDD−0.5 V ⇒ `OUT_LOD[x]=1` |
| 读出 | `ERROR_LOD`(0x18) 的 `OUT_LOD[5:0]`，MSB=IN6 … LSB=IN1 |
| **前提** | 🛑 必须有**低阻回流路径**（右腿电极到地，例如电压基准或 RLD 放大器输出）。**没有回流时，所有使能的 LOD 脚全报脱落。** |

### 1.3 为什么选 DC 模式，不选两种 AC 模式

手册给了三种模式：

| 模式 | `LOD_CN`(0x06) 配置 | 适用 | 本项目为何不用 |
|---|---|---|---|
| **DC** ✅ | `SELAC_LOD=0` | 电阻性电极（Ag/AgCl 湿电极、AECG100 输出端） | **本项采用** |
| 模拟 AC | `SELAC_LOD=1, ACAD_LOD=1` | 电容耦合/干电极（DC 被隔断） | 需要额外激励频率与阈值调参，湿电极用不上 |
| 数字 AC | `SELAC_LOD=1, ACAD_LOD=0` | 测**一对**电极的**串联**阻抗 | 🛑 只能判一对电极的"串联连通"，**判不出单根**（手册 §8.3.18 明写） |

> 结论：要"哪一根掉了"就必须用 DC 或模拟 AC。台架是 AECG100 + 湿电极，选 **DC**。

### 1.4 硬件滤波只有微秒级 —— 这是软件防抖存在的唯一理由

手册 §8.3.25：报警需连续 N 个 **409.6 kHz**（下降沿触发）周期才被接受，N 由 `ALARM_FILTER`(0x2E)
低 4 位编程，1~16。本工程 `0x2E = 0x33`（默认值）⇒ `AFILTER_LOD = 3`。

```
⚠ 两个都要算上（T235 §3.1 订正，2026-11-12）
手动册 Figure 73：AFILTER_LOD 的语义是「consecutive counts **+1**」⇒ 实际计数 = 3 + 1 = **4**

每个计数 = 1 / 409.6 kHz ≈ 2.44 µs
4 个计数 ≈ 9.8 µs
⚠ 若"数字时钟周期"按"下降沿翻转"理解为二分频（完整周期 4.88 µs）⇒ 4 × 4.88 ≈ 19.5 µs

⇒ 正确口径是区间：**约 9.8 ~ 19.5 µs**（拉满 16 计数也只有 ≈ 39 ~ 78 µs）
```

⇒ 对**人体运动伪迹、电极夹机械抖动**（毫秒~秒级）等于**完全没滤波**。
必须由 MCU 侧软件防抖补上（见 §2.4）。

### 1.5 锁存 + 读后清零 —— 决定了"必须自己锁存"

🛑 **2026-11-12 订正（T235 §2.1）**：本节旧版写"错误在读之前已消失 ⇒ 读回来是 0 ⇒ 事件永久丢失"，
**写反了**。手册 §8.3.27 三句连读才是真义：

```
All error bits in the registers 0x18 through 0x1E are latched in a high state
when an error occurs and will only return to zero after being read.
The error bits will remember an error until the user reads the error.
... Upon read, the error bits will be cleared. If the error condition has
disappeared before the error is read, the error bits will remain low *after* being read.
```

关键在 **"remain low **after** being read"**：读**之前**仍是 1（锁存记住了这次事件），
读**之后**才变 0，且因故障已消失而**不再自动重新置位**。

正确时序：

```
故障发生（哪怕只有一瞬）
   ↓
硬件锁存位 = 1
   ↓
即使故障早已消失，下一次读取**仍得到 1**
   ↓
读取后清零；若故障仍在，几个内部时钟周期后重新置 1
```

⇒ **芯片本身不会丢事件**，20 ms 低频读取**不会**漏掉两次读取之间的短事件。

那"为什么还要 20 ms 才读"？真实理由三条（与"防丢事件"无关）：

| # | 理由 | 量化 |
|---|---|---|
| 1 | **SPI 开销**：逐样本读 = 853 次寄存器事务/秒，与数据读取抢同一条 `hspi3` | 853 Hz × 每次 2 B 事务 |
| 2 | **旧实现是"读了不存"**：丢事件发生在**固件侧**，不在芯片侧 | 逐样本读把锁存消耗掉却只用于当个样本 ⇒ 上层拿不到"曾经发生" |
| 3 | **时间常数对齐**：20 ms 与 60 / 500 ms 防抖成整数关系 | 60 = 3×20、500 = 25×20 |

> 一句话：**芯片负责"记住"，固件负责"记录"**。低频读是为了省总线和让软件锁存有意义，
> 不是为了抢救会被芯片丢掉的事件。

两条仍然成立的推论：

1. 读到 0 **不能**证明"从未脱落"——只证明"上次读之后没新增"，且**必须配合防抖**才敢下结论。
2. 读得太勤仍然有害：锁存被高频消耗，`s_lod_latched` 拿到的是"两次读之间有没有新事件"，
   拼不出**持续时间**；而防抖需要的正是连续非零的**次数**。

### 2.1 寄存器配置（`ads1293.c:342~350`，`regs_leaderIII` 表内）

### 2.2 通道语义：FLEX 路由 → AECG 接线 → CH1 极性（**本节是"哪根线是哪个电极"的唯一口径**）

#### 2.2.1 手册给的位域（`FLEX_CH1_CN`，地址 `0x01`，Figure 33）

```
Addr 7 6 5 4 3 2 1 0
0x01  TST1   POS1   NEG1

[7:6] TST1  00 = 测试信号断开，CH1 由 POS1/NEG1 决定（默认）
[5:3] POS1  CH1 正端：000 断开 / 001 IN1 / 010 IN2 / 011 IN3 / 100 IN4 / 101 IN5 / 110 IN6
[2:0] NEG1  CH1 负端：编码同上
```

#### 2.2.2 `0x11` 的逐位解码

```
0x11 = 0b0001_0001
        ↑↑↑ ↑↑↑
        │   └── NEG1 = 001 ⇒ 负端 = IN1
        └────── POS1 = 010 ⇒ 正端 = IN2
TST1 = 00（测试信号断开）
```

⇒ **CH1 = IN2 − IN1**（`regs_leaderIII` 表 `{0x01, 0x11}`，`ads1293.c:337`）。
**这一条是寄存器位域直接算出来的，不是靠波形极性反推的。**

#### 2.2.3 与 AECG100 的接线对应（现场确认，T232 §12.2）

⚠ 关键：**导联线上印的标签 ≠ AECG100 端子名，两者是交叉的**。这是极性问题的源头。

| 芯片脚 | 导联线的电极标签 | 实际接 AECG100 端子 | 在 CH1 中的角色 |
|---|---|---|---|
| **IN1** | **RA** | **LA** | CH1 **负端** |
| **IN2** | **LA** | **RA** | CH1 **正端** |
| **IN3** | —（N 线） | **N2** | 不参与 CH1 差分，仅 LOD 监测 |
| **IN4** | —（N 线） | **N1** | 不参与 CH1 差分；**该脚被 RLD 放大器输出驱动**（`SELRLD=100`），是 LOD 的回流出口（§2.3） |

所以：

```
CH1 = IN2 − IN1
    = (接 AECG100 RA 端子的那根线) − (接 AECG100 LA 端子的那根线)
    = AECG_RA − AECG_LA
```

#### 2.2.4 极性：为什么 `AECG_RA − AECG_LA` 出来是**正立**的

不是"CH1 接反了"，而是**信号源的定义**决定的：

- AECG100 有「**输出电极选择**」设置，本台架历次采集**都在同一设置下**（选 RA 作为驱动/参考点）。
- 在该设置下，AECG100 输出的正峰在 **RA 端子**上表现为电位**高于** LA ⇒ `RA − LA > 0` ⇒ 屏上 QRS 正立。
- 反过来把 LA/RA 两根线**互换**接，`CH1` 就变成 `LA − RA` ⇒ 波形倒置。**实测正是如此**（T232 §12）。
- 因为"正立"与 MIT-BIH 及常规采集的观察习惯一致，**软件不做任何取反**。

> 一句话：**通道没错、极性没错，正立来自信号源把 RA 定义成参考点**。
> 换成真实人体（RA/LA 贴片）时，`CH1 = RA − LA` 就是**倒置的 I 导联**（I 导联标准是 LA − RA）；
> 这一点在**换到人体测量时必须重新确认是否需要取反**，别默认沿用台架结论。

#### 2.2.5 掩码为什么是 `0x07`

要监测的是"**接在电极上的那几根线**"：IN1（RA 线）、IN2（LA 线）、IN3（N2 线）。

🛑 **IN4 绝对不能使能**（`0x0F` 是错的），因为 **IN4 这个脚被 RLD 放大器的输出驱动**
（`SELRLD=100` 把 RLD 输出内部路由到 IN4，见 §2.3.4）。对一个**由放大器驱动的节点**做
"注入电流看能不能回流"的检测没有意义，而且注入的 8 nA 会叠加在 RLD 环路上。

它的异常不是没监测，而是**通过"回流断 ⇒ 全报"体现**（§2.3）。

### 2.3 回流路径：「拔 IN4 全报」的机制（**已闭环，2026-11-11 19:00 确认**）

#### 2.3.1 现象（实测，T232 §16.3）

> 拔掉 **IN4**（AECG N1）⇒ `lod=1`（三路全报），但 **QRS 打点继续**。

#### 2.3.2 手册的前提

`§8.3.16` 原文要点：LOD 电流必须有**低阻回流路径**（右腿电极到地，例如电压基准或 RLD 放大器输出）；
**没有回流时，所有使能的 LOD 脚全报脱落**。

⇒ 拔 IN4 导致"全报"，与手册这条前提**完全吻合**，是**预期行为，不是误报**。

#### 2.3.3 🛑 术语纠正（2026-11-11 18:49 猛哥指出）

**"IN4 是 RLD 输出点"这个说法是错的**，本文件旧版本与 `ads1293.c` 注释里都有，现更正：

| 事实 | 依据 |
|---|---|
| **IN4 是普通电极输入脚**（引脚表中 IN1~IN6 均为 Analog Input） | 引脚表 |
| **芯片的 RLD 输出是独立引脚 `RLDOUT`（pin 9）** | 引脚表 |
| `RLD_CN(0x0C)` 的 `SELRLD[2:0]` 是"把 RLD 输出**路由到**某个 IN 脚"的多路选择器（`100` = 连到 IN4） | Figure 44 |
| 本工程 `0x0c = 0x04` ⇒ `SELRLD = 100` | `ads1293.c:355` |

⇒ 准确表述：**"本工程按 `SELRLD=100` 把 RLD 输出（内部）路由到了 IN4 引脚"**，
不是"IN4 天生是 RLD 输出"。

#### 2.3.4 两条现场确认（2026-11-11 19:00，猛哥）

| # | 项 | 结论 |
|---|---|---|
| Q1 | `0x0C=0x04`（`SELRLD=100`，RLD→IN4）是否是期望行为？ | ✅ **是，这是设计要求，寄存器值不动** |
| Q2 | 板级 IN4 与 `RLDOUT`(pin 9) 是否连通？ | ✅ **不通**（断电实测确认） |

两条合起来，机制就唯一了：

```
        ADS1293 内部                         板级                     AECG100
  ┌──────────────────────┐
  │ RLD 放大器            │
  │   ↓ SELRLD=100 路由   │
  │ IN4 引脚 ─────────────┼──► IN4 测试点 ──► N1 端子 ──► 参考/回流节点
  └──────────────────────┘
        RLDOUT (pin 9)  ✗ 本设计不使用（板上接 CMOUT/RLDOUT 补偿网络，不参与回流）

  ⇒ LOD 在 IN1/IN2/IN3 注入的 8 nA，经体内/参考回到 N1，由 RLD 放大器吸收 ⇒ 回流成立
  ⇒ 拔掉 IN4 这一根 ⇒ 回流断开 ⇒ 三根使能脚全部顶到 VDD ⇒ 全报（手册 §8.3.16 原文行为）
```

**两个派生结论**：

1. **IN4 不能当电极输入用**（它被 RLD 输出驱动），因此 `EN_LOD` 掩码只能是 `0x07`，`0x0F` 错。
2. **LOD 的正确性依赖"IN4 ↔ AECG N1"这根线**：这根线掉了，LOD 会全报而不是"报某一路"——
   这是**设计上接受的**，因为此时 RLD 也失效，整条信号链本来就不成立。

#### 2.3.5 与机制无关、但必须记住的语义

| 现象 | 解释 |
|---|---|
| `lod` 置位 | LOD 电流失去回流 ⇒ **三根使能脚全部顶到 VDD** ⇒ 按手册就是全报 |
| QRS 仍能打点 | CH1 是**差分**信号，信号本身还在；回流只影响共模抑制，不管信号有没有 |

⇒ 若将来要做"抑制打点"，必须另判 `CH1 无效 = (IN1 off) || (IN2 off)`（T232 §15.2），
**不能直接用 `lod`**。

### 2.4 状态机：低频读 + 软件锁存 + 非对称防抖（`ads1293.c:450~517`）

三个变量、两个计数器：

| 变量 | 含义 | 用途 |
|---|---|---|
| `s_lod_raw` | 最近一次**原始**读值 | 只做诊断（`ads1293_lod_raw()`），**不参与判决** |
| `s_lod_latched` | 锁存值，`\|= raw & ECG_LOD_MASK` | 防止"读后清零"丢事件；只留已启用输入 |
| `s_lod_stable` | 防抖后对外输出 | 就是 STA bit4 的来源 |

📌 **`ECG_LOD_MASK`（`ads1293.h:178`，值 `0x07u`）是使能掩码的唯一真源**（T235 §3.2，2026-11-12 落码）：

| 用到它的地方 | 写法 |
|---|---|
| 寄存器表 `regs_leaderIII` | `{0x07, ECG_LOD_MASK}`（`ads1293.c:344`） |
| 软件锁存 | `s_lod_latched \|= (uint8_t)(raw & ECG_LOD_MASK)`（`ads1293.c:487`） |

以前两处各写一次 `0x07` 魔数，改掩码时必漏一处。🛑 改掩码时**必须同时确认 IN4（bit3）仍在掩码外**——
它被 RLD 输出驱动（`SELRLD=100`），把它算进"脱落"等于把 RLD 环路扰动报警（§2.2.5）。

| 参数 | 值 | 折算时间 |
|---|---|---|
| `LOD_POLL_MS` | 20 ms | 轮询周期（读 SPI 的节流） |
| `LOD_ASSERT_CNT` | 3 | ≥60 ms 连续非零 ⇒ 置位 |
| `LOD_CLEAR_CNT` | 25 | ≥500 ms 连续全零 ⇒ 清除（**M > N，非对称**） |

```
          读 0x18（每 20 ms）
                 │
      ┌──────────┴──────────┐
   raw != 0              raw == 0
      │                     │
latched |= raw        assert_cnt = 0
clear_cnt = 0         clear_cnt++（上限 25）
assert_cnt++（上限 3）
      │                     │
assert_cnt>=3 ?       clear_cnt>=25 ?
      │是                   │是
stable = latched      latched = 0
                      stable  = 0
```

三条设计要点：

1. **清除只由"持续无故障"驱动**，不由"单次读到 0"驱动 —— 否则一次 SPI 抖动就把脱落抹掉。
2. **SPI 读失败时保持现状**（`return`，不清不置）—— 把通信故障和"导联好了"分开。
3. **非对称**：置位快（60 ms）、清除慢（500 ms）。取向是"宁可晚点说好了，
   也别在脱落/正常之间来回跳"。

### 2.6 输出：STA 字节的 bit4 / bit5（`ads1293.c:1288~1331`）

```c
/* bit4 = 任意启用输入脱落（完整性提示，图标用） */
if ((s_lod_stable & ECG_LOD_MASK)      != 0u) { sta |= 0x10u; }

/* bit5 = CH1_INVALID（门控用；判据由 ECG_LOD_GATE_POLICY 决定） */
```

STA 完整位定义（协议 v2.2 §4，全部**运行期读取**，禁止用编译期宏）：

| 位 | 含义 | 数据源 |
|---|---|---|
| bit0 | mode：0=diag ／ 1=mon | `ecg_filter_f64_mode_is_mon()` |
| bit1 | notch：0=off ／ 1=on | `ecg_filter_f64_notch_is_on()` |
| bit2 | channel：0=I ／ 1=I&II | `ads1293_ch2_is_on()` |
| bit3 | raw853：0=off ／ 1=on | `ads1293_raw853_is_on()` |
| **bit4** | **LOD 任意脱落**：0=正常 ／ 1=有输入脱落 | `(s_lod_stable & ECG_LOD_MASK) != 0` |
| **bit5** | **CH1_INVALID**：0=CH1 可用 ／ 1=CH1 不可用（**门控用**） | `(s_lod_stable & ECG_LOD_GATE_CRIT) != 0` |
| bit6~7 | 保留 0 | — |

⚠ 历史注释曾写"bit4 本步恒 0：ECG_LOD_EN=0 ⇒ LOD 未使能"——**已随本项一并更正**（现在恒有效）。

#### 2.6.1 为什么拆成两个位（2026-11-12，任务 3）

一个 bit 无法同时满足两件事：**提示**要"宁可多报"，**门控**要"准确"。

| 场景 | bit4 | bit5 | 屏上 | 测量 |
|---|---|---|---|---|
| 全部接好 | 0 | 0 | 亮灰 | 正常 |
| 拔 **IN3**（CH1 仍有效） | **1** | **0** | **红叉** | **照常打点/出 BPM** |
| 拔 **IN1 或 IN2** | 1 | **1** | 红叉 | 停测（门控） |
| 拔 IN4 / 回流断 | 1 | **1**（三路全报，连坐 IN1/IN2） | 红叉 | 停测（§2.6.2 订正） |

⇒ 这正是 T235 §2.3 提的两个状态：`bit4=1` ⇒ **LEAD_ALERT**，`bit5=1` ⇒ **MEASUREMENT_INVALID**。

#### 2.6.2 策略宏（`ads1293.h`）

```c
#define ECG_LOD_CH1_MASK      0x03u   /* bit0=IN1、bit1=IN2 */
#define ECG_LOD_GATE_POLICY   0       /* 0 = 仅 CH1 无效（默认）／1 = 任意 LOD */

#if (ECG_LOD_GATE_POLICY == 0)
#define ECG_LOD_GATE_CRIT     ECG_LOD_CH1_MASK   /* 只看 IN1|IN2 */
#else
#define ECG_LOD_GATE_CRIT     ECG_LOD_MASK       /* 含 IN3、含回流断 */
#endif
```

| 策略 | `bit5` 判据 | 拔 **IN3** | 拔 IN1 或 IN2 | 拔 **IN4**（回流断） |
|---|---|---|---|---|
| **0（默认，当前）** | `IN1 \| IN2` 任一置位 | `0x04 & 0x03 = 0` ⇒ **不停测** | `0x01/0x02` ⇒ **停测** | `0x07 & 0x03 = 0x03` ⇒ **停测** |
| 1 | 任意启用输入置位 | ⇒ 停测（保守） | ⇒ 停测 | ⇒ 停测 |

🛑 **2026-11-12 订正（我原先写错，被回归测试的用例设计查出来）**：
旧表把「拔 IN4／回流断」写成「策略 0 时**不**置位 / 不停测」，**是错的**。
原因：回流断时按手册 §8.3.16 **三路全报**（`s_lod_stable = 0x07`），
而 `0x07 & ECG_LOD_CH1_MASK(0x03) = 0x03 ≠ 0` ⇒ **bit5 照样置位**。

⇒ 准确说法：**策略 0 与策略 1 的唯一差别，就是「仅 IN3 脱落时是否停测」**。
所有会导致 IN1 或 IN2 置位的情形（含回流断的连坐）都会停测。
从产品安全角度看这是好事（RLD 失效时共模抑制已崩，信号本就不可信），
但**台架上会表现为"拔 AECG N1 就停测"**，与 T232 §16.3 观察到的"拔 IN4 时 QRS 仍在跑"不同 ——
**注意区分：那是"信号还在"，这是"我们选择不信它"。**

🛑 **改策略只需重编 STM32**，ESP32 与上位机不用动（它们只认 bit5 的值）。
🛑 **CH2 说明**：`ch2=on` 时 CH2 是 CH1 的**逐点复制**（`ads1293.c` 帧封包段）⇒ CH1 失效即两路失效，
所以策略 0 在当前实现下等价于"任意通道无效"，是安全的默认值；**等 CH2 独立采集后才需要重新评估**。

### 2.7 附：RLD 环路原理 —— LOD 的"回流"到底从哪来（2026-11-11 19:01 校订）

> 缘起：猛哥口述了一版 RLD 原理并问是否合理。本节是**逐句核过手册 §8.3.12 原文后的定稿**。
> 与 LOD 的关系：LOD 注入的 8 nA 必须有一条低阻回流路径，**这条路径的末端就是 RLD 的输出节点**。

#### 2.7.1 环路四步（手册 §8.3.12 原文口径）

```
① 采样   共模检测器把选定输入脚电压取平均 → CMOUT
         （CM_DET_EN 0x0A 每脚一位，MSB=IN6；本机 0x0A=0x07 ⇒ IN1+IN2+IN3 参与）
   ↓
② 比较   RLD 运放把 CMOUT 与 RLDREF 引脚上的参考电压比较
         原文：The CMOUT is compared by the RLD to the reference voltage present on the RLDREF pin
   ↓
③ 反相放大  「When used in an inverting amplifier topology…」——⚠ 反相是**外部拓扑**决定的：
         运放**负输入恒接 RLDINV 引脚**，把 CMOUT 接到 RLDINV 就是反相放大器
   ↓
④ 驱动回人体  输出把右腿电极驱动到"抵消参考电压与实测共模之差"的方向 → 负反馈 → 共模被拉回参考电平
   ↓
   输出**同时**出现在两个地方（原文 "always connected to the RLDOUT pin, and **in addition**,
   can be connected to one of the IN1-IN6 terminals by programming the SELRLD bit"）：
        · RLDOUT (pin 9)                    —— 恒有
        · SELRLD 选中的 INx（本机 = IN4）   —— 额外并接
```

#### 2.7.2 🛑 由此解开的一个疑问：「IN4 与 RLDOUT 引脚不通」是正常的

原文的 **"and in addition"** 说明：RLD 输出的**同一个内部节点同时驱动** `RLDOUT` 与 `SELRLD` 选中的 `INx`。

⇒ 断电测到 **IN4 ↔ RLDOUT(pin 9) 不通**（2026-11-11 19:00 实测）与 **"RLD 输出出现在 IN4 上"** 并不矛盾：
它们是**芯片内部并联的两条出口**，PCB 上不相连。
（且本设计把 RLDOUT 引脚接到了 `CMOUT/RLDOUT` 网络 + R6 10k / R7 10M / C 1nF 到 AGND，实际回流不走它。）

#### 2.7.3 本机的实际环路配置（与"典型应用"的差异）

| 项 | 典型应用 | **本机实测配置** | 出处 |
|---|---|---|---|
| 共模输入 | IN1=RA / IN2=LA / IN3=LL | `0x0A=0x07` ⇒ IN1+IN2+IN3（**但台架这三根的解剖含义不同**，见 §2.2.3） | `ads1293.c:352` |
| RLD 负输入 | `RLDINV` | `RLDINV`（恒接，无法改） | 手册 |
| RLD 正输入 | `RLDIN` 引脚 | 🛑 **内部 RLDREF** —— 因为 `0x17`(`AFE_PACE_CN`) `= 0x05` ⇒ **`PACE2RLDIN=1`**，手册注："the RLD amplifier is disconnected from the RLDIN pin and connected internally to the RLDREF pin" | `ads1293.c:366` |
| RLD 输出 | `RLDOUT` → 右腿电极 | `RLDOUT` 接补偿网络（不用）+ **`SELRLD=100` 并接到 IN4** | `ads1293.c:355` |
| 右腿电极 | RL | 台架上是 **AECG100 N1**（不是人体 RL） | §2.2.3 |
| 起搏通道 | 可选 | `SHDN_PACE=1`（关断），但 `PACE2RLDIN=1` 仍生效 | `0x17=0x05` |

⚠ **待确认（新增）**：`0x17=0x05` 的 `PACE2RLDIN=1` 是**有意**（把正输入改到内部参考、让 `RLDIN` 引脚避开外部噪声）
还是**沿用旧配置**？两种都工作，但若要接真实人体并需要 `RLDIN` 引脚做外部参考时会有影响。

#### 2.7.4 与 LOD 的接口点

回流链路的末端就是这个 RLD 输出节点：

```
LOD 注入 8 nA（IN1/IN2/IN3）
   → 经电极/参考回到 AECG N1
   → N1 即 IN4 引脚
   → IN4 被 RLD 输出（SELRLD=100）驱动 ⇒ 电流被 RLD 放大器吸收
   ⇒ 回流成立 ⇒ 比较器保持"未脱落"
```

⇒ 拔掉 IN4 这一根 = **把回流末端摘掉** ⇒ 三根使能脚全部顶到 VDD ⇒ 全报（§2.3，手册 §8.3.16 原文行为）。

#### 2.7.5 两个可直接用于诊断、但本工程未接的报警位

| 位 | 含义 | 为什么不接 |
|---|---|---|
| `ERROR_STATUS(0x19).bit1` `RLDRAIL` | RLD 输出接近电源轨（<0.2 V 或 >VDD−0.2 V）⇒ 环路维持不住 | 当前只读 `0x18`；若将来要判"RLD 环路失效"应加读 `0x19` |
| `ERROR_STATUS(0x19).bit0` `CMOR` | 共模电平超出可测范围 | 同上 |

🛑 **要用 `0x19` 必须先知道：它是"事件位"，不是"状态位"**（T235 §3.6，2026-11-12 补）

手册 §8.3.27 原文：

```
For all error registers, except ERROR_STATUS, the error bits will return to
their high state within a few internal clock cycles if the error condition is
still present after a register read.
The bits in the ERROR_STATUS register only respond to new errors. If an error
persists after the ERROR_STATUS register is read, the error condition will not
be reflected in the error status register and the ALARMB pin will not pulse low again.
```

| 寄存器 | 读后若故障仍在 | 语义 | 能不能当"当前状态"轮询 |
|---|---|---|---|
| `0x18` `ERROR_LOD` 等 | **重新置 1** | 锁存 + 自恢复 | ✅ 可以（本工程就是这样用的） |
| `0x19` `ERROR_STATUS` | **仍为 0**，直到出现**新**错误 | 纯事件通知 | 🛑 **不能** —— 20 ms 轮询会漏掉持续故障 |

⇒ 若将来接 `RLDRAIL`/`CMOR`，必须**软件保持**（读到一次 1 就自己锁存，像 `s_lod_latched` 那样），
或者改用 `ALARMB` 引脚中断捕获"新事件"，**不能直接把轮询结果当持续状态**。

### 3.1 物理链路

### 3.2 显示帧格式（`TYPE=0x01`，`ads1293.c:1596~1648`）

```
AA 55 | TYPE | LEN(2B LE) | SEQ(2B) | STA(1B) | 样本(2B × N × nch) | CRC8
 ↑帧头2B  ↑1B    ↑2B         ↑2B       ↑1B                            ↑1B
```

| 字段 | 说明 |
|---|---|
| `TYPE` | `0x01` = 显示帧（`0x03` = 快照帧，**不含 STA**） |
| `LEN` | **PAYLOAD 字节数** = `3 + 2·nch·N` = `SEQ(2) + STA(1) + 样本` |
| `N` | 每帧每通道样本数 = `_popoutcnt` = **25**（500 Hz × 50 ms 帧周期） |
| 帧总长 | `6 + LEN` |

| 档 | nch | LEN | LEN 奇偶 | 帧总长 |
|---|---|---|---|---|
| 单通道（`ch=I`） | 1 | `3 + 50 = 53 = 0x35` | **奇** | **59 B** |
| 双通道（`ch=I&II`） | 2 | `3 + 100 = 103 = 0x67` | **奇** | **109 B** |

🛑 **两档 LEN 都是奇数**，所以 STA 一直存在。判双通道**只看帧长 109 B**，画布切了不算。

### 3.3 CRC8

| 项 | 值 |
|---|---|
| 多项式 | `0x07` |
| 初值 | `0x00` |
| 反射 | 否 |
| 覆盖范围 | 从 `TYPE` 起、到样本末字节止 = `6 + 2·nch·N` 字节（**不含** `AA 55` 前导，**不含** CRC 自己） |
| 实现 | `stm32/Filter/ecg_crc8.c`（查表版，`ECG_CRC8_USE_TABLE=1`） |

⚠ 加/减 STA 时**四处长度耦合必须同步**（当年漏一处 CRC 就错）：
① `LEN` ② CRC 覆盖长度 ③ 发送总长 ④ CH2 段偏移 `8 + 2N`。

### 3.4 下行命令里**没有** LOD

`485-send` 的支持集是 `start | stop | snap | mode 0|1 | notch 0|1 | ch2 0|1`，
**没有 LOD 开关**。原因：LOD 是**编译期宏 `ECG_LOD_EN`**，不提供运行期开关。
⇒ 验收时不能"发命令开 LOD"，只能确认固件是 `ECG_LOD_EN=1` 这一版。

### 3.5 快照帧不带 STA

`TYPE=0x03` 的快照帧只被计数、被 `continue` 跳过，**不更新 STA**
（`ecg_pipeline.c:723`）。所以快照期间屏上状态是上一次显示帧留下的值。

## 4 ESP32 端实现

### 4.1 解帧：`has_sta` 由 LEN 奇偶决定（`ecg_frame.c:99~140`）

```c
const bool     odd     = (len & 1u) != 0;
const uint16_t hdr_len = odd ? 3u : 2u;   /* SEQ(2)+STA(1) 或 SEQ(2) */
fr->has_sta = odd;
fr->sta     = odd ? payload[2] : ECG_STATE_UNKNOWN;   /* 0xFF */
```

约定来源：协议 v1.1 的旧帧**没有 STA**（LEN 偶），v1.1+ 加了 STA ⇒ LEN 变奇。
本工程两档显示帧 LEN 都是奇（53 / 103）⇒ 恒带 STA。

### 4.2 上抛：只在显示帧上更新（`ecg_pipeline.c:723~742`）

```c
if (fr.type == ECG_TYPE_SNAPSHOT) { s_snapshots++; continue; }   /* 快照：不算 */
if (fr.type != ECG_TYPE_DISPLAY)  { continue; }                  /* 未知类型：丢弃 */
s_frames++;
app_state_set_sta(fr.sta, fr.has_sta);                           /* ★STA 唯一写入口 */
```

`app_state_set_sta()`（`app_state.c:107~117`）同时记**时间戳** `sta_ms`（T213）：

```c
s_st.sta     = has_sta ? sta : 0xFF;
s_st.has_sta = has_sta;
s_st.sta_ms  = esp_timer_get_time() / 1000;      /* 帧龄，供 CLI 判陈旧 */
```

🛑 **`has_sta == false` 时 `sta` 被写成 `0xFF`** —— 而 `0xFF & 0x10 != 0`。
⇒ **任何读 bit4 的地方必须先判 `has_sta`，否则会把"未知"读成"脱落"**。
（`ui_bpm.c:210` 的 `const bool lod = valid && ((st->sta & 0x10u) != 0u);` 就是这道门。）

### 4.3 屏上图标（`ui_bpm.c:124~219`，T232-C2）

三态映射：

| `has_sta` | `sta & 0x10` | 图标 | 颜色 |
|---|---|---|---|
| `false` | —（值无意义） | 导联线，**无叉** | 暗灰 `0x5A5F63` |
| `true` | 0 | 导联线，无叉 | 亮灰 `0xC8CDD2` |
| `true` | 1 | 导联线 **+ 红叉** | 红 `0xFF5252` |

实现要点：

- 图元绘制（`lv_line` + `lv_obj`），不用 `LV_SYMBOL_*`（全工程零引用）、不用图片（34×34 不值当）
- 位置：BPM 盒（160×50）最左侧，x=6..40；数字右对齐 `-58`、单位 `-14`
- 刷新：`on_bpm_tick` **每 200 ms**（`APP_BPM_UPDATE_MS`）；`ico_sync()` 排在**冻结判断之前**
  —— 冻结只停画面，脱落仍是事实
- 开销：状态不变时首次比较即 `return`，零样式写入
- 叉的尺寸：`{9,10}→{23,24}`（14×14，线宽 2），中点在导联线包围盒中心 `(16,17)`

日志判据：**只在状态变化时**打 `I (t) ui_bpm: lead icon -> unknown|ok|LEAD-OFF`
⇒ **日志行数 = 切换次数**。⚠ 因此"没有日志"通常等于"状态没变"，不等于"功能坏了"。

### 4.4 CLI 回读（`cli_console.c:1856~1890`，`485-stat`）

```
STATUS    : diag notch=on ch=I raw853=0 lod=0  (raw=0x02, 距更新 0.0 s；停流时不刷新)
```

- `raw=0xNN` = **原始 STA 字节**，比图标信息量大（能看出是哪一位在动）
- `距更新 X s` = 帧龄 ⇒ **≥2 s 标 ★陈旧**（500 Hz 下每帧 25 样本＝50 ms，2 s 已漏 40 帧）
- `lod=N` = bit4

🛑 `STATUS: unknown(no STA)` **不等于故障**：只在"没收到显示帧"时出现（停流 / 只收快照帧）。
但要注意 §5.3 的**陈旧**问题。

### 4.5 C-3 联动：**判据已就绪（STM32 侧），动作未接（ESP32 侧）**

2026-11-12 任务 3 之后，判据问题已解决：STM32 在 **STA bit5** 上输出 `CH1_INVALID`，
ESP32 只需要按这个位做动作，**不需要再判"哪根掉了"**（它本来就拿不到逐输入信息）。

| 行为 | 现状 |
|---|---|
| 判据：CH1 是否可用 | ✅ **已实现**（STM32，`bit5`，策略宏 `ECG_LOD_GATE_POLICY`，§2.6.2） |
| LOD/CH1 无效 ⇒ 抑制 R 峰打点 | ⬜ **未实现**（ESP32） |
| ⇒ BPM 立即显示 `--` | ⬜ 未实现（现在只有 4 s 超时失效 T-15） |
| ⇒ HRV / 统计停更 | ⬜ 未实现 |

ESP32 侧落地时的三条注意（**别踩**）：

1. 🛑 **门控要做在"样本喂入侧"**，不能只调 `ecg_pipeline_rpeak_reset()` —— 单纯 reset 挡不住下一拍噪声重新触发。
2. 复用 T-15 的 BPM 失效路径（把"4 s 无新峰"的触发条件扩成"4 s 无新峰 **或** bit5=1"），避免出现第二套失效逻辑。
3. `bit4` 仍要驱动图标（拔 IN3 出红叉），**门控只看 bit5** —— 两件事不要混在一个判断里。

## 5 端到端时序：一次"拔掉 IN1"的账单

```
t=0      人手拔下 IN1
         │
         ├─ 0 ~ 7 µs    ADS1293：比较器翻转 + AFILTER_LOD 3 计数确认
         │
         ├─ ? ~ 0.4 s   物理充电：8 nA 把输入节点从 0.65 V 顶到 VDD−0.5 V
         │              （见下方"为什么不是 60 ms"）
         │
         ├─ ≤20 ms      STM32 下一次 ads1293_lod_poll 读到 raw≠0
         ├─ +60 ms      assert_cnt 满 3 次 ⇒ s_lod_stable 置位
         ├─ ≤50 ms      下一帧显示帧带上 STA.bit4=1（帧周期 50 ms）
         ├─ ≤200 ms     ESP32 ico_sync 在下一个 BPM tick 上画红叉
         │
         └─ 实测合计：**0.4 ~ 1.6 s**（台架 2026-11-11 18:30 实测）

恢复方向（插回）：
         物理放电 + clear_cnt 满 25 次（≥500 ms）+ 帧周期 + tick
         └─ 实测合计：**0.6 ~ 1.8 s**
```

### 5.1 为什么实测比"理论 80 ms"慢 1~2 个数量级

> ⚠ **本节是假说，尚未直接验证**（T235 §3.7，2026-11-12 标注）。
> 下面这套"净充电电流模型"**能解释**观测到的非对称，但**没有实测证据**证明它是唯一原因。
> 判别实验见 §5.2。

纯数字路径的理论上限是 `≈10 µs + 20 ms + 60 ms + 50 ms + 200 ms ≈ 330 ms`，
其中**软件可解释的部分只有 ~80 ms**（20 ms 轮询 + 60 ms 置位防抖），
剩下 250 ms 以上必须在物理层解释。

假说：**8 nA 与输入节点的漏电流是同一量级**。
节点要抬升 ΔV ≈ 2.15 V（0.65 V → 2.8 V），
若净充电电流只剩几百 pA ~ 几 nA，`t = C·ΔV / I_net` 就会落在**几百 ms ~ 秒**量级。
这能解释实测的两个非对称：

- 拔 IN1 ≈ 0.4 s / 拔 IN2 ≈ 1.6 s —— 两根线的节点电容与漏电不同
- 恢复比脱落慢 —— 放电要靠漏电慢慢泄，同样没有快速通路

⇒ 若假说成立，"要更快只能加大注入电流"（`0x08` 升档，每档 8 nA，最大 2.040 µA）。

### 5.2 判别实验：电流档扫描（**待做，15 分钟**）

| 档位 | `0x08` | 注入电流 | 每档测 5 次置位延迟 | 判读 |
|---|---|---|---|---|
| 现档 | `0x01` | 8 nA | 记录均值/离散 | 基线 |
| 中档 | `0x08` | 64 nA | 同上 | 若 ≈1/8 ⇒ 充电模型成立 |
| 高档 | `0x10` | 128 nA | 同上 | 若 ≈1/16 ⇒ 进一步确认 |

| 结果 | 结论 |
|---|---|
| 延迟近似按 **∝ 1/I** 缩短 | ✅ 充电模型成立；同时决定"要不要升档换速度" |
| 延迟**基本不变** | ❌ 瓶颈不在充电：转向比较器阈值 / `ALARM_FILTER` / 电极极化 / 回路阻抗 |

⚠ 注意：升档会**同时**放大患者注入电流（3 路合计 8 nA→24 nA→48 nA→192 nA→384 nA），
需与 §7.4 的电气安全口径一起看，不是纯性能取舍。

**当前决定：本轮维持 `0x01`（8 nA）** —— 实测已满足 ≤2 s 判据，先不升档；
等做过 §5.2 再谈是否需要更快。

## 6 验收方法与判据

### 6.1 判据表

| # | 判据 | 通过条件 | 手段 |
|---|---|---|---|
| 1 | 四根各自可检出 | 拔 IN1/IN2/IN3 **直接**触发；拔 IN4 **经回流断间接**触发（三路全报） | 拔/插 + `485-stat` |
| 2 | **掉线与通道影响可区分**（⚠ 不是"分路上报"） | 拔 IN3 ⇒ `lod=1` 但 QRS 继续；拔 IN1/IN2 ⇒ 两者都停 | 观察 `peaks` |
| 3 | 置位延迟 | ≤2 s | 时刻表 + 轮询 |
| 4 | 恢复延迟 | ≤2 s | 同上 |
| 5 | 不误报 | 静置空载 `peaks=0`、`lod=0` | 30 min 长稳 |
| 6 | 噪声代价 | RMS 抬升 ≤2×、无饱和 | `stat on` 对比 LOD-OFF/ON |
| 7 | 屏上指示 | 脱落出红叉、恢复撤叉 | 目视 + `lead icon` 日志 |
| 8 | 回流依赖 | 拔 IN4 ⇒ `lod=1`（**预期行为**） | 拔/插 |

🛑 **判据 2 的界限（T235 §2.4 订正，2026-11-12）**：它验证的是"**掉哪根 ⇒ 对 CH1 有什么影响**"，
**不代表协议已经分路上报**。现状必须分开写清：

| 层 | 有没有逐输入信息 |
|---|---|
| ADS1293 `ERROR_LOD(0x18)` | ✅ 有，`OUT_LOD[5:0]` 逐脚 |
| STM32 内部（`s_lod_stable` / `ads1293_lod_raw()`） | ✅ 有，8 位掩码保留 |
| **二进制帧协议** | ❌ **只有 STA bit4 汇总位** |
| ESP32 / 上位机 | ❌ 只能知道"有脱落"，不知道"哪一根" |
| 分路显示 | ❌ 未实现，需扩协议 |

### 6.2 🛑 采集口径的四个坑（都实发过）

1. **必须在 `485-start` 之前开始累积串口缓冲** —— 否则「`unknown → ok/LEAD-OFF`」这次
   起流后的首切换落在窗口外，会误判成"图标不工作"。
2. **必须校验帧新鲜度** —— 只看 `raw=0x02` 而不看 `距更新 X s`，可能把**陈旧值**当成实时值。
   判据：`距更新 ≤0.5 s` 才算有效采样。
3. **`unknown(no STA)` 不是故障** —— 没起流 / 只收快照帧都会这样（§4.4）。
4. **测"信号消失"要关信号源输出，不要拔线** —— 拔线同时改变了 LOD 回路，
   一次改动引入两个变量，数据不可用（T-2 首次测法因此作废）。

### 6.3 轮询 raw STA 的参考实现

`485-stat` 每 ~0.3 s 一次，正则取 `raw=(0x..)` 与 `距更新 ([0-9.]+) s`，
把连续相同的 raw 压成"段"，**切换次数 = 段数 − 1**。这是判定"抖/不抖"最直接的办法。

## 7 已知边界与未覆盖

### 7.1 🛑 停流后图标不会回到"未知"（**已拍板：不改，维持现状**）

`has_sta` **只在显示帧到达时被写**，没有任何路径把它复位为 `false`。
⇒ `485-stop` 停流后，屏上图标**保持最后一帧的状态**（红色或亮灰都保持），
不会自动变成"未知（暗灰）"。

当前可用的间接判据是 `sta_ms`（`485-stat` 的 `距更新`），但它只服务于 CLI。

| 取向 | 决定 |
|---|---|
| **A 维持现状（保持最后状态）** ✅ | **猛哥 2026-11-11 18:47 拍板：不改** |
| B `ico_sync()` 里按 `sta_ms > 2 s` 降级为"未知（暗灰）" | 不采用 |

🛑 注意这不是"没发现问题"，而是**明知有这个行为、选择保留**。
若将来临床反馈"停流后还挂着红叉会被误读"，再启用 B（改动只在 `ui_bpm.c` 的 `ico_sync()` 一处，
不涉及 STM32 与协议）。

### 7.2 停流/快照期间状态为陈旧值

同上原因：快照帧不更新 STA（§3.5），快照期间的状态是上一次显示帧的值。

### 7.3 「显示侧要不要防抖」—— 已拍板 A（不改）

真阳性也会让红叉闪一下（实测最短 0.5 s：仅"捏住电极夹轻晃"就能让 DC 通路瞬断）。

| 取向 | 决定 |
|---|---|
| **A 保持现状（立即显示）** ✅ | **猛哥 2026-11-11 18:38 拍板**：医疗设备优先"如实反映"，不压真实事件 |
| B 显示侧 ≥1 s 防抖 | 不采用（真脱落提示会晚 1 s） |

### 7.4 DC LOD 的物理局限

| 局限 | 说明 |
|---|---|
| 干电极/电容耦合电极 | DC 电流被隔断 ⇒ **DC LOD 失效**，必须换模拟 AC 模式（本项目未实现） |
| 半脱（接触电阻变大但未断） | DC LOD 是**阈值型**（VDD−0.5 V），只判"断/不断"，判不出"劣化到多少 kΩ" |
| 8 nA 下的湿电极 | 漏电流与注入电流同量级 ⇒ 响应时间不稳定（0.4~1.6 s 的离散即来源于此） |
| **回流单点依赖** | 回流唯一通道是 **IN4 → AECG N1**（RLD 输出经 `SELRLD=100` 注入该脚，`RLDOUT` 不用）。这根线一断，**LOD 全报**而不是报某一路 —— 设计上接受，因为此时 RLD 也失效、信号链本就不成立 |

### 7.5 未覆盖的测试

| 项 | 状态 |
|---|---|
| LOD-ON 下空载 30 min 长稳（判据 5） | ⬜ 噪声底已变，需重跑（T232 §16.6 第 3 项） |

### 7.6 ✅ 已关闭的评审项（T235 §2.2 SPI 健康判据）

**结论：不加健康判据、不扩 STA bit5、不加配置寄存器回读自检。** 理由分两类，归属清楚：

| 失败类 | 现象 | 发生可能 | 归属 |
|---|---|---|---|
| **A 传输层失败** | HAL 返回 timeout/busy | 🛑 **架构上几乎不可构造**：LOD 轮询与样本读取在**同一个 `while(1)` 串行执行**（`demo.c:139` / `:145`），共用 `hspi3` ⇒ SPI 坏则数据也读不到 ⇒ 没有帧 ⇒ ESP32 看到的是"帧流断"而不是"LOD 陈旧" | 不需要处理 |
| **B 传输成功但值错**（如欠压读回全 `0x00`） | HAL 返回 `HAL_OK` 但数据错 | 台架上**真实发生过**（11-11 欠压 3/6 失败、满电 8/8；回显 `got=0x00` 而非哨兵 `0xFD/0xFE`） | **由产品层兜底**：真实产品有**电池电量检测 + 上电自检**，欠压不会到达系统层（猛哥 2026-11-12 09:26 拍板） |

⚠ **这个"关闭"是有前提的，必须写下来**：它把 B 类故障的防线**转嫁给系统层**。
若将来产品**没有**实现电池电量检测或上电自检，本条自动失效，LOD 层会重新暴露"读回全 0 ⇒ 报正常"的假阴性。
⇒ 登记为**跨模块前置条件**，不在本项范围内实现，但**不能忘**。

🛑 顺带一个只影响台架的注意事项（不是产品需求）：台架环境**没有** BMS/自检，
若测试中再遇欠压，现象是"LOD 报正常 + 波形是一条零线"。排查口诀：

```
波形全 0 且 lod=0  ⇒ 先查 ADS1293 供电，别先怀疑 LOD 或算法
（判据：`485-stat` 的 crc_err=0、frames 正常增长，但样本恒 0）
```

## 8 一页速查

```
原理   ：注入 8 nA 直流 → 看能否回流 → 不能回流则节点顶到 VDD−0.5V → 比较器翻转
配置   ：0x06=0x00(DC,使能) 0x07=0x07(IN1/2/3) 0x08=0x01(8nA) 0x2E=0x33(默认)
         0x0C=0x04(SELRLD=100：RLD 输出内部路由到 IN4 → AECG N1，LOD 回流靠它；RLDOUT/pin9 不用)
硬件滤波：4 计数（3+1）×2.44 µs ≈ 9.8 µs（若二分频 ≈19.5 µs）⇒ 软件防抖必需
防抖   ：20 ms 轮询 / 3 次(60 ms)置位 / 25 次(500 ms)清除 / 读失败保持现状
锁存   ：0x18 = 事件锁存，**读过才清**，故障仍在则读后重置 ⇒ 芯片不丢事件；
         固件 s_lod_latched |= raw 是为了拿"持续时间"，不是为了防丢
出口   ：STA bit4 = 任意启用输入脱落（图标用）／bit5 = CH1_INVALID（门控用）
         策略宏 ECG_LOD_GATE_POLICY：0=仅 IN1|IN2（默认）／1=任意 LOD
         ⚠ 协议 v2.2 §4 现写"bit5~7 保留"，bit5 已启用 ⇒ 协议文档待补、上位机待查
帧     ：AA 55 | TYPE=01 | LEN | SEQ | STA | 样本 | CRC8     LEN=53(59B) / 103(109B)
CRC8   ：poly 0x07 / init 0x00 / 不反射 / 覆盖 TYPE..样本末
ESP32  ：LEN 奇 ⇒ has_sta；has_sta=false 时 sta=0xFF(bit4=1！) ⇒ 读 bit4 前必判 has_sta
显示   ：BPM 左侧 200 ms 刷新，亮灰=正常 / 红+叉=脱落 / 暗灰=未知
实测   ：置位 0.4~1.6 s，恢复 0.6~1.8 s（8 nA）
边界   ：①停流后图标保持最后状态；②AFE 失联（欠压）会读回全 0 ⇒ 假"正常"，
         由产品层 BMS/上电自检兜底（§7.6）
```
