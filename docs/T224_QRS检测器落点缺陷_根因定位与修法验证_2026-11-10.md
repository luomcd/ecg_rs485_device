# T224 QRS 检测器落点缺陷：离线重放定位根因与修法验证

> **日期**：2026-11-10　**状态**：证据完成，修法已验证，**待批准进入固件实现（P3）**
> **上游**：T221（缺陷发现，v0.3）、T222（技术讨论稿，v0.2）、T223（第三方评审）
> **本文的定位**：T223 判定「T222 的即修方案不能直接落码」。本文用 **Path B（PC 端逐位重放）**
> 在不改固件的前提下定位真因、验证修法、补齐全心率回归，给出**可直接落码的最小改动**。
> **重要订正**：T222 v0.2 把 60 bpm 判为 FAIL（6 轮 3 异常）。本文 §6 把这 6 个异常间期逐个拆开后，
> 结论修正为「**两个独立缺陷**」，而不是「60 bpm 这一个心率坏了」。

## 0 摘要

1. **真因已定位到代码级**：`locate_rpeak()` 的搜索窗是 `[trigger ± 40]`，而滤波历史
   `ECG_RP_FILT_HIST = 140`。**回溯（backtrack）路径**触发时 `trigger` 落后当前样本过多的距离，
   窗口滑出历史 ⇒ 精修失效。失效有**两种形态**，此前只发现了第一种。
2. **修法已验证**：在**候选入池那一刻**就把精修落点 `fid` 算好存进候选池，回溯直接取用
   （即 T223 Q2 的「trigger / fiducial 双坐标」）。**与心率无关、主路径行为一字不改**；
   RAM 代价已实测：并列 `int16_t` 数组 **+128 B**（算上诊断字段 +192 B），
   不是「零内存增长」（T225 §4.1 订正）。
3. **回归已跑完**：9 个心率 / **11 份采集**（2 mV、各 180 s、零坏帧零丢帧）。
   **90 / 120 bpm 由 FAIL → PASS（σ 2.59 / 5.40 → 0.35 / 0.23）**，
   其余 **7 个心率 σ(e) 一位数没变**。全心率峰数与理论拍数差 ≤3 拍，无系统性漏检。
4. **仍未解决**（本文不掩盖）：60 bpm 那 2 个非 R 形态事件（**尚未定性**，见 §6.2——
   已排除「缺幅度/极性门」这个说法，倾向输入瞬变/跳样本）；以及一份历史记录里疑似
   输入流不连续、无原始数据可复核。

## 1 方法与可复算性

### 1.1 为什么走 Path B（PC 端重放）而不是改固件试

T223 的核心批评是「诊断证据不足以支撑修法」。改固件试验有两个硬伤：
① 每改一次要烧录、且无法观察内部状态（`trigger` / `loc` / 窗口覆盖量都是局部变量）；
② 无法在同一份信号上做 A/B（换算法必然重采，信号漂移混进结论）。

因此把 `ecg_rpeak.c` **逐位搬到 PC**（`replay_rpeak.py`），喂 485 直抓的连续样本流，
输出每个峰的完整决策过程。**一致性校验**：同一份 90 bpm 数据，重放算出的 RR 序列
（333/334/342/324/325）与固件记录完全一致，配对结构（185 对）也一致。

### 1.2 数据链

```
ADS1293 → STM32L476 → UART5 → RS-232 → UT-2211（+5V 供电）→ RS-485 → CH340 → PC(COM27)
```

- **PC 直抓，不经 ESP32**：排除 ESP32 侧丢帧/缓冲对结论的干扰。
- 帧格式 `AA 55 | TYPE | LEN(2) | SEQ(2) | STA | 25×int16 | CRC8`，59 B/帧。
- 每份采集：180 s、约 3610 帧、90250 样本（≈501.4 Hz）、**坏帧 0 / 丢帧 0 / 段内尖刺 0**。
- 每份采集前重发 `0x01`（START），使滤波器/阈值从同一冷启动条件收敛；
  统计时剔除前 10 拍（`--skip 10`）以排除开机瞬态。

### 1.3 工具（均已入库，可复算）

| 文件 | 作用 |
|---|---|
| `esp32/485tools/replay_rpeak.py` | C 算法逐位重放；`RP_FILT_HIST` / `RP_FID_MODE` 两个环境变量做离线实验 |
| `esp32/485tools/pc485_cmd.py` | PC 侧直接下发 485 命令（绕开 ESP32），帧格式与 `ecg_cmd.c:27` 一致 |
| `esp32/485tools/pc_sweep_replay.py` | 起流 → 抓 N 秒 → 同一份样本跑多组参数，出横向对比表 |
| `esp32/485tools/cap485_quality.py` | 抓帧 + 误码/丢失/尖刺分析 |

复算命令：

```bat
cd esp32\485tools
py.cmd pc_sweep_replay.py --bpms 90 --from-file 90=_raw_90bpm_2mv.bin --configs 140:0,140:1,512:0
```

## 2 关键前提：这个缺陷对**信号幅度**高度敏感

这是本项目最容易踩的坑，也是此前「重放不复现现场故障」的全部原因。

| 采集 | AECG100 振幅 | 波形 max / min | 检出峰处样本值中位 | 回溯次数 | σ(e) |
|---|---|---|---|---|---|
| 11-09 宽格式记录（WinApp） | **2 mV** | 10293（峰高） | — | — | **2.72 FAIL** |
| 11-10 10:55 `_raw_90bpm.bin` | **1 mV** | 4970 / −1416 | 4851 | **0** | **0.35 假 PASS** |
| 11-10 11:19 `_raw_90bpm_2mv.bin` | **2 mV** | 10224 / −2368 | 10061 | **22** | **2.59 FAIL** |
| 11-10 11:24 `_raw_90bpm_2mv_b.bin` | **2 mV** | — | — | 22 | **2.53 FAIL** |

两份 2 mV 数据是**同一支算法、同一台设备、同一天**，唯一变化是振幅 ⇒ 单变量坐实「幅度相关」。

> **🛑 记入判据**：以后任何「重放不复现现场故障」的排查，第一件事查**幅度/增益**，
> 不要先怀疑算法移植错。11-10 上午为此白跑了半天。

**幅度为什么会影响回溯次数**（未完全定论，如实记录）：2 mV 时 90 bpm 每 180 s 有 22 次回溯，
1 mV 时 **0 次**。回溯只在「某拍积分峰低于主阈值 `thr = noise + 0.25·(signal − noise)`」时触发，
可推测与 `signal_peak` 的 EMA 收敛尺度、以及量化底噪在两种幅度下的相对占比有关。
**这一点不影响本文修法**（修法针对窗口覆盖，覆盖需求只与心率有关、与幅度无关），
但它意味着：**缺陷的暴露程度取决于信号条件**，不能因为某次测不到就认为不存在。

## 3 代码级根因

### 3.1 相关常量（`ecg_rpeak.h`）

| 常量 | 值 | 含义 |
|---|---|---|
| `ECG_RP_INTEG_WIN` | 60 | 积分窗长（样本） |
| `ECG_RP_LOCATE_HALF` | 40 | 落点搜索半径 ⇒ 窗宽 81 |
| `ECG_RP_FILT_HIST` | **140** | 滤波值历史深度 ⇒ **覆盖 [s−139, s]** |
| `ECG_RP_REFRACTORY` | 80 | 不应期 |

### 3.2 触发坐标与窗口覆盖的算术关系

主路径触发时：`trigger = s − 1 − 30`，即 `trigger = s − 31`。

- 窗口上沿 `trigger + 40 = s + 9` —— **落在未来**，永远取不到。
  所以「满窗 81」是个**不存在的基准**；实际最多只能扫到 **72 个**（`[trigger−40, trigger+31]`）。
- 窗口下沿 `trigger − 40 = s − lag − 40`。历史最早只有 `s − 139`。
  ⇒ **左截断条件：`lag > 99`**。
- `lag` = 回溯触发时 `trigger` 距当前样本的距离。

`locate_rpeak()` 的实现：

```c
return found ? best_idx : integrated_peak;   // found = 窗口内是否扫到任何样本
```

### 3.3 两种失效形态（这是本文最关键的发现）

| | **形态 ①：完全未精修** | **形态 ②：部分覆盖、静默选错** |
|---|---|---|
| 条件 | `lag` 大到窗口整体滑出历史 | 窗口只是**半边**滑出 |
| `found` | `false` | **`true`** |
| 返回 | `integrated_peak`（= trigger，原样） | 窗口内 |滤波值| 最大的那个（**错的**） |
| `loc == trigger` | **成立**（能被统计发现） | **不成立**（统计上完全隐身） |
| 实测代表 | 90 bpm，lag 212，扫到 **0/72** | 120 bpm，lag 158，最窄只扫到 **22/72** |
| 单拍误差 | 9 样本（18 ms） | **27 样本（54 ms）** |

**形态 ② 比 ① 更危险**：它 `found=true`、`loc≠trigger`，任何「精修率」「loc==trigger 计数」
都查不出来，只有「窗口实际覆盖量」能抓。这也是我此前只发现形态 ①、把 120 bpm 误当成
「另一个缺陷」的原因。

### 3.4 单拍误差的量级来源

从逐峰决策跟踪可以直接看到坐标关系（90 bpm / 2 mV，连续三个主路径接受的峰）：

```
#13 trig=833  → loc=863   (+30)   原始样本值≈R 顶
#18 trig=1500 → loc=1530  (+30)
```

即**主路径的落点稳定落在 `trigger + 30`**（窗口右缘在 `trigger+31` 饱和），
而此处原始样本值确实≈波形最大值 ⇒ 主路径落点正确。

回溯**未精修**时落点 = `trigger`，实测整体比相邻主路径峰偏移约 **9 个样本**
（P95 = P99 = **9.0**，21 个坏峰 × 2 = **42 个异常间期**，与实测完全对应）。

> ⚠ 这里只给**实测偏移量**，不宣称几何机理：`trigger` 对应的是积分域的强极大值，
> 它相对滤波/原始域的 R 顶有多少偏移，取决于波形形态，不能一概而论。

### 4.1 一个必须承认的指标局限

`σ(e)` 只能反映**抖动**，不能反映**落点是否在正确位置**。本次三种配置
（现状 / fid / h=512）在 90 bpm 下都验证了「检出峰处的原始样本值中位 ≈10061，
波形最大值 10224」⇒ 落点确实在 R 顶，不是落在 T 波或下降支上。

> **🛑 记入判据**：以后凡是「落点算法改动」，验收必须同时看
> **σ(e) + 峰处原始样本值**，不能只看 σ(e)。一个恒定偏移 20 样本的落点，σ(e) 可以完美。

## 5 修法论证：为什么选「候选存 fid」而不是「加大 filt_hist」

### 5.1 两种修法在 RR 指标上等价

90 / 120 bpm 上，`h=512 fid=0` 与 `h=140 fid=1` 给出**完全相同的 σ(e)**（0.35 / 0.23）。
所以不能靠效果选，要靠工程性质选。

### 5.2 所需历史深度随心率线性增长 ⇒ 加窗口是「会随心率失效的补丁」

回溯在 `s − last_peak > 1.66 × avg_RR` 时触发，候选下界是 `last_peak + REFRACTORY`：

```
需要的历史深度 ≈ 1.66 × RR − 80 + 41
```

| 心率 | RR（样本） | 需要 filt_hist ≥ | 512 够不够 |
|---|---|---|---|
| 300 | 100 | 127 | 够 |
| 180 | 167 | 238 | 够 |
| 120 | 251 | 377 | 够 |
| 90 | 334 | 515 | **刚好不够**（实测需要 253 就够用，见下） |
| 60 | 502 | 794 | **不够** |
| 40 | 753 | **1170** | **远远不够** |

（上表是理论上界；实测 90 bpm 只要 253 就够，因为回溯挑的是候选池里**幅值最大**的那个，
不一定取到窗口下界。但**下界随心率线性增长这个性质不变**，低心率迟早失效。）

⇒ `filt_hist` 从 140 加到 512 只是把失效点推迟到 60 bpm 以下，**不是修复**，
而且白吃 RAM（512 × 8 B = 4 KB vs 现在的 1.1 KB）。

### 5.3 选定方案：候选入池即存 fid

```
候选池元素： (trigger, value, slope)  →  (trigger, value, slope, fid, fid_val)
```

- 入池那一刻 `s` 与主路径接受时**完全相同**（同一时刻、同一窗口、同一 `fabsf` 比较）
  ⇒ **主路径行为一字不改**，这是「7 个心率 σ 一位数没变」的原因。
- 回溯直接用 `fid`，不再事后去找已经不存在历史。
- **内存（实测 sizeof，非估算，T225 §4.1 订正）**：
  用**并列数组** `int16_t cand_fid_delta[ECG_RP_CAND_MAX]`，**不塞进 `ecg_rp_cand_t`**
  （结构体是 `int64+float+float`=16 B，8 字节对齐下塞个 `int16` 会撑到 24 B，白涨 512 B）。

  | 配置 | `sizeof(ecg_rpeak_t)` | 增量 |
  |---|---|---|
  | `ECG_RP_DIAG=1`，`USE_STORED_FID=0` | 3920 B | — |
  | `ECG_RP_DIAG=1`，`USE_STORED_FID=1` | 4112 B | **+192 B**（fid 128 + 诊断窗宽 64） |
  | `ECG_RP_DIAG=0`，`USE_STORED_FID=0` | 3888 B | — |
  | `ECG_RP_DIAG=0`，`USE_STORED_FID=1` | 4016 B | **+128 B**（只加 fid） |

- 算力：每个候选入池多一次 `locate_rpeak()`。实测 90 bpm 每拍约 1~3 个候选，
  单次 locate 最多扫 72 个样本 ⇒ 每拍多 ~200 次比较，**相对 500 Hz 采样完全可忽略**。
- **与心率无关**：不依赖 `lag`，不需要预估最坏情况。

### 5.4 落码要点（供 P3 评审）

1. `ecg_rpeak.c` 候选结构体加字段，`cand_push()` 内计算 fid。
2. 回溯分支把 `locate_rpeak((uint32_t)best->index)` 换成 `best->fid`。
3. **主路径调用点不动**。
4. 主路径与回溯必须共用同一个「候选/落点解析」函数，禁止两处各写一套（T223 明确要求）。
5. 回归判据：本文 §4 的 9 个心率全部保持或改善；且必须复核「峰处原始样本值」不下滑
   （防止修法把落点改到下降支）。

## 6 60 bpm 的 6 个异常间期拆解 ⇒ 缺陷 A / 未定性现象 / 待查 三分

T222 v0.2 依据「6 轮 3 异常（50%）」把 60 bpm 判为 FAIL。把这 6 个异常间期逐个拆开后，
发现它们是**两类完全不同的东西**。数据来源 `_wide_60bpm_1.txt` / `_wide_60bpm_3.txt`
（宽格式，记录每个峰 ±3 个原始采样值）。

| 轮次 | 峰# | RR / 偏差 | 该峰 ±3 原始采样值 | 归类 |
|---|---|---|---|---|
| 1 | #14 | 449 / **−51** | `9279 9893 10354 [10462] 10193 9844 9556`（正常 R） | **A 落点漂移** |
| 1 | #15 | 471 / −29 | `−407 −479 −523 −595 −633 [−645] −640`（**全负、单调缓降**） | **可疑（未定性）** |
| 1 | #16 | 80 / −420 | `530 599 700 [710] 643 654 670`（R 的 **6.8%**） | **可疑（未定性）** |
| 1 | #117 | 425 / **−75** | `9097 9720 10213 [10572] 10554 10306 9856`（正常 R） | **A 落点漂移** |
| 3 | #172 | 463 / **−37** | `8584 9309 9910 10331 [10549] 10435 10181`（正常 R） | **A 落点漂移** |
| 3 | #173 | 437 / −63 | `2075 2632 3211 3843 4508 [−579] −621`（**单样本跳 5087**） | **待查**（疑似流不连续） |

（第 2 轮完全干净：180 峰、0 异常）

### 6.1 缺陷 A：落点漂移 —— 本文 §3/§5 已修

**确定性事件 3 个**（#14 / #117 / #172），偏差 37~75 样本。
60 bpm 时回溯滞后可达 ≈750 样本，远超 140，也远超 512 ⇒ 再次印证「加窗口」在低心率必然失效、必须用 fid。

> **#173 改列「待查」**（T225 §4.5）：它的窗口里有 `4508 → −579` 的单样本跳变 5087，
> 先要排除输入流不连续，才能算到缺陷 A 头上。因此不并入 A 的计数。

### 6.2 可疑现象（原称「缺陷 B」）—— **已降级为未定性，不作 C1/C2 的依据**

> **🛑 v0.2 订正（2026-11-10 15:00，依据 §6.2.1 的三条复核）**
> 本文 v0.1 把 #15 / #16 定性为「缺陷 B：无幅度/极性门」，并据此提出 C1 极性门 + C2 幅度门。
> **该定性证据不足，现降级为「一个未定性的可疑现象」**。理由见下，**不要再据此设计门控**。

#### 6.2.1 三条反证

**① 原文写的「P 波误检」是推断，不是观测，且被数据反证**

#16 与 #15 的间隔是 **80 个样本，正好等于 `ECG_RP_REFRACTORY`**。
如果 #16 真是落在 P 波位置，它落在哪取决于 P 波位置，**不会恰好卡在不应期边界上**。
80 这个数字的含义是「**触发连续到来、被不应期削平后的第一个可接受位置**」，
指向的是一串连续误触发，而不是一个离散的 P 波。

**② 相邻两拍之间原始电平跳了约 10000 码（≈1.1 mV）**

```
#14 窗口结束  +9556
#15 窗口起点   −407        ← 相邻两拍之间电平差约 10000 码
```

#15 的窗口是 `−407 → −645` 的**单调缓降**，根本不是 QRS 形态。
一个把电平整体压低 ~1 mV 的**基线台阶**，经高通/微分后必然产生瞬态振铃，
足以让积分包络出现一串局部极大 ⇒ 连续误触发。**这是输入端的瞬变，不是"正常心拍缺一道门"。**

**③ 11-10 新发现的机制恰好能制造这种瞬变，且 11-09 没留证据排除它**

11-10 做上板验证时发现：**环缓满时 `push_sample()` 会直接跳过检测器不喂样本**
（`ecg_ring_push` 失败就跳过，是设计行为）。实测撞到一次 180 s 跑出
`fed=77700 / pushed=101075` ⇒ **23% 样本没进检测器**。

检测器看到的是**不连续的样本流**，滤波器/积分会产生瞬态误触发 —— 与 ①② 的形态一致。
而 11-09 那批记录**没有记录 `fed` / `pushed`**，**无法事后核对当时是否跳过样本**。

#### 6.2.2 一条反向佐证：差异不在波形

| | 11-09 那 1 份（`_wide_60bpm_1.txt`） | 11-10 三份（同 AECG100 / 同 60 bpm / 同 2 mV） |
|---|---|---|
| 回溯触发次数 | 有（#15/#16 的量级只有回溯能接受） | **0 次** |
| 未定性事件 | 2 | **0** |

同一台信号源、同一幅度、同一算法，11-10 回溯**一次都没触发**。
⇒ **差异来自输入流或运行状态，不是"60 bpm 的波形本身会诱发缺门"。**

## 7 结论与待办

### 7.1 结论

1. **缺陷 A（落点精修窗口覆盖不足）**：根因、两种形态、量级、因果链均已闭合，
   修法在 9 个心率上验证通过，**已进入固件实现（T226）并上板验证通过**。
2. **原「缺陷 B（无幅度/极性门）」已降级为未定性的可疑现象**（§6.2）：证据只有单一记录里
   约 2 s 的一簇事件，且被「相邻两拍电平跳 ~10000 码」「rr=80 恰等于不应期」两条数据反证，
   另有 11-10 新发现的「环缓满 ⇒ 跳样本」机制无法排除。**不据此设计门控。**
3. **指标方法论修订**：`σ(e)` 单独使用不足以判定落点正确性，必须加「峰处原始样本值」；
   「失败率」必须按轮次统计，不能用 σ 均值掩盖（T223 已指出，本文落实为 §4 表与 §4.1）。
