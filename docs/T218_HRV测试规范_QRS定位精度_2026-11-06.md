# T218 HRV 测试规范 · QRS 峰定位精度

> **状态**：v0.1 立稿（2026-11-06）。**这是一份活的文档**，后续每轮测试都在 §8 追加记录、在 §9 补结论。
> **脚本**：`esp32/485tools/hrv_analyze.py`
> **上游**：T215（CH2/LOD/HRV 评估）、T217（`rpeak rec` 记录功能）
> **适用**：真机态（STM32+ADS1293 → RS485 → ESP32），信号源 AECG100 固定 180 bpm

---

## 1 这份文档解决什么

HRV（心率变异性）分析对 **R 峰的时间精度**极其敏感。500 Hz 采样下 1 个样本 = 2 ms，
而 RMSSD 的生理典型值只有 20~50 ms —— 定位抖动几个样本，结论就废了。

所以"能不能做 HRV"不能靠"看着挺准"，必须先回答三个量化问题：

| 问题 | 对应指标 | 不回答会怎样 |
|---|---|---|
| 时基准不准？ | 拟合斜率 vs 理论 RR | 所有时间量整体偏，且看不出来 |
| 单峰抖动多大？ | σ(e) | RMSSD 被噪声淹没，误当生理变异 |
| 有没有漏检/多检？ | 异常 RR 计数 | 一次漏检产生 2×RR 假间期，RMSSD 直接失真 |

本文定义这三个量的**测法、算法、判据**，并给出当前基线。

---

## 2 真值基准（判定的锚点）

信号源 **AECG100 固定 180 bpm** ⇒ 理论 RR 是算得出来的：

```
RR_true = 60 / 180 = 0.333333 s
        = 0.333333 × 500 Hz = 166.667 样本
```

**这是整套判据的唯一锚点。** 换信号源（比如 60 bpm）必须把 `--true-bpm` 一起改，
否则 Slope 偏差、异常间期判据全部失效。

> ⚠ 若将来用真实人体做测试，**没有真值**，只能用"同一段录像离线批处理"做交叉比对，
> 判据也要换一套（见 §9 待补）。

## 3 数据采集操作步骤

### 3.1 前置

| 项 | 要求 |
|---|---|
| 信号源 | AECG100 输出 180 bpm，接好导联 |
| 链路 | STM32 上电 → RS485 → ESP32 |
| 串口 | COM35 空闲（**关掉 SerialDebug 等占用工具**） |

### 3.2 命令序列

```
485-start              开 ESP32 侧 UART1（★这一步不会让 STM32 出数据）
485-send start         发 0x01，STM32 进 RUN（下行约 50% 丢包，失败就重发）
485-stat               看 frames 在涨 = 真在出数据
rpeak rec              开始记录，固定 300 s，到点自动落盘 -> /sdcard/rpeak_hrv.txt
```

等待 300 s。期间可以用 `rpeak` 查询剩余秒数。

```
rpeak                  应显示「QRS 记录：on（剩 xxx s）」
（300 s 后自动停）
rpeak                  应显示「QRS 记录：off」
```

> 🛑 **`485-start` ≠ 让 STM32 出数据**。只发 `485-start` 后 `485-perf` 会全 0，别误判链路坏。
> 🛑 记录**只在 485 源下允许**；FILE 源会覆盖 `mit-run` 的批处理结果，固件已挡。

### 3.3 数据回传

两种方式，二选一：

```bash
# ① 直接在 PC 上一条命令搞定（推荐）
py hrv_analyze.py --port COM35 --dump rpeak_hrv.txt --true-bpm 180

# ② 先落盘再分析
py hrv_analyze.py --port COM35 --dump rpeak_hrv.txt > rpeak_hrv.txt   # 或串口工具另存
py hrv_analyze.py rpeak_hrv.txt --true-bpm 180
```

脚本能容忍 `result-dump` 自带的 `# ---- BEGIN/END` 行与 `cardiolite>` 提示符混排。

## 4 脚本原理

### 4.1 观测模型

第 k 个峰的实测位置：

```
p_k = k · T + e_k        T = 真 RR（166.667），e_k = 该峰的定位误差
```

三个量必须**分开**估，混在一起就会得出错的结论。

### 4.2 ① 时基 —— 线性拟合斜率

对 `(k, p_k)` 做最小二乘，斜率 `a` 就是实测平均每拍前进多少样本。

```
等效采样率 fs_eff = fs × T_true / a
```

- `a = 166.667` ⇒ `fs_eff = 500.000 Hz`，时基无偏
- 实测 `a = 166.338` ⇒ `fs_eff = 500.99 Hz`（偏 +0.197%）

**意义**：时基偏差会让所有 HRV 时间量（SDNN、RMSSD、LF/HF 的频段边界）
整体缩放。0.2% 对 RMSSD 是 0.02 ms 量级，可忽略；但若到 1% 就必须校。

### 4.3 ② 定位抖动 σ(e) —— **这里有个陷阱**

🛑 **不能用"去线性趋势后残差的 std"**。第一版脚本就是这么写的，结果算出
σ(e) = 30.9 样本（61.8 ms），而同期 RR 的 σ 只有 3.86 样本 —— 差 8 倍，模型错了。

**为什么错**：`p_k` 是 RR 的**累加**。若 RR 带白噪声，位置残差就是**随机游走**，
std 随 `√k` 增长，反映的是极慢的漂移，不是单峰精度。

**正确估计（两种，互为交叉校验）**：

| 方法 | 推导 | 公式 |
|---|---|---|
| **(a) 相邻差法** | `RR_k = T + (e_{k+1} − e_k)`，白噪声下 `σ(RR)=√2·σ(e)` | `σ(e) = σ(RR)/√2` |
| **(b) 二阶差分法** | `d2_k = e_{k+1} − 2e_k + e_{k−1}`，`σ(d2)=√6·σ(e)` | `σ(e) = σ(d2)/√6` |

- **(b) 是主判据**：二阶差分天然消掉线性趋势与慢漂，抗心率慢变
- **(a) 作交叉校验**：两法比值应在 **0.7~1.4**；偏离说明 `e` 非白噪声
  （有漏检补偿，或检测点在 R 波与 T 波之间跳）

### 4.4 ③ 漏检 / 多检 —— 用**相对真值**判，不用相对中位数

| 现象 | RR 特征 | 判据 |
|---|---|---|
| 漏检一个 QRS | RR ≈ **2×T** | `RR > 1.40·T` |
| 多检一个假峰 | RR ≈ **0.5×T** | `RR < 0.75·T` |

🛑 不能用"相对中位数 ±60%"——固定 180 bpm 下，0.7×T 这种明显异常的间期
会被漏掉（实测就出现过 `RR=116=0.70·T` 未被第一版判据捕获）。

计数一致性作为独立校验：

```
应有 = 跨度秒数 × bpm / 60 + 1
差值 > ±1.5 ⇒ 有漏检或多检
```

## 5 结果解读

脚本输出分三段，逐段对应上面的模型：

```
① 时基
   拟合斜率       : 166.338 样本/拍（真值 166.667），偏差 -0.328
   等效采样率     : 500.99 Hz（名义 500 Hz），+0.197%

② 定位抖动 σ(e)
   二阶差分法     : x.xxx 样本 = x.xx ms      ← 主判据
   相邻差法       : x.xxx 样本 = x.xx ms      ← 交叉校验
   RR σ / RMSSD   : x.xxx / x.xxx 样本
   交叉校验       : ✓ 两法一致 / ⚠ 偏离

③ 漏检 / 多检
   计数           : 应有 898.1 个，实测 900 个，差 +1.9
   ⚠ 疑似多检 N 处（RR < 0.75·T）
```

| 指标 | 含义 | 好坏怎么看 |
|---|---|---|
| 拟合斜率偏差 | 时基误差 | \|偏差\|/T < 0.1% 可忽略 |
| **σ(e)** | **单峰定位抖动** | **唯一决定 HRV 可用性的量** |
| RR σ | 相邻差标准差 | ≈ √2·σ(e) 才自洽 |
| RMSSD | 相邻 RR 差值均方根 | 固定心率下应 ≈ 测量噪声 |
| 计数差 | 多了还是少了峰 | >±1.5 必须查异常间期 |
| 两法比值 | 噪声白不白 | 0.7~1.4 正常 |

> 💡 固定 180 bpm 时，**RMSSD 就是测量噪声本身**（生理变异为 0）。
> 所以这里算出的 RMSSD 可以直接当"噪声底"。

## 6 判定依据（阈值从哪来）

HRV 的核心时域指标：

```
RMSSD = sqrt( mean( (RR_{k+1} − RR_k)² ) )
```

生理典型值 **20~50 ms**。工程要求测量噪声对 RMSSD 的污染 < 5%：

```
允许 σ(e) < 0.05 × RMSSD_typical / √2
         ≈ 0.05 × 20 ms / 1.414
         ≈ 0.71 ms
         ≈ 0.35 样本  @500 Hz
```

另有一条 HRV 文献经验判据：**R 峰定位误差应 < 1 ms ⇒ < 0.5 样本**。

取两者中较宽的一条作为 PASS 线：

| 判定 | σ(e) @500 Hz | σ(e) 时间 | 可用范围 |
|---|---|---|---|
| **PASS** | ≤ 0.5 样本 | ≤ 1.0 ms | 时域 + 频域 HRV 都可用 |
| **WARN** | 0.5 ~ 1.0 样本 | 1 ~ 2 ms | 只可做均值/趋势类；RMSSD 需谨慎 |
| **FAIL** | > 1.0 样本 | > 2 ms | 不可用于 HRV，须改定位算法 |

> 这两个阈值是**工程推导**，不是拍脑袋：从 "RMSSD 污染 <5%" 反推 + 文献经验值。
> 若要更严（例如做 LF/HF 频域），可按同样方法用目标指标的典型值重算。

## 7 首次基线结果（2026-11-06，AECG100 180 bpm）

**采集**：`rpeak rec` 满程 300 s，900 个峰，文件 6011 B。

| 指标 | 值 | 说明 |
|---|---|---|
| 峰数 / 跨度 | 900 / 299.05 s | 3.01 峰/s |
| 拟合斜率 | 166.338 样本/拍 | 真值 166.667，**偏差 −0.328** |
| 等效采样率 | **500.99 Hz** | 偏 +0.197% |
| RR 均值 / 中位 | 166.32 / 167 样本 | — |
| RR σ | 3.856 样本 = **7.71 ms** | — |
| RMSSD | 5.502 样本 = **11.00 ms** | 固定心率下＝测量噪声 |
| **σ(e)（相邻差法）** | **2.73 样本 = 5.45 ms** | 3.856/√2 |
| 计数一致性 | 应有 898.1，实测 900，**差 +1.9** | ⇒ 约 2 个多检 |
| 最小 RR | **116 样本（0.70·T）** | 多检指纹 |

**判定：FAIL**。σ(e) ≈ 2.7 样本（5.45 ms），距 PASS 线（0.5 样本）**差约 5.5 倍**。

### 7.1 三个已知问题（按严重度）

1. **σ(e) 偏大 5.5 倍** —— HRV 不可用的直接原因。要亚样本定位（抛物线拟合峰顶 / 过零插值）。
2. **约 2 个多检** —— 计数 +1.9、最小 RR=0.70·T 是"插入假峰"的典型指纹。
   多检比抖动更致命：一次多检产生一个假短间期，RMSSD 被它单独拉高。
3. **时基 +0.197%** —— 影响小，但根因需查（是重采样器 853.33→500 的取整，
   还是 STM32 侧时基）。若将来做频域 HRV，这一项会被放大。

> ⚠ 第 1、2 条的数值来自**修正前脚本的原始统计**（RR σ / 计数），
> 修正后的 `sigma_e_d2` 尚未在真数据上复跑（COM35 被占用）。
> 下次测试时用新脚本复跑，以两法交叉校验的结果为准。
