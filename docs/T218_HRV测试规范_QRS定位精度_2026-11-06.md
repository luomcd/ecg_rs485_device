# T218 HRV 测试规范 · QRS 峰定位精度

> **状态**：v0.1 立稿（2026-11-06）。**这是一份活的文档**，后续每轮测试都在 §8 追加记录、在 §9 补结论。
> **脚本**：`esp32/485tools/hrv_analyze.py`
> **上游**：T215（CH2/LOD/HRV 评估）、T217（`rpeak rec` 记录功能）
> **适用**：真机态（STM32+ADS1293 → RS485 → ESP32），信号源 AECG100 固定 180 bpm

---

## 1 这份文档解决什么

HRV（心率变异性）分析对 **R 峰的时间精度**极其敏感。500 Hz 采样下 1 个样本 = 2 ms，
而 RMSSD 的生理典型值只有 20~50 ms —— 定位抖动几个样本，结论就废了。

所以"能不能做 HRV"不能靠"看着挺准"，必须先回答三个量化问题：

| 问题 | 对应指标 | 不回答会怎样 |
|---|---|---|
| 时基准不准？ | 拟合斜率 vs 理论 RR | 所有时间量整体偏，且看不出来 |
| 单峰抖动多大？ | σ(e) | RMSSD 被噪声淹没，误当生理变异 |
| 有没有漏检/多检？ | 异常 RR 计数 | 一次漏检产生 2×RR 假间期，RMSSD 直接失真 |

本文定义这三个量的**测法、算法、判据**，并给出当前基线。

---

## 2 真值基准（判定的锚点）

信号源 **AECG100 固定 180 bpm** ⇒ 理论 RR 是算得出来的：

```
RR_true = 60 / 180 = 0.333333 s
        = 0.333333 × 500 Hz = 166.667 样本
```

**这是整套判据的唯一锚点。** 换信号源（比如 60 bpm）必须把 `--true-bpm` 一起改，
否则 Slope 偏差、异常间期判据全部失效。

> ⚠ 若将来用真实人体做测试，**没有真值**，只能用"同一段录像离线批处理"做交叉比对，
> 判据也要换一套（见 §9 待补）。

## 3 数据采集操作步骤

### 3.1 前置

| 项 | 要求 |
|---|---|
| 信号源 | AECG100 输出 180 bpm，接好导联 |
| 链路 | STM32 上电 → RS485 → ESP32 |
| 串口 | COM35 空闲（**关掉 SerialDebug 等占用工具**） |

### 3.2 命令序列

```
485-start              开 ESP32 侧 UART1（★这一步不会让 STM32 出数据）
485-send start         发 0x01，STM32 进 RUN（下行约 50% 丢包，失败就重发）
485-stat               看 frames 在涨 = 真在出数据
rpeak rec              开始记录，固定 300 s，到点自动落盘 -> /sdcard/rpeak_hrv.txt
```

等待 300 s。期间可以用 `rpeak` 查询剩余秒数。

```
rpeak                  应显示「QRS 记录：on（剩 xxx s）」
（300 s 后自动停）
rpeak                  应显示「QRS 记录：off」
```

> 🛑 **`485-start` ≠ 让 STM32 出数据**。只发 `485-start` 后 `485-perf` 会全 0，别误判链路坏。
> 🛑 记录**只在 485 源下允许**；FILE 源会覆盖 `mit-run` 的批处理结果，固件已挡。

### 3.3 数据回传

两种方式，二选一：

```bash
# ① 直接在 PC 上一条命令搞定（推荐）
py hrv_analyze.py --port COM35 --dump rpeak_hrv.txt --true-bpm 180

# ② 先落盘再分析
py hrv_analyze.py --port COM35 --dump rpeak_hrv.txt > rpeak_hrv.txt   # 或串口工具另存
py hrv_analyze.py rpeak_hrv.txt --true-bpm 180
```

脚本能容忍 `result-dump` 自带的 `# ---- BEGIN/END` 行与 `cardiolite>` 提示符混排。

## 4 脚本原理

### 4.1 观测模型

第 k 个峰的实测位置：

```
p_k = k · T + e_k        T = 真 RR（166.667），e_k = 该峰的定位误差
```

三个量必须**分开**估，混在一起就会得出错的结论。

### 4.2 ① 时基 —— 用 **RR 中位数**，不要用拟合斜率

对 `(k, p_k)` 做最小二乘，斜率 `a` 就是实测平均每拍前进多少样本：

```
等效采样率 fs_eff = fs × T_true / a
```

**🛑 但斜率会被漏检/多检系统性拉偏**，这是 210 bpm 那次实测暴露出来的：

| 估计方法 | 210 bpm 实测 | 解读 |
|---|---|---|
| 拟合斜率 | 141.426 ⇒ **505.06 Hz（+1.012%）** | 假的，见下 |
| **RR 中位数** | 143 ⇒ **499.50 Hz（−0.100%）** | ★ 真实情况 |

同一次记录里有 **18 处多检**（RR≈0.65T）和 7 处漏检（RR≈1.65T）。多检让平均间隔
变短、斜率变小，**正好伪装成"时基偏快 1%"**。而中位数对少数异常值不敏感。

⇒ **时基一律以 RR 中位数为准**；拟合斜率只在③「无异常间期」时才可引用。

**意义**：时基偏差会让所有 HRV 时间量（SDNN、RMSSD、LF/HF 的频段边界）整体缩放。
180 bpm 那次的 +0.197%、210 bpm 那次的 −0.100%，都在 0.2% 以内，可忽略；
若到 1% 就必须校准。

### 4.3 ② 定位抖动 σ(e) —— **这里有个陷阱**

🛑 **不能用"去线性趋势后残差的 std"**。第一版脚本就是这么写的，结果算出
σ(e) = 30.9 样本（61.8 ms），而同期 RR 的 σ 只有 3.86 样本 —— 差 8 倍，模型错了。

**为什么错**：`p_k` 是 RR 的**累加**。若 RR 带白噪声，位置残差就是**随机游走**，
std 随 `√k` 增长，反映的是极慢的漂移，不是单峰精度。

**正确估计（两种，互为交叉校验）**：

| 方法 | 推导 | 公式 |
|---|---|---|
| **(a) 相邻差法** | `RR_k = T + (e_{k+1} − e_k)`，白噪声下 `σ(RR)=√2·σ(e)` | `σ(e) = σ(RR)/√2` |
| **(b) 二阶差分法** | `d2_k = e_{k+1} − 2e_k + e_{k−1}`，`σ(d2)=√6·σ(e)` | `σ(e) = σ(d2)/√6` |

- **(b) 是主判据**：二阶差分天然消掉线性趋势与慢漂，抗心率慢变
- **(a) 作交叉校验**：两法比值应在 **0.7~1.4**；偏离说明 `e` 非白噪声
  （有漏检补偿，或检测点在 R 波与 T 波之间跳）

### 4.4 ③ 漏检 / 多检 —— 用**相对真值**判，不用相对中位数

| 现象 | RR 特征 | 判据 |
|---|---|---|
| 漏检一个 QRS | RR ≈ **2×T** | `RR > 1.40·T` |
| 多检一个假峰 | RR ≈ **0.5×T** | `RR < 0.75·T` |

🛑 不能用"相对中位数 ±60%"——固定 180 bpm 下，0.7×T 这种明显异常的间期
会被漏掉（实测就出现过 `RR=116=0.70·T` 未被第一版判据捕获）。

计数一致性作为独立校验：

```
应有 = 跨度秒数 × bpm / 60 + 1
差值 > ±1.5 ⇒ 有漏检或多检
```

## 5 结果解读

脚本输出分三段，逐段对应上面的模型：

```
① 时基
   拟合斜率       : 166.338 样本/拍（真值 166.667），偏差 -0.328
   等效采样率     : 500.99 Hz（名义 500 Hz），+0.197%

② 定位抖动 σ(e)
   二阶差分法     : x.xxx 样本 = x.xx ms      ← 主判据
   相邻差法       : x.xxx 样本 = x.xx ms      ← 交叉校验
   RR σ / RMSSD   : x.xxx / x.xxx 样本
   交叉校验       : ✓ 两法一致 / ⚠ 偏离

③ 漏检 / 多检
   计数           : 应有 898.1 个，实测 900 个，差 +1.9
   ⚠ 疑似多检 N 处（RR < 0.75·T）
```

| 指标 | 含义 | 好坏怎么看 |
|---|---|---|
| 拟合斜率偏差 | 时基误差 | \|偏差\|/T < 0.1% 可忽略 |
| **σ(e)** | **单峰定位抖动** | **唯一决定 HRV 可用性的量** |
| RR σ | 相邻差标准差 | ≈ √2·σ(e) 才自洽 |
| RMSSD | 相邻 RR 差值均方根 | 固定心率下应 ≈ 测量噪声 |
| 计数差 | 多了还是少了峰 | >±1.5 必须查异常间期 |
| 两法比值 | 噪声白不白 | 0.7~1.4 正常 |

> 💡 固定 180 bpm 时，**RMSSD 就是测量噪声本身**（生理变异为 0）。
> 所以这里算出的 RMSSD 可以直接当"噪声底"。

## 6 判定依据（阈值从哪来）

HRV 的核心时域指标：

```
RMSSD = sqrt( mean( (RR_{k+1} − RR_k)² ) )
```

生理典型值 **20~50 ms**。工程要求测量噪声对 RMSSD 的污染 < 5%：

```
允许 σ(e) < 0.05 × RMSSD_typical / √2
         ≈ 0.05 × 20 ms / 1.414
         ≈ 0.71 ms
         ≈ 0.35 样本  @500 Hz
```

另有一条 HRV 文献经验判据：**R 峰定位误差应 < 1 ms ⇒ < 0.5 样本**。

取两者中较宽的一条作为 PASS 线：

| 判定 | σ(e) @500 Hz | σ(e) 时间 | 可用范围 |
|---|---|---|---|
| **PASS** | ≤ 0.5 样本 | ≤ 1.0 ms | 时域 + 频域 HRV 都可用 |
| **WARN** | 0.5 ~ 1.0 样本 | 1 ~ 2 ms | 只可做均值/趋势类；RMSSD 需谨慎 |
| **FAIL** | > 1.0 样本 | > 2 ms | 不可用于 HRV，须改定位算法 |

> 这两个阈值是**工程推导**，不是拍脑袋：从 "RMSSD 污染 <5%" 反推 + 文献经验值。
> 若要更严（例如做 LF/HF 频域），可按同样方法用目标指标的典型值重算。

## 7 首次基线结果（2026-11-06，AECG100 180 bpm）

**采集**：`rpeak rec` 满程 300 s，900 个峰，文件 6011 B。
**分析**：`hrv_analyze.py --port COM35 --dump rpeak_hrv.txt --true-bpm 180`（修正后版本）

### 7.1 时基

| 指标 | 值 | 说明 |
|---|---|---|
| 拟合斜率 | 166.338 样本/拍 | 真值 166.667，**偏差 −0.328** |
| 等效采样率 | **500.987 Hz** | 偏 **+0.197%** |

### 7.2 定位抖动

| 指标 | 值 | 说明 |
|---|---|---|
| **σ(e) 二阶差分法** | **2.246 样本 = 4.49 ms** | ★ 主判据 |
| σ(e) 相邻差法 | 2.726 样本 = 5.45 ms | 交叉校验 |
| 两法比值 | **0.82** | ✓ 在 0.7~1.4 内 ⇒ e 近似白噪声 |
| RR σ | 3.856 样本 = 7.71 ms | — |
| RMSSD | 5.502 样本 = **11.00 ms** | 固定心率下＝测量噪声 |

### 7.3 漏检 / 多检

| 指标 | 值 |
|---|---|
| 计数一致性 | 应有 898.1，实测 900，**差 +1.9** |
| 疑似多检 | **4 处**，RR 均为 116~117 样本（**0.70·T**） |
| 多检位置 | 第 153 / 182 / 627 / 689 个间期 |

**判定：FAIL**。σ(e) = 2.25 样本（4.49 ms），距 PASS 线（0.5 样本）**差 4.5 倍**。

### 7.4 三个已知问题（按严重度）

**① σ(e) 偏大 4.5 倍** —— HRV 不可用的直接原因。
要亚样本定位（抛物线拟合峰顶 / 线性插值过零点）才可能压到 0.5 样本以内。

**② 4 处 RR=116~117（0.70·T）呈固定模式，不是随机噪声** 🛑
这是本次最有价值的发现：4 次短间期的**数值几乎完全相同**（116/116/116/117），
随机误检不会这么整齐，说明存在**系统性的检测偏移**。

可能的机理（待验证）：
- 检测器偶尔锁到 T 波或某个固定延迟的伪迹上，比 R 峰早约 51 样本（102 ms）；
- 若是"插入假峰"，后面应当紧跟一个 ≈51 样本的补偿间期，但**未观察到**
  （51 < 0.75T 同样会被标记，说明没有配对出现）；
- 更可能是一次**峰位置提前**（同一拍被检早），而非多出一拍。

⚠ 这条与"计数差 +1.9"相互印证但机理不清 ⇒ 第 2 轮测试要专门抓这 4 处
附近的原始波形（需峰处邻域值，见 §9 缺口 1）。

**③ 时基 +0.197%** —— 影响小（对 RMSSD 是 0.02 ms 量级），但根因未明：
可能是重采样器 853.33→500 的取整，也可能是 STM32 侧时基。
做频域 HRV 之前必须归因。

## 7B 第二次基线（2026-11-06 后半，**AECG100 210 bpm**）

**采集**：`rpeak rec` 满程 295 s（跨度），1043 个峰。
**分析**：`hrv_analyze.py --port COM35 --dump rpeak_hrv.txt --true-bpm 210`

> 真值：RR = 500×60/210 = **142.857 样本 = 285.71 ms**
> ⚠ 换心率必须改 `--true-bpm`，否则斜率偏差与漏检/多检阈值全部失效。

### 7B.1 结果

| 指标 | 值 | 与 180 bpm 对比 |
|---|---|---|
| **时基（RR 中位数）** | 143 样本 ⇒ **499.50 Hz（−0.100%）** | 180 bpm：+0.197% |
| 拟合斜率（不可信） | 141.426 ⇒ 505.06 Hz（+1.012%） | 被多检污染 |
| **σ(e) 二阶差分** | **6.808 样本 = 13.62 ms** | 180 bpm：2.25 样本 ⇒ **恶化 3 倍** |
| σ(e) 相邻差 | 7.903 样本 = 15.81 ms（比值 0.86 ✓） | 2.73 样本 |
| RR σ / RMSSD | 11.176 / 16.676 样本（22.35 / 33.35 ms） | 3.86 / 5.50 样本 |
| 计数差 | 应有 1033.5、实测 1043 ⇒ **+9.5** | +1.9 |
| 多检 | **18 处**（RR = 0.65~0.73·T） | 4 处 |
| 漏检 | **7 处**（RR = 1.60~1.65·T） | 0 处 |
| 异常率 | **2.40%**（25/1042） | 0.44% |

**判定：FAIL**，σ(e) = 6.81 样本，距 PASS 线差 **13.6 倍**。

### 7B.2 三个结论

**① 时基没问题，别被斜率骗了。**
拟合斜率给出 +1.012% 的"时基偏差"，但同期 18 处多检把平均间隔拉短了。
用 RR 中位数重算只有 **−0.100%**。这条促使脚本改判据（§4.2）。

**② 检测器在高心率下明显退化，这是关键发现。**

| | 180 bpm | 210 bpm | 变化 |
|---|---|---|---|
| RR（样本） | 167 | 143 | −14% |
| σ(e)（样本） | 2.25 | 6.81 | **+203%** |
| 异常率 | 0.44% | 2.40% | **+5.5 倍** |

RR 只缩短 14%，抖动却涨 3 倍、异常率涨 5.5 倍 ⇒ **不是线性恶化，是检测器进了
不适用的工况**。合理猜测：RR 缩短后 T 波与 QRS 靠得更近（0.65·T ≈ 93 样本 = 186 ms，
正落在 R-T 间隔量级），检测器时而锁到 T 波上。

**③ 异常间期的数值高度一致，说明是系统性而非随机。**

多检集中在 0.65~0.73·T，漏检集中在 1.60~1.65·T。随机噪声不会这么整齐。
且 `0.65 + 1.65 = 2.30 ≠ 2.0` ⇒ 不是简单的"多检一次 + 漏检一次"配对，
更像**同一拍在 R 峰与 T 波之间来回跳**。

⇒ 要定论必须看这几处附近的**原始波形**（需峰处邻域值，§9 缺口 1 因此升为最高优先）。

## 7C 证据强度分级（🛑 攻坚前必读，别把假设当结论）

2026-11-09 明确：现有发现里有**两类东西混在一起**，攻坚时必须分开对待。

### 7C.1 已确定（方法闭合 / 可复算 / 有数据）

| # | 结论 | 证据 |
|---|---|---|
| 1 | **时基必须用 RR 中位数判**，不能用拟合斜率 | 同一次 210 bpm 记录：斜率 +1.012%、中位数 −0.100%，差 10 倍；且同期有 18 处多检可解释斜率为何偏小。方法层面已闭合，**任何后续测试都按此执行** |
| 2 | **σ(e) 不能用「去趋势残差 std」** | 数学上：峰位置是 RR 的累加，RR 白噪声 ⇒ 残差是随机游走（std ∝ √k）。实测反证：残差给 30.9 样本，真值 2.25，差 8 倍。方法层面已闭合 |
| 3 | 两次基线的**具体数值** | σ(e)=2.25 / 6.81 样本，异常率 0.44% / 2.40%，多检 4 / 18 处，漏检 0 / 7 处。计算过程可复算，**数值本身确定** |
| 4 | 180 bpm 下 **4 处 RR=116/116/116/117**（0.70·T）数值高度一致 | 观测事实，非推断。随机噪声不会产生这种一致值 ⇒ **存在系统性成分**（但"是什么"未定，见下） |
| 5 | 210 bpm 下多检集中在 0.65~0.73·T、漏检集中在 1.60~1.65·T | 观测事实 |

### 7C.2 待验证（只是假设，不能当结论用）

| # | 假设 | 现有支撑 | 缺什么 |
|---|---|---|---|
| 1 | **"高心率导致检测器退化"是一条规律** | 只有 180 / 210 bpm **各一次** 300 s | **重复性**：每心率 ≥3 次。若 210 的异常率忽高忽低（比如某次是电极接触问题），就不是"退化规律" |
| 2 | **误检来自 T 波** | `0.65·T ≈ 93 样本 = 186 ms`，落在 R-T 间隔量级 | **波形证据**：峰处邻域值，直接看那几处检到的是什么 |
| 3 | **退化是非线性的** | 两个点（180/210） | 至少 3~4 个心率点，否则不能谈曲线形状 |
| 4 | **"同一拍在 R/T 之间跳"**（由 `0.65T+1.65T=2.30T≠2T` 推出） | 纯推理，无观测 | 波形 + 与 R-T 实测间隔对照 |

### 7C.3 这个区分为什么重要

两条关键判断都依赖它：

- 若「退化」只是**偶发**（接触不良、某次信号源设置不同），改进方向完全不同 —— 不是改算法，是控条件。
- 若「T 波误检」**不成立**，那么"加不应期"这个修法就是错的，会把真 R 峰也挡掉。

⇒ **P2e（重复性）与 P2d（邻域值）是任何算法改动的前置**。在拿到这两组数据之前，
不应对检测器做结构性修改。

## 9 待补充 / 已知缺口

| # | 缺口 | 影响 | 计划 |
|---|---|---|---|
| 1 | 记录内容**只有峰号，无峰处波形值** | 判不了"点是否落在峰顶"；210 bpm 那 18 多检 + 7 漏检**无法定性** | 🔴 **最高优先**（P2d）：新开独立文件写峰处邻域值，不动 `P <号>` 口径 |
| 2 | **无重复性验证** | 每心率只有 1 次 300 s，"退化是规律"无法成立（§7C.2） | 🔴 P2e：每心率 ≥3 次，看异常率是否稳定复现 |
| 3 | **Se / PPV 未量化**，也未与 MIT-BIH 标注比对 | 脚本只列异常条数，没换算成检出率/阳性预测值 | 🟡 P2c：半天，纯脚本改动；标注比对可复用 `mitbih_eval.py` 口径 |
| 4 | 无**真实人体**数据的判据 | 现在的阈值全部依赖 AECG100 真值 | 用同一段数据的离线批处理做交叉比对 |
| 5 | 未做频域（LF/HF） | 频段边界对时基误差敏感 | 时域 PASS 后再开 |
| 6 | 32 KB 缓冲上限 300 s | 长时记录需轮转或 PSRAM | T215 §2.6（为 P2d 的前置） |
| 7 | 时基 ±0.2% 的**归因未定** | 做频域前必须查清是重采样取整还是 STM32 侧时基 | 用 raw853 直出模式对照 |
| 8 | **打点的绝对偏移未量化**（屏上肉眼可见滞后） | 若偏移恒定 ⇒ 对 RR 无害；若随心率变 ⇒ 会混进 σ，可能正是 210 bpm σ 变大的原因 | ① 用 P2d 的邻域值算"峰索引是否在 ±3 内取到最大值"；② 同一时刻在 60 / 210 bpm 各看一次屏上打点做对照 |
| 9 | **波形偶发失真无法复现**（屏上偶尔一个波形形状不对） | 与打点滞后可能同源也可能不同源；**当前没有任何波形导出手段**，只能目视 | 加 `wave-dump`：把环缓最近 10 s（5000 样本）打到串口（约 30 KB，几秒传完）。比 P2d 更直接命中"那一段波形" |

> **2026-11-09 记录（波形偶发失真）**
> 与 §9-8 的打点滞后**分开对待**，三者的判据不同：
>
> | 候选 | 判据 | 现状 |
> |---|---|---|
> | 链路丢字节/错帧 | `485-stat` 的 `crc_err` / `resync` / `seq_gaps` / `ovf` 是否在失真时刻上涨 | 30 s 窗口实测全 0，**暂无证据** |
> | AFE / 信号本身（电极、共模、伪迹） | 链路指标干净，但波形畸变 | 未测 |
> | 重采样 / 显示层 | 数据正确但画错 | 未测（无波形数据） |
>
> ⇒ 唯一能定性的手段是**把波形取下来**。ESP32 环缓有 5000 样本（10 s），
> `wave-dump` 只是读出来打印，不需要改存储、不占 SD，实现成本低。
