# T237 评审方案：CH2 真实数据上传

> **日期**：2026-11-12  
> **评审对象**：`T237_CH2真实数据上传_方案_2026-11-12.md`  
> **评审依据**：T232、T234、当前 STM32/ESP32 源码、T101 协议、ADS1293 数据手册、AECG100 用户手册  
> **评审性质**：方案准入评审、实现审查和分阶段验收  
> **评审结论**：**批准方案 B 的技术方向，暂不批准当前方案直接落码。**

---

## 0 评审目标

本评审方案要回答四个问题：

1. 是否可以把 CH2 从“CH1副本”改成“经过完整滤波链和重采样的真实数据”；
2. 如何保证 CH1 的现有行为、帧格式和 QRS 结果不被重构破坏；
3. 如何证明 CH2 的确是另一路独立采样、独立滤波的数据；
4. 默认开启双通道对现有上位机、WinApp、ESP32 显示和带宽是否可接受。

评审分为：

- **设计准入**：架构和状态边界是否成立；
- **实现准入**：代码文件、结构布局、接口和资源预算是否闭环；
- **功能验收**：CH1 逐位不变、CH2 真实独立；
- **系统验收**：双通道默认策略、WinApp/ESP32/PC 工具兼容；
- **实验验收**：当前接线和改线后的 CH1/CH2 波形语义。

---

## 1 方案选择评审

T237 比较了三种方案：

| 方案 | 内容 | 评审意见 |
|---|---|---|
| A：只做 dc_block + 重采样 | 改动小，但不含 notch/带通 | **不满足“完整滤波链真实数据”目标** |
| **B：上下文重构** | 同一套 restore/filter 代码，两个独立状态上下文 | **推荐** |
| C：复制函数 | 两套重复逻辑 | **不采用**，必然产生后续分叉 |

### 结论

- **批准方案 B 的总体方向**；
- 不接受“纯机械搬移、CH1 调用点零改动”的表述；
- 必须把初始化、设置、状态读取和上下文生命周期一起纳入重构范围。

---

## 2 P0 阻断项

### P0-1 上下文重构不能只包装 `ecg_restore_process()`

当前 `g_dc`、`f64` 同时被以下路径直接使用：

- `ads1293_filter_chain_init()`；
- `ads1293_status_byte()`；
- `vcomcmd.c` 的 notch/mode 设置；
- `vcomcmd.c` 的 notch/mode/profile 读取；
- `fast_restore_snippet.c` 内部的 blank/reset/process；
- `ads1293.c` 中的全局定义和死代码分支。

T237 只列了部分设置调用，不能覆盖所有访问点。

### 必须补充的设计

明确区分两层初始化：

```text
ecg_restore_chain_init(ctx)
    - ecg_dc_block_init(&ctx->dc, ECG_DC_BLOCK_FC_HZ_F)
    - ecg_filter_f64_init(&ctx->flt)

ecg_restore_session_start(ctx)
    - 复位 base/seen/blank/hold/startup
```

当前 `ecg_restore_start()` 只复位后者，不能擅自承担 DC block 和 filter 初始化。

### 放行条件

- 所有 `g_dc/f64` 的读写都通过 context 接口完成；
- `chain_init` 和 `session_start` 的顺序与原固件一致；
- `ecg_filter_f64_init` 的 notch/mode 默认值在两路一致；
- 不存在任何 legacy 全局旁路。

---

### P0-2 853 Hz 模式缺少 CH2 滤波值存储

T237 计划在入队后的打包阶段使用局部变量 `f2`：

```text
CH2 = ecg_out_codes_to_lsb(f2)
```

但 `f2` 在 `ads1293_raw_popoutput()` 返回时已离开作用域，而打包发生在 FIFO 累计到 25 个输出样本之后。

### 放行条件

500 Hz 和 853 Hz 两种模式都必须把 CH2 结果写入队列元素。

推荐：

```c
ecgfilter.ch2_out = ecg_out_codes_to_lsb((float)f2);  /* 853模式 */
```

500 Hz 模式则用 `out2` 的输出写入 `ch2_out`。

不允许依赖临时变量或事后重新计算。

---

### P0-3 默认双通道会破坏现有 WinApp

T237 建议：

```c
_bch2 = 1;
```

但同时承认 WinApp 只支持 59 B 单通道帧。默认改为 109 B 后：

- WinApp 可能无法解析；
- 现有自动化脚本、回放和测试可能失去可比性；
- ESP32 能解析不等于整个系统兼容。

### 放行条件

- 本轮保持 `_bch2=0`；
- 通过现有 `ch2 on` 命令做双通道验证；
- WinApp、ESP32、PC 工具全部完成 109 B 帧适配后，才允许默认双通道；
- 或者建立显式能力协商/版本机制，禁止静默改变默认帧长。

---

### P0-4 CH1“逐位不变”的验证方式不足

T237 计划用一份 MIT 记录比较峰序列和 BPM。

但这只能证明 QRS 结果没变，不能证明：

- `filterraw` 相同；
- 500 Hz 重采样输出相同；
- 屏幕波形相同；
- SD/帧样本字节相同；
- notch/mode 切换和伪迹空白时序相同。

### 放行条件

必须直接比较 CH1 样本流：

| 对比项 | 判据 |
|---|---|
| `filterraw` | 改动前后逐样本完全一致 |
| `dsrateraw` | 500 Hz 输出逐样本完全一致 |
| 单通道 59 B 帧 | 样本区逐字节一致 |
| `rpeak` | 峰序列一致 |
| notch on/off | 两种状态均逐样本一致 |
| diag/mon | 两种状态均逐样本一致 |
| raw853 on/off | 切换点无尖峰、无状态残留 |
| 伪迹/空白注入 | blank/reset时序一致 |

不能仅以“峰数相同”通过。

## 3 P1 关键问题

### P1-1 `ecg_filter_t` 字段布局可能造成内存膨胀

当前 `ecg_filter_t` 为32 B：

```c
uint32_t idxraw;
uint16_t dtcycles;
int32_t  ecgraw;
uint32_t idxfilter;
int16_t  dsrateraw;
int32_t  ecgraw2;
double   filterraw;
```

若把 `int16_t ch2_out` 加到结构末尾，受8字节对齐影响，很可能从32 B变成40 B：

- `EcgQueueFilterBuf` 增加约200 B；
- `ecgpopout[25]` 栈空间增加约200 B；
- 实际内存与 T237预算不符。

建议利用现有 padding：

```c
uint16_t dsrateraw;
int16_t  ch2_out;
int32_t  ecgraw2;
double   filterraw;
```

并用 `sizeof` 和 `_Static_assert(sizeof(ecg_filter_t) == 32)` 验证。

`ecg_restore_ctx` 的大小也必须用 `sizeof` 实测，不能只按字段相加。

---

### P1-2 两个重采样器必须共同初始化、复位和锁步

增加 `out2` 后：

- `ads1293_filter_chain_init()` 必须初始化两个 resampler；
- `ads1293_set_raw853(0)` 必须同时复位 `out` 和 `out2`；
- 每个853样本必须对两路各调用一次；
- 500 Hz 模式必须比较两个返回值是否一致。

建议：

```c
int o1 = ecg_out_f32_process(&out,  ch1_codes, &ch1_out);
int o2 = ecg_out_f32_process(&out2, ch2_codes, &ch2_out);
if (o1 != o2) {
    s_out_desync++;
}
```

只有两个输出同时成立时才入队。

---

### P1-3 设置同步和状态回读必须覆盖

必须统一切换 notch/mode：

```text
CH1 ctx
CH2 ctx
```

同时回读只能来自 CH1，前提是：

- CH1/CH2 设置确实同步；
- 不存在两路状态分叉；
- 有设置版本/断言保护。

必须移除 `vcomcmd.c` 对外部 `f64` 的直接依赖，改用：

```c
ecg_restore_set_notch(on);
ecg_restore_set_mode(mon);
ecg_restore_get_notch();
ecg_restore_get_mode();
```

---

### P1-4 CPU预算必须可测

当前 `dtcycles` 只覆盖 CH1。

增加 CH2 后至少记录：

```text
dtcycles_ch1
dtcycles_ch2
dtcycles_total
max
overrun
```

判据：

```text
max(total) 必须明显低于 DRDY 周期约1172 µs
```

不能仅凭“应该够”放行。

---

### P1-5 LOD 与 CH2 并非完全无关

CH2当前为：

```text
IN3 − IN1
```

LOD 正在 IN1/IN3 注入8 nA，即使电流很小，也可能影响：

- 输入偏置；
- 共模；
- 噪声；
- 伪迹空白；
- CH2 基线。

因此仍需验证：

- LOD-OFF 与 LOD-ON 下的 CH2；
- CH2独立伪迹判定；
- LOD期间CH2是否仍可发布；
- IN1/IN3脱落时CH2的有效性。

## 4 CH2真实性验收

### 4.1 当前接线

```text
IN1 ← AECG LA
IN2 ← AECG RA
IN3 ← AECG N2
IN4 ← AECG N1 / RLD回流
```

通道：

```text
CH1 = RA − LA
CH2 = N2 − LA
```

CH2不是标准导联II，也不保证是有效ECG；该阶段只验证：

- CH2 ADC链路；
- CH2滤波链；
- CH2不是CH1副本；
- 地端输入的实际表现。

### 4.2 改线验证

```text
IN1 ← AECG LA
IN2 ← AECG N2
IN3 ← AECG RA
IN4 ← AECG N1 / RLD回流
```

通道：

```text
CH1 = N2 − LA
CH2 = RA − LA
```

该阶段让CH2获得当前AECG100可产生的真实ECG差分。

### 4.3 独立信号验证

仅比较“CH1段!=CH2段”不够，因为噪声不同也会满足。

应额外测试：

- 在IN3注入已知方波，CH2响应、CH1基本不响应；
- 在IN1断开时两路都失效；
- CH1、CH2分别与预期算式一致；
- 使用并联RA/LA输入，验证两个AFE链接近一致；
- 检查极性、幅度、噪声和重采样点数。

## 5 分阶段实施与放行

### 阶段1：只重构CH1

实施：

- 新建context；
- 迁移dc/filter；
- 包装旧接口；
- 不增加CH2输出。

放行：

- 编译通过；
- CH1完整样本流逐位一致；
- notch/mode/raw853/blank行为不变；
- QRS序列一致。

### 阶段2：加入CH2上下文

实施：

- `s_ctx2`；
- `out2`；
- `ch2_out`；
- 500/853模式真实数据；
- 双resampler复位和锁步统计。

放行：

- `ch2_out`来自真实CH2；
- 实际结构大小和栈预算通过；
- CPU总耗时满足DRDY时基；
- `s_out_desync=0`。

### 阶段3：系统兼容

实施：

- `ch2 on` 109 B帧；
- ESP32双画布；
- PC工具解析；
- WinApp适配或明确禁用。

放行：

- 帧长、CRC、样本偏移全部正确；
- 109 B帧无解析错误；
- 默认双通道开关策略已批准。

### 阶段4：接线和波形验证

实施：

- 当前接线；
- 改线；
- 独立注入。

放行：

- CH1/CH2运算关系符合接线；
- CH2真实独立；
- LOD-ON/OFF均稳定；
- 无错误饱和或通道串扰。

---

## 6 必须修正的文档项

1. 删除“ads1293.c一行不改”的说法；
2. 将“550 Hz”改为“500 Hz”；
3. 明确context初始化的两层接口和顺序；
4. 补充853模式下CH2值的队列存储；
5. 给出`ecg_filter_t`字段的精确放置位置；
6. 以实测`sizeof`替代字段估算；
7. 补充所有`g_dc/f64`读写迁移点；
8. 默认双通道改为实验开关，直到WinApp适配；
9. CH1回归增加逐样本/逐字节判据；
10. 补充LOD对CH2的影响验证。

---

## 7 最终评审结论

### 批准

- 批准方案B作为总体技术路线；
- 批准“同一套滤波代码、两个独立上下文”的架构；
- 批准以`ch2 on`先做实验性双通道验证；
- 批准分阶段实施和逐阶段回退。

### 暂不批准

- 暂不批准当前T237直接落码；
- 暂不批准默认双通道；
- 暂不批准以峰序列替代CH1逐位回归；
- 暂不批准没有真实CH2存储路径的853模式；
- 暂不批准仅以“CH2与CH1不同”证明真实独立。

### 一句话

> **T237的架构选择正确；完成上下文生命周期、CH2入队存储、结构对齐、双重采样锁步、主机兼容和逐样本回归六项修改后，方可进入实现。**
