# T229 评审结果：空载乱打点、阈值下限与 START 语义

> **日期**：2026-11-11  
> **评审对象**：`T229_ABC方案_空载乱打点与START语义_2026-11-11.md`  
> **评审结论**：**问题分析可接受，方案不按现版直接批准。**  
> **建议实施顺序**：**B → A-clear → A-resume → C**。  
> **当前状态**：T229 所述代码尚未实施；本文件只给评审结论，不修改固件。

---

## 0 总体意见

T229 对空载乱打点、零初值启动伪影和 START 语义的拆分方向是正确的。三状态实测、
±26 µV 噪声峰与约 1,500 µV 真实 R 的幅度对比，足以证明空载误检是真实问题，
不是单纯的指标口径问题。

但当前方案存在三个必须先修正的工程问题：

1. **B 只改主阈值一行不完整**。候选入池次级阈值和回溯接受阈值仍可能放行弱噪声峰。
2. **A 的“`485-start` 完全不清零”过于粗糙**。跨越 STOP、换源、换导联或长时间空档后，
   直接沿用旧 `last_peak`、BPM 和 T 波历史会制造新的时序错误。
3. **C 是协议行为变化，不是内部小改**。转换常开、输出关闭、队列继续运行和 ESP32
   样本时间轴之间必须有明确契约，否则会引入跨段错拍和旧数据问题。

因此不建议“A+B 一次落码、C 随后”直接施工。应拆成可单独归因、单独回退的小步骤。

## 1 已认可的事实与判断

### 1.1 空载乱打点是真实问题

认可 T229 和 T228 §9 的实测：

- AECG100 上电但未输出时，可稳定复现约 **3.7～4.5 拍/秒**；
- 误打点位置原始值约 **±172 LSB、典型 ±26 µV**；
- 真实 R 波约 **9,923 LSB、约 1,514 µV**；
- 两者幅度相差约 58 倍。

因此，这不是“屏上有残留点”或“正常低幅 QRS”，而是检测器把无有效 ECG 时的
微小波形/噪声当成了 R 峰。

### 1.2 AECG 不同电源状态必须分开

T229 对以下状态分开统计是正确的：

- AECG100 下电；
- AECG100 上电但未输出；
- 导联夹悬空/未接人体；
- 正常 ECG 输出。

后续验收不能只写“AECG 关闭”，必须记录：

- AECG 电源状态；
- 是否有基线输出；
- 导联连接状态；
- 设备当前数据源是 485 实时源还是 FILE 回放；
- 首样本值、DC 均值、噪声 RMS、峰峰值；
- START/STOP 与 ESP32/STM32 复位顺序。

### 1.3 当前不能用 LOD 直接解决

当前 STM32 配置为：

```c
#define ECG_LOD_EN 0
```

且 `ads1293_status_byte()` 中 bit4 LOD 仍为常量 0。T229 判定“当前配置下 LOD
完全不可用”是符合现状的。

但应表述为 **“当前未启用/未验证，暂不能作为判据”**，不能永久认为 LOD 不可用。
LOD 仍是后续产品级“导联脱落提示”的必要能力，只是不能作为本轮第一落点。

### 1.4 排除 `K × noise_peak` 作为主闸门是合理的

无信号时 `noise_peak` 可能被伪峰自身抬高，闸门跟着漂移，无法可靠区分“无信号”
和“弱信号”。这一点认可，不应用相对噪声门替代绝对有效性判断。

## 2 B 方案评审：方向对，但不是一行改动

### 2.1 B 不能只改主阈值

T229 提议：

```c
thr = fmaxf(ECG_RP_THR_FLOOR,
            noise_peak + 0.25f * (signal_peak - noise_peak));
```

但当前检测器至少有三个独立阈值入口：

1. 主路径接受阈值 `threshold`；
2. 候选入池次级阈值 `sec_thr`；
3. 回溯路径接受阈值 `need`。

如果只给主阈值加绝对下限，弱噪声峰仍可能：

1. 通过 `sec_thr` 进入候选池；
2. 主路径不接收；
3. 稍后被回溯路径用未加下限的 `need` 接受并打点。

**结论：B 必须抽取统一的阈值函数，使主路径、候选池和回溯路径同时受绝对下限约束。**

建议形式：

```c
static float effective_threshold(const ecg_rpeak_t *rp, float ratio)
{
    const float adaptive =
        rp->noise_peak + ratio * (rp->signal_peak - rp->noise_peak);
    return fmaxf(rp->thr_floor, adaptive);
}
```

其中：

- 主阈值使用 `ratio = 0.25f`；
- 候选入池/Backtrack 使用 `ratio = 0.5f`；
- `rp->thr_floor` 由配置或增益档初始化，不在每个样本重复换算。

### 2.2 200 µV 只能作为实验起点

`integ ∝ (dV/dt)²`，不仅取决于幅度，还取决于 QRS 宽度和形态。
T229 的 `k ≈ 0.043 /µV²` 是用一个参考 QRS 形态估出来的，不能直接推广为：

> 所有 200 µV 以上 QRS 都能通过，所有 200 µV 以下波形都应被挡住。

正式选值前必须定义产品要求：

- 最低需要检出的 QRS 幅度；
- 对应 QRS 宽度、极性和导联；
- 在最低幅度下的灵敏度下限；
- 无信号条件允许的误打点率；
- 不同增益档的标定表。

建议首轮仍可取 **200 µV 等效**做实验，但必须同时测试：

- 0.2 / 0.3 / 0.5 mV；
- 不同 QRS 宽度；
- 正/负主极；
- PVC、低电压 QRS；
- MIT-BIH 与真实低幅数据；
- 各增益档。

### 2.3 验收不应简单要求“MIT 逐峰绝对不变”

如果 B 正确挡掉了一些低幅伪峰，MIT-BIH 的 FP 或峰序列发生变化不一定代表回归失败。
验收应逐项判断：

- TP 是否减少；
- 真值是否被误拒；
- 减少的峰是否确实为非真值 FP；
- Se / +P / F1 / DER 是否发生可接受变化；
- 完整数据和剔边口径都要报告。

“逐峰完全一致”可以作为无差异时的强证据，但不能成为忽略合法改进的硬性条件。

## 3 A 方案评审：拆成 A-clear 与 A-resume

### 3.1 清屏不复位检测器：认可

T212 已把清屏定义为纯视觉动作。清屏后：

- 清空已绘制的点和波形；
- 保留检测器状态；
- 保留 BPM 历史；
- 后续新点继续使用同一检测 epoch。

这部分独立、低风险，建议实施。

可命名：

> **A-clear：清屏只清视觉状态，不复位 R 峰检测器。**

### 3.2 `485-start` 完全不清零：不认可

`485-start` 可能对应：

- 掉流后重新打开接收；
- STOP 后恢复；
- 换源后恢复；
- STM32 复位后重新起流；
- 用户长时间未采集后重新开始。

这些场景之间没有共同的时间连续性。

如果直接保留：

- `last_peak`；
- `last_accepted_slope`；
- `peak_n / peaks[]`；
- BPM 历史；
- `sample_index`；

则恢复后可能出现：

- 旧峰与新信号组成巨大 RR；
- BPM 使用上一段的峰值历史；
- 旧斜率导致新 R 波被误判为 T 波；
- 长时间空档后旧 `signal_peak` 压制新信号；
- 换导联/换增益后旧幅度尺度失配。

因此，**“同一路连续信号只是断了一段”这个前提在 STOP 和换源场景下不成立。**

### 3.3 推荐改为显式 suspend/resume

建议新增检测器生命周期接口：

```text
INIT
SETTLING
VALID
NO_SIGNAL / LEAD_OFF
SUSPENDED
```

`ecg_rpeak_suspend()`：

- 标记检测暂停；
- 不再发布新峰。

`ecg_rpeak_resume(gap_samples, same_source, same_gain, same_lead)`：

- 短空档且状态一致：可保留滤波器和噪声估计；
- 清除 `last_peak`、BPM 历史、T 波斜率和候选池；
- 长空档/换源/换导联/换增益：进入 `SETTLING`，完成重新收敛后再发布峰。

核心原则：

> **可以保留“信号统计状态”，不能无条件保留“心搏时序历史”。**

### 3.4 A 的重新定义

建议将 A 拆为：

| 子项 | 内容 | 风险 |
|---|---|---|
| A-clear | 清屏不复位检测器 | 低 |
| A-resume | START 后按 gap/source/gain 决定保留哪些状态 | 中 |
| A-reset | 人工强制 `rpeak reset` | 低 |

不建议把三项合并成一个“不清零”宏。

## 4 C 方案评审：暂缓，另立协议与采样连续性设计

### 4.1 C 不是纯内部实现变化

即使 `0x01/0x02` 字节和帧格式不变，START 从“复位并启动采集”改成“仅开始发送”，
对上位机仍是可观察的语义变化。

必须确认：

- WinApp 是否假设每次 START 后样本从零开始；
- 上位机是否依赖 START 清空队列；
- 其他客户端是否依赖当前 ACK 时序；
- 改模式、陷波、通道、增益后是否需要显式重启链；
- STOP 期间时间段如何记录。

### 4.2 STOP 期间持续转换会制造时间空档

如果 `0x02` 只关闭输出、ADC 和滤波链继续运行：

- STM32 的样本时间继续前进；
- ESP32 在 STOP 期间收不到样本；
- ESP32 检测器的 `sample_index` 不前进；
- 恢复后第一帧与检测器旧状态不属于同一时间轴。

因此 C 与 A 的关系不是简单的“C 后不清零即可”，而必须引入：

- 段编号/epoch；
- 时间戳或绝对样本号；
- gap 长度；
- 暂停和恢复标记；
- ESP32 检测器的 suspend/resume。

### 4.3 “STOP 态继续排空队列”必须定义完整

队列排空不能只是删除数据，应明确：

1. ADC 是否持续读取；
2. 原始队列是否持续消费；
3. 滤波链是否每样本继续更新；
4. 输出队列关闭后数据如何处理；
5. 队列深度是否持续监控；
6. 恢复时首帧如何证明是实时数据。

建议验收：

- STOP 60 s；
- 检查原始队列无持续增长；
- 检查滤波状态持续推进；
- START 后首帧时间戳紧跟当前时间；
- 首帧不包含 60 s 前旧样本；
- 不产生 STOP 期间的旧峰。

### 4.4 “采集中/仅输出关闭”状态应作为必需项

C 落地后如果协议没有运行态位，上位机无法区分：

- STM32 未运行；
- ADC 运行但输出关闭；
- 通信断开；
- 队列异常。

该状态位及协议兼容策略应在本轮设计时确定，不能作为可选补充。

### 4.5 功耗和长期运行影响

ADC 常开会提高：

- 功耗；
- 温升；
- 电极偏置电流和极化；
- 长期噪声/基线漂移风险。

即使当前功耗可接受，也应记录实测值，并纳入长期运行验证。

## 5 推荐实施顺序

不建议 T229 的“A+B 同一次、C 随后”。建议改为：

### 第一步：B

- 统一主阈值、次级阈值、回溯阈值；
- 先以 200 µV 等效值做实验；
- 跑空载三状态、MIT-BIH、自建低幅 QRS；
- 确认没有真实峰误杀。

### 第二步：A-clear

- 清屏只清视觉；
- 检测器和 BPM 保持；
- 与空载问题无耦合，可独立验收。

### 第三步：A-resume

- 引入 suspend/resume；
- 定义 gap/source/gain/lead 变化的处理；
- 不允许把旧心搏历史无条件带入新段。

### 第四步：C

- 另立 START/STOP 协议与采样连续性设计；
- 加 epoch/gap/运行态状态；
- 完成上位机兼容性确认和功耗测量；
- 在 B 已稳定后实施。

每一步单独构建、单独记录基线、单独回退。

## 7 必须逐项归因的代码风险

### 7.1 次级阈值与回溯阈值

当前主路径、候选池和回溯路径不能只共享“理念”，必须共享同一个下限计算函数。
否则 B 的主路径看起来修好了，回溯仍会漏过噪声候选。

### 7.2 `last_peak` 与 BPM 跨段污染

恢复后必须明确：

- 是否保留 BPM；
- 是否保留最近 RR；
- 是否丢弃上一条 `last_peak`；
- 是否把恢复后的首个峰作为新段的初始峰。

建议长空档后 BPM 重新显示 `--`，而不是继续沿用旧值。

### 7.3 T 波斜率跨段污染

`last_accepted_slope` 可能来自不同增益或不同导联。换源、换增益后必须清除或标记无效。

### 7.4 行列队列与显示 epoch

R 峰绝对号依赖 `s_push_seq`。STOP/START 后若序列空间变化，界面点和波形的 epoch 必须同步，
不能只改检测器而不同步 UI 队列。

## 8 编译期开关建议

编译期开关可以保留，但不建议用开关掩盖状态设计缺失。

建议拆分：

| 开关 | 作用 | 默认 |
|---|---|---|
| `ECG_RP_THR_FLOOR_UV` | 绝对门限等效幅度 | 200，实验值 |
| `ECG_RP_KEEP_STATE_ON_CLEAR` | 清屏是否保留检测器 | 1 |
| `ECG_RP_RESUME_POLICY` | 短 gap / 长 gap / 换源策略 | 显式枚举 |
| `ECG_STM32_START_IS_SWITCH` | STM32 START 新语义 | 0，默认关闭 |

`ECG_STM32_START_IS_SWITCH` 在协议和连续性方案未定前不应默认开启。

## 9 最终结论

### 批准

- 批准 T229 作为问题分析和实验依据；
- 批准 B 进入实现验证；
- 批准 A-clear 单独实施；
- 保留 A-resume 和 C 为后续独立设计。

### 暂不批准

- 不批准 B 的“一行改动”表述；
- 不批准 `485-start` 无条件不清零；
- 不批准 A+B 绑定一次提交；
- 不批准 C 直接按“纯输出开关”落码；
- 不批准在未定义最低 QRS 幅度和增益标定的情况下固化 200 µV 门限。

### 一句话结论

> **T229 方向正确，但不能整包施工。先做统一阈值下限解决空载乱打点，再把清屏与**
> **START 恢复语义拆开，最后另立 STM32 输出开关与采样连续性方案。**
