# T236 LOD bit5 回归测试清单（2026-11-12）

> **被测改动**：2026-11-12 那批 —— ① `ECG_LOD_MASK` 单一真源 ② **新增 `STA.bit5 = CH1_INVALID`**
> ③ ESP32 `485-stat` 增加 `ch1inv` 显示
> **范围**：ADS1293 + STM32 → RS485 → ESP32（模拟真机台架）。
> 🛑 **本轮不测**：WinApp 全部；ESP32 门控动作（未实现）；CH2 数据正确性（`CH2≡CH1` 未变）。
> **性质**：回归 + 新功能验收。**任一组 FAIL 即停止后续组**，先定位。
>
> 相关文档：机制见 `T234`（§2.6 bit4/bit5、§2.7 回流、§5 时序）；历史用例见 `T232` §16。

## 1 期望值速查（**先记住这三组字节**）

| 工况 | `raw` STA | bit4 `lod` | bit5 `ch1inv` | 屏上 | QRS 打点 |
|---|---|---|---|---|---|
| 全接好 | **`0x02`** | 0 | 0 | 亮灰 | 正常 |
| **只拔 IN3** | **`0x12`** | 1 | **0** | 红叉 | **继续** |
| 拔 IN1 / IN2 / IN4 | **`0x32`** | 1 | **1** | 红叉 | 停 |

> `0x02` 里的 bit1 是 **notch=on**（当前 profile 默认）。若把陷波关了，全接好应是 `0x00`，
> 其余两组同理各减 `0x02`。**测前先 `485-stat` 确认 notch 状态，别拿错基准。**

🛑 **拔 IN4（回流断）为什么也会 `ch1inv=1`**：手册 §8.3.16 规定"无回流时**所有使能脚全报**"，
所以 `s_lod_stable = 0x07`，而 `0x07 & 0x03 ≠ 0` ⇒ bit5 照样置位。
**这是预期变更**（T232 §16.3 观察到"拔 IN4 时 QRS 仍在跑"，那是"信号还在"，不是"我们信它"）。

## 2 A 组：链路与解析回归（不动线，全自动）

| # | 用例 | 期望 | 实测 | 判定 |
|---|---|---|---|---|
| **A1** | **上电 S2 帧扫描自检**（`main.c:352`，自动跑） | 6 个 `.bin` 全 **PASS** | | ☐ |
| A2 | `485-start` + `485-send start` | `frames` 增长、`crc=0`、`resync=0`、`gaps` 不增 | | ☐ |
| A3 | 帧长 | 单通道 **59 B**；`ch2 on` 后 **109 B** | | ☐ |
| **A4** | **STA 基准字节** | 全接好恒 **`0x02`**，且 `ch1inv=0` | | ☐ |

> 一次证明"帧格式与 STA 解析没被 bit5 破坏"。日志关键字：`==== S2: frame scan`。

## 3 B 组：bit5 新功能（需人工拔插，**本轮重点**）

> 操作要求：动作**干脆一次到位**，不要停在半插状态；每次动作后**等 3 s** 再记录。
> 记录三件事：`raw` 字节、屏上图标、`peaks` 是否继续增长。

| # | 动作 | 期望 `raw` | `lod` | `ch1inv` | 屏上 | 打点 | 实测 raw | 判定 |
|---|---|---|---|---|---|---|---|---|
| B1 | 全接好（基线） | `0x02` | 0 | 0 | 亮灰 | 正常 | | ☐ |
| B2 | 拔 **IN3** | `0x12` | 1 | **0** | 红叉 | **继续** | | ☐ |
| B3 | 插回 IN3 | `0x02` | 0 | 0 | 亮灰 | 继续 | | ☐ |
| B4 | 拔 **IN1** | `0x32` | 1 | **1** | 红叉 | 停 | | ☐ |
| B5 | 插回 IN1 | `0x02` | 0 | 0 | 亮灰 | 恢复 | | ☐ |
| B6 | 拔 **IN2** | `0x32` | 1 | 1 | 红叉 | 停 | | ☐ |
| B7 | 插回 IN2 | `0x02` | 0 | 0 | 亮灰 | 恢复 | | ☐ |
| **B8** | 拔 **IN4**（回流断） | `0x32` | 1 | **1** | 红叉 | **停**（预期） | | ☐ |
| B9 | 插回 IN4 | `0x02` | 0 | 0 | 亮灰 | 恢复 | | ☐ |
| B10 | 同时拔 IN1+IN2 | `0x32` | 1 | 1 | 红叉 | 停 | | ☐ |

**B2 与 B4 是本组的分水岭**：只有这两个的差别能证明 bit4/bit5 真的分开算。
若 B2 也出现 `ch1inv=1` ⇒ 策略宏或掩码写错（`ECG_LOD_GATE_CRIT` 没生效）。

## 4 C 组：掩码与防抖回归

| # | 用例 | 期望 | 实测 | 判定 |
|---|---|---|---|---|
| C1 | 连续拔插 IN1 **10 次** | `raw` **只出现** `0x02` / `0x12` / `0x32`，高 3 位恒 0 | | ☐ |
| C2 | 置位延迟（拔 → `lod=1`） | ≤2 s（基线 0.4~1.6 s） | | ☐ |
| C3 | 恢复延迟（插回 → `lod=0`） | ≤2 s（基线 0.6~1.8 s） | | ☐ |

> C1 是 `ECG_LOD_MASK` 的间接判据：若锁存里混进了 bit3 以上的位，`raw` 会出现 `0x0A`/`0x1A` 之类。

## 6 命令速查（本轮全部判据的可执行版）

```bash
# 起流（顺序不能反，且重启/烧录后要重来）
485-start
485-send start

# 单次读 STA（看 raw / lod / ch1inv / 帧龄）
485-stat

# 连读链路（frames / crc / 帧长 / 性能）
485-perf 10

# 1 s 窗口样本统计（噪声代价）
stat on
stat

# LOD 门限不动、只看打点
rpeak on
```

**轮询 raw STA 时间线**（B/C 组的记录手段）：每 ~0.3 s 调一次 `485-stat`，
正则取 `raw=(0x..)` 与 `ch1inv=(\d)`，把连续相同的值压成段 ⇒ **切换次数 = 段数 − 1**。

## 7 结果判定

| 结论 | 条件 |
|---|---|
| **通过** | A 全过、B 全过（尤其 B2 vs B4）、C 全过、D1 无新误报 |
| **有条件通过** | A/C/D 过，B 有偏差但能解释（例如延迟超 2 s 但机理清楚） |
| **不通过** | B2 与 B4 表现相同（bit4/bit5 没分开）／A4 基准不是 `0x02`／D3 出现恒零波形 |

**回归结论要回答的一句话**：`bit5` 的加入是否**只动了一个本来恒 0 的保留位**，
没有影响波形、打点、帧格式、图标与既有判据。
