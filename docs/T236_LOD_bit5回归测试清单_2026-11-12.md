# T236 LOD bit5 回归测试清单（2026-11-12）

> **被测改动**：2026-11-12 那批 —— ① `ECG_LOD_MASK` 单一真源 ② **新增 `STA.bit5 = CH1_INVALID`**
> ③ ESP32 `485-stat` 增加 `ch1inv` 显示
> **范围**：ADS1293 + STM32 → RS485 → ESP32（模拟真机台架）。
> 🛑 **本轮不测**：WinApp 全部；ESP32 门控动作（未实现）；CH2 数据正确性（`CH2≡CH1` 未变）。
> **性质**：回归 + 新功能验收。**任一组 FAIL 即停止后续组**，先定位。
>
> 相关文档：机制见 `T234`（§2.6 bit4/bit5、§2.7 回流、§5 时序）；历史用例见 `T232` §16。

## 1 期望值速查（**先记住这三组字节**）

| 工况 | `raw` STA | bit4 `lod` | bit5 `ch1inv` | 屏上 | QRS 打点 |
|---|---|---|---|---|---|
| 全接好 | **`0x02`** | 0 | 0 | 亮灰 | 正常 |
| **只拔 IN3** | **`0x12`** | 1 | **0** | 红叉 | **继续** |
| 拔 IN1 / IN2 / IN4 | **`0x32`** | 1 | **1** | 红叉 | 停 |

> `0x02` 里的 bit1 是 **notch=on**（当前 profile 默认）。若把陷波关了，全接好应是 `0x00`，
> 其余两组同理各减 `0x02`。**测前先 `485-stat` 确认 notch 状态，别拿错基准。**

🛑 **拔 IN4（回流断）为什么也会 `ch1inv=1`**：手册 §8.3.16 规定"无回流时**所有使能脚全报**"，
所以 `s_lod_stable = 0x07`，而 `0x07 & 0x03 ≠ 0` ⇒ bit5 照样置位。
**这是预期变更**（T232 §16.3 观察到"拔 IN4 时 QRS 仍在跑"，那是"信号还在"，不是"我们信它"）。

> 🛑 **B8 的"打点"判据要分清"位"与"动作"**（本轮回填时订正）：
> `ch1inv=1` **已置位**（`raw=0x32`），但 `peaks` **仍在增长**。
> 因为 **C-3 门控在 ESP32 侧还没接**（`ch1inv` 只是显示）——
> 打点停不停只取决于**CH1 差分信号还在不在**：拔 IN1/IN2 信号消失 ⇒ 停；拔 IN3/IN4 信号仍在 ⇒ 继续。
> ⇒ 本轮 B 组验证的是**判据位正确**，不是"停测动作"（那要等门控落码）。

## 6 命令速查（本轮全部判据的可执行版）

```bash

# 单次读 STA（看 raw / lod / ch1inv / 帧龄）
485-stat

# 连读链路（frames / crc / 帧长 / 性能）
485-perf 10

# 1 s 窗口样本统计（噪声代价）
stat on
stat

# LOD 门限不动、只看打点
rpeak on
```

正则取 `raw=(0x..)` 与 `ch1inv=(\d)`，把连续相同的值压成段 ⇒ **切换次数 = 段数 − 1**。

## 9 本轮执行中发现的问题（A 组，2026-11-12 10:45~10:55）

### 9-1 🛑 `485-send ch2` 之后流拉不回来（**阻塞 A3 双通道**）

| 现象 | 细节 |
|---|---|
| 操作 | `485-send stop` → `485-send ch2 1` → `485-send start` |
| 结果 | `frames=0`、`rx=0`，连发 4 次 `start` 均无效 |
| 恢复 | 必须 `485-stop` → `485-start` → `485-send start` 才恢复（实测恢复后 131→309→417 帧） |

- **未定性**：不清楚是 `0x06` 命令本身、还是 ESP32 侧源状态问题。
- **判断**：与本轮改动（`ECG_LOD_MASK` / `bit5` / `ch1inv`）**无关** —— 这三处都不碰通道切换路径。
  但**需要单独立项排查**，因为它会让"切双通道"这个已有功能不可用。
- 临时规避：切通道后若 `frames` 不动，先 `485-stop` 再 `485-start`。

### 9-2 每个新会话都必须重新初始化

`485-start` 内部会 `rs485_reset_stat()` 清零计数器；且新开会话后 STM32 侧不保证仍在流状态。
⇒ **每个测试会话的第一组命令固定为**：`485-stop` → `485-start` → `485-send start`。
（本次 A6 第一次跑就因为这个拿了全 0，白跑一轮。）

### 9-3 烧完 STM32 若指示灯不亮 / `rx=0`：拔插 USB

ST-LINK CLI `-P ... -Rst` 报 `Verification OK`、`MCU Reset`，但 MCU 实际**没有跑起来**
（板上指示灯不亮、链路上 `rx=0 B`）。
⇒ 拔插一次 USB 后正常。**烧录后先看灯**，别急着判"固件有问题"。
