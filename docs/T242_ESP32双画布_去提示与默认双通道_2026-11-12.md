## 1 改动一：删掉画布 2 的 "no data" 提示

**原状**：`s_lbl_c2` 是挂在屏幕上的 label，文案
`"Single-channel file (Lead I) -- canvas 2 no data"`，只在**单通道**时显示，双通道时
`LV_OBJ_FLAG_HIDDEN` 藏掉。

**为什么要删**（猛哥 2026-11-12）：STM32 `T239 步2` 起 CH2 是真实第二路、且默认开启
⇒ 双画布**常态就有数据**，那条"无数据"提示在常态下恒为假；留在代码里只等某次
`set_dual_channel(false)` 把它翻出来误导人。单通道回退时画布 2 是**空白网格**，本身就自明。

**改法**：整块删除（不是改文案、不是改条件），四处：

| 位置 | 处理 |
|---|---|
| `:89` 静态声明 `s_lbl_c2` | 删除，原处留 ★T242 注释说明"删了什么、为什么、别复活" |
| `:716~720` 创建 + 设文案 + 对齐 | 整块删除，留注释指向 `paint_canvas2_static()` |
| `apply_theme()` 里设文字色 | 删掉那一行（其余两个 label 不变） |
| `ui_waveform_set_dual_channel()` | 原"显隐 label"分支改为：**只在切回单通道时** `paint_canvas2_static()` 重刷空白网格 |

⚠ 最后一条是**行为保留项**，别一起删：切回单通道若不重绘，画布 2 会留着上一次双通道的
CH2 轨迹，看着像"单通道却还在画第二路"。

## 2 改动二：上电默认双通道

`static bool s_dual = false;` → **`= true;`**

依据：STM32 侧 `_bch2` 上电初值已是 1（`T239` 拍板 Q1）⇒ 上行帧本来就是 109 B。
ESP32 若仍从单通道起步，屏上会先只画 CH1，直到有人敲 `485-send ch2 1` ——
与"芯片侧已经给了两路"的事实不符。

**开关仍由 `485-send ch2 0|1` 负责**（`cli_console.c:2054`）：它同时把 STM32 的 `0x06`
与本变量一起改，两边不会一个改一个不改。

**已知边界（写进注释了）**：若有人从**别的通道**（WinApp / STM32 ASCII `test ch2 off`）
把 STM32 改成单通道而 ESP32 没被告知 ⇒ 本变量仍 true、收到 59 B 帧 ⇒ 画布 2 是一条平线。
补一句 `485-send ch2 1` 即可。**不做"按帧长自动跟随"**：那要在 pipeline 任务里调 LVGL
（非线程安全），收益只是省一条命令，不值。

## 4 遗留

- 本次同时曝出一条**操作硬事实**（不是本次改动引起）：`485-send start` 即便回显
  `START(0x01) -> ESP_OK` 也可能**根本没到 STM32**（下行丢失），表现为"发了 start 但
  `rx` 不涨"。⇒ **必须以 `485-stat` 的 `rx` 在涨为起流判据**，不能看命令回显。
  本轮因此白跑两次 60 s 窗口（`Δframes=0`）。
- ESP32 的 USB-Serial-JTAG 在**每次开串口**时都会复位芯片 ⇒ 统计量归零、`源` 退回 FILE、
  485 未初始化。一次会话里必须把 `485-start`／`485-send …`／`485-stat` 全做完。
