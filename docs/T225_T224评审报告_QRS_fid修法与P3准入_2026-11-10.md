## 0 结论摘要

1. T224 的核心判断可信：90/120 bpm 的主要问题不是漏检，而是回溯路径触发时，
   `locate_rpeak()` 的搜索窗已经滑出 `filt_hist`，导致落点未精修或只在不完整窗口内静默选错。

3. 候选入池时保存 `fid` 是最小、与心率无关的修法。**下一步就是 P3，把 `fid` 落进 C 实现。**
4. P3 不应改 `filt_hist`，不应调整不应期，也不应同时加入幅度/极性门。
5. T224 中有若干数据计数、内存预算和重放夹具一致性问题。它们不推翻算法结论，但在 P3
   完成回归并宣布结案前必须修正。

## 3 已认可的评审结论

### 3.1 根因成立

当前 C 实现的候选池只保存：

```c
index / value / slope
```

主路径接受时立即调用 `locate_rpeak(peak)`；回溯路径则在更晚的时刻再次调用
`locate_rpeak(c->index)`。回溯越晚，历史环形缓冲区越可能已覆盖采样点：

- 窗口完全滑出：`found == false`，直接返回粗触发坐标；
- 仅部分窗口可见：`found == true`，但在残缺窗口内选极值，指标上更隐蔽。

T224 对两种情况的条件、现象和实测代表事件描述与代码一致。

### 3.2 修法方向成立

在候选入池时计算并保存 `fid`，回溯时直接读取，等价于把“当时窗口覆盖最全”的精修结果
随候选一起保存。它不依赖回溯滞后量，因此不会像扩大 `filt_hist` 那样在低心率再次失效。

### 3.3 分阶段处理正确

缺陷 B 的 60 bpm 假峰不是坐标问题，而是候选本身不应被接受。它与缺陷 A 分开验收，
避免用扩大窗口或移动落点掩盖门控缺陷，是正确的工程边界。

## 4 必改问题

### 4.1 R1：统一内存预算，修正“零内存增长”表述

**严重度：P1；影响 P3 设计评审与实现验收。**

T224 摘要写“零内存增长”，但 §5.3 又估计增加约 256 B，二者矛盾。

当前候选结构为：

```c
typedef struct {
    int64_t index;   /* 8 B */
    float   value;   /* 4 B */
    float   slope;   /* 4 B */
} ecg_rp_cand_t;     /* 通常 16 B */
```

若直接在结构体内增加 `int16_t fid_delta`，受 8 字节对齐影响，很可能使每项变成 24 B：

- 64 项：`64 × 8 B = +512 B`，不是 +256 B；
- 若再保存一个未使用的 `fid_val`，字段本身可能被对齐填充吸收，但仍然增加 512 B。

建议改为并列数组：

```c
int16_t cand_fid_delta[ECG_RP_CAND_MAX];
```

增加 **128 B**，且不破坏原候选结构布局。若不保存滤波值，则删除 `fid_val`；
后续幅度门需要的是原始域幅度，不应复用这里的滤波值。

结论：**可以增加少量 RAM，但不能写成“零内存增长”，也不能把 +256 B 当作已核实预算。**

### 4.2 R2：统一候选解析，主路径与回溯共用 fid

**严重度：P1；影响 T223 必需项。**

T224 §5.4 第 1/2 条基本正确，但第 3/4 条需要落实为一个明确的数据流：

```text
trigger + value + slope
        ↓
build_candidate()
        ↓
refine_qrs_fiducial()  ← 只在入池时执行一次
        ↓
candidate{trigger, value, slope, fid_delta}
        ↓
主路径接受 / 回溯接受都从同一候选解析 fid
```

推荐约束：

1. `cand_push()` 在当前样本处理时计算 `fid`；
2. 主路径若在同一轮接受该候选，直接复用刚算出的 `fid`；
3. 回溯使用 `c->index + c->fid_delta`；
4. 候选时序筛选和接受后的删除仍使用 `trigger`，不能改用 `fid`；
5. 不在主路径和回溯分支各写一套落点策略。

“主路径调用点不动”应理解为**对外行为和判定不变**，不要求内部重复调用
`locate_rpeak()` 两次。复用同一次计算结果更容易满足统一解析要求。

### 4.3 R3：明确这是“最小 fid 修复”，不是完整双坐标重构

**严重度：P1；影响后续幅度/极性门设计。**

当前 `last_peak` 保存的是 fid，而候选索引和不应期使用 trigger，`spacing` 又存在
“当前 trigger 减上一条 fid”的混合坐标语义。

P3 可以选择：

- **P3A（推荐）**：冻结现有触发、间距和不应期行为，只修候选 fid 保存及回溯输出；
  明确该阶段不是完整双坐标重构。
- **P3B（后续）**：增加 `last_trigger` 与 `last_fid`，把搜索/不应期与 RR/BPM/打点彻底分坐标。

不要在 P3A 中悄悄改变坐标语义，否则“主路径逐峰不变”的验收口径会失去意义。

### 4.4 R4：补齐重放夹具的候选删除逻辑

**严重度：P1；影响 P3 回归 oracle 的可信度。**

固件在回溯接受候选后，会删除 `index <= accepted_trigger` 的候选。Python
`replay_rpeak.py` 当前没有等价删除步骤。

本次 60/90/120 bpm 的逐峰输出完全一致，因此现有结论不受影响；但 P3 将用 Python
结果作为 C 实现的逐峰 oracle，此差异必须修复后再作为长期回归基准。

### 4.5 R5：修正数据份数与事件归类

**严重度：P2；影响文档严谨性，不改变算法方向。**

1. T224 表中有：
   - 60 bpm × 3；
   - 90 bpm × 2；
   - 120 bpm × 1；
   - 150/180/210/270/300 bpm × 5。

   合计是 **11 份采集**，不是摘要中的“9 个心率 / 10 份采集”。

2. 60 bpm #173 同时出现在“缺陷 A 的 4 个事件”和“疑似输入流不连续、待查”中。
   建议改为：
   - 缺陷 A 确定：3 个；
   - 疑似输入流不连续：1 个，待原始流复核；
   - 缺陷 B：2 个。

## 5 P3 实现建议

### 5.1 数据结构

建议使用并列数组，避免为 2 B 偏移破坏 16 B 结构对齐：

```c
/* ecg_rpeak_t 的候选部分 */
ecg_rp_cand_t cand[ECG_RP_CAND_MAX];
int16_t       cand_fid_delta[ECG_RP_CAND_MAX];
int           cand_n;
int           cand_pos;
```

`fid_delta = fid - trigger`。在当前 `ECG_RP_LOCATE_HALF == 40` 下，
`int16_t` 有足够范围；若未来扩大搜索半窗，需增加静态范围检查。

### 5.2 编译开关

建议保留一个编译期基线开关，例如：

```c
#ifndef ECG_RP_USE_STORED_FID
#define ECG_RP_USE_STORED_FID 1
#endif
```

用途：

- 默认固件走 fid 修复；
- host 回归可编译 `ECG_RP_USE_STORED_FID=0` 生成现状基线；
- 同一份 C 源码可逐峰证明“主路径不变、回溯修复”。

### 5.3 明确不做

- 不增加 `ECG_RP_FILT_HIST`；
- 不改 `ECG_RP_LOCATE_HALF`；
- 不改积分窗、不应期或 `1.66 × avg_RR` 回溯阈值；
- 不在 P3 加幅度门、极性门或原始域峰值重估；
- 不把今日 60 bpm 三份 PASS 解释为缺陷 B 已消失。

## 6 P3 验收标准

### 6.1 代码级

- 每个新候选保存 `fid_delta`，范围有保护；
- 主路径与回溯路径使用同一候选解析结果；
- 候选删除条件继续按 trigger 判断；
- `locate_rpeak()` 不再在回溯时依赖已滑出历史的窗口。

### 6.2 离线回归

必须覆盖全部 **11 份**固定心率抓包：

| 指标 | 放行要求 |
|---|---|
| 峰数 | 与现有一致或仅保留原有首尾 ±3 拍边界差 |
| σ(e) | 90/120 bpm ≤ 0.5，其他心率不劣化 |
| 异常间期 | 90/120 为 0；其他心率不增加 |
| P95 / P99 / max | 不劣于各自现状 PASS 基线 |
| 峰处原始样本值 | 90 bpm 中位仍接近 R 顶，不出现下降支系统性偏移 |
| 主路径输出 | fid 开关前后逐峰完全相同 |
| 回溯路径输出 | C 与 Python `FID_MODE=1` 逐峰完全相同 |

### 6.3 诊断与失败保护

- 搜索失败时仍保留粗 trigger，不因精修失败丢拍；
- 诊断模式记录 `trigger / fid / lag / 窗口覆盖量 / 来源（主路径或回溯）`；
- fid 索引必须位于当前候选允许的局域窗口内；
- 若候选在回溯前已被环形池覆盖，应明确如何处理，不能读取陈旧槽位。

### 6.4 后续阶段

P3 完成后进入 P4：

- MIT-BIH Se / PPV / DER；
- 真实人体、导联反向、低幅 QRS、PVC；
- 缺陷 B 的负向大摆幅与小鼓包专项复现；
- 同总线双接收，复核疑似输入流不连续。

## 7 风险清单

| 风险 | 后果 | 控制措施 |
|---|---|---|
| 在结构体内直接加字段 | RAM 预算误判、结构对齐意外膨胀 | 使用并列 `int16_t` 偏移数组 |
| fid 与 trigger 混用 | 不应期、回溯范围出现坐标偏移 | P3A 冻结现有语义，后续显式拆分 |
| 主路径重复计算落点 | 不满足统一解析，且增加无谓算力 | 候选入池计算一次并复用 |
| Python 与 C 状态机不同 | 回归 oracle 可能漏掉分叉 | 补候选删除、再做逐峰比较 |
| 把 60 bpm 新抓包当 B 已解决 | 条件触发的假峰进入产品 | 缺陷 B 保持独立 WARN/专项 |

## 8 最终意见

T224 已经足以支持启动 P3。建议批准以下最小实施范围：

> 在候选入池时计算并保存 fid 偏移；主路径和回溯路径复用同一候选解析结果；
> 保留编译期基线开关；用 11 份固定心率抓包完成 C/Python 逐峰一致性和定位回归。

批准前提不是要求先完成缺陷 B，而是要求 P3 合并前补齐：

1. 候选池内存预算和并列数组设计；
2. 主/回溯统一候选解析；
3. Python 与 C 候选删除逻辑一致；
4. 11 份数据计数及 #173 归类修正。

P3 完成后，应由实验结果决定是否继续做完整双坐标重构；不要在同一提交里同时改变
落点、不应期、阈值和幅度门，否则即使指标改善也无法单独归因。
